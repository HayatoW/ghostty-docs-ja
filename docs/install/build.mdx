---
title: Ghostty をソースからビルドする
description: |-
  ソースコードから自分で Ghostty をビルドします。バイナリやパッケージを利用できない方、
  または Ghostty に貢献したい開発者にのみ推奨します。
---

<Tip>

**ほとんどのユーザーには、Ghostty をソースからビルドすることをお勧めしません。**
ビルド済みバイナリやパッケージを利用できる場合は、そちらを使ってください。
お使いのプラットフォーム向けのビルド済みバイナリやパッケージがあるかは、[バイナリとパッケージのページ](/docs/install/binary)で確認できます。

Ghostty の開発やパッケージ化を行う場合は、それぞれ
[「Ghostty の開発」](https://github.com/ghostty-org/ghostty/blob/main/HACKING.md)と
[「Ghostty のパッケージ化」](https://github.com/ghostty-org/ghostty/blob/main/PACKAGING.md)のドキュメントも確認してください。
このページは、個人利用のために Ghostty をソースからビルドしたい、またはその必要があるエンドユーザーを主な対象としています。

</Tip>

Ghostty をビルドするには、まず [Zig](https://ziglang.org/) をインストールする必要があります。

<Important>

Zig は今も急速に進化している言語のため、Ghostty の各バージョンは、Zig の**特定の** 1 バージョンでのみビルドを保証しています。
**古い Zig コンパイラーでも新しい Zig コンパイラーでも、Ghostty をビルドできない場合があります。**
パッケージマネージャーが提供する Zig のバージョンが Ghostty の要求と異なる場合は、
[Zig のダウンロードページ](https://ziglang.org/download/)にある Zig コンパイラーの静的バイナリリリースを使えます。

</Important>

Ghostty の各バージョンが必要とする Zig のバージョンは次のとおりです。

| Ghostty のバージョン | Zig のバージョン |
| --------------- | ----------- |
| 1.0.x           | 0.13.0      |
| 1.1.x           | 0.13.0      |
| 1.2.x           | 0.14.1      |
| 1.3.x           | 0.15.2      |
| tip             | 0.15.2      |

公式のビルド環境は [Nix](https://nixos.org/) で定義されています。
Ghostty のビルドに Nix は必須ではありませんが、Nix 環境は CI テストやリリース成果物のビルドに使う環境なので、最も確実なビルド方法です。
Nix 環境の設定方法は、[Nix でのビルド](#building-with-nix)を参照してください。

プラットフォームによっては、Ghostty のビルドに追加の依存関係が必要です。
Linux は [Linux](#linux)、macOS は [macOS](#macos) を参照してください。

## ソースコードの入手 {/* #getting-the-source-code */}

まず、**Ghostty のソース tarball をダウンロード**します。

<Warning>

Git リポジトリをチェックアウトして Ghostty をソースからコンパイルすることもできますが、
Ghostty の開発者や貢献者以外には**お勧めしません**。
ソース tarball にはさまざまな前処理済みファイルが含まれており、コンパイルに必要な依存関係が大幅に少なくなるためです。

Ghostty に貢献する場合、開発環境でのビルド方法は
[「Ghostty の開発」](https://github.com/ghostty-org/ghostty/blob/main/HACKING.md)を参照してください。
ほとんどの手順はまったく同じですが、以降は簡単にするため、ソース tarball からのビルドを前提とします。

</Warning>

安定版のソース tarball と付属のチェックサムは、`release.files.ghostty.org` の以下のパスにあります。
`VERSION` は `1.0.0` のようなプレフィックスなしのバージョン番号です。

```
https://release.files.ghostty.org/VERSION/ghostty-VERSION.tar.gz
https://release.files.ghostty.org/VERSION/ghostty-VERSION.tar.gz.minisig
```

署名ファイルは、次の公開鍵を使い、
[minisign](https://jedisct1.github.io/minisign/) で署名されています。

```
RWQlAjJC23149WL2sEpT/l0QKy7hMIFhYdQOFy0Z7z7PbneUgvlsnYcV
```

開発版（「tip」）のソース tarball は、[GitHub の `tip` リリース](https://github.com/ghostty-org/ghostty/releases/tag/tip)から、
`ghostty-source.tar.gz` という名前で入手できます。

<Important>

このソース tarball は、GitHub が自動生成する「Source code (zip)」や「Source code (tar.gz)」とは**異なります**。
自動生成版には前処理済みファイルが含まれず、Git のチェックアウトと同じ内容です。

</Important>

リリース tarball を展開し、展開されたソースフォルダーに移動します。

```sh
tar -xf ghostty-VERSION.tar.gz
cd ghostty-VERSION/

# Or when using a tip source tarball:
# (REVISION is the commit SHA of the latest commit)

tar -xf ghostty-source.tar.gz
cd ghostty-VERSION-main+REVISION/
```

Zig と必要な依存関係をインストールしたら、`zig build` でバイナリをビルドできます。

```sh
zig build -Doptimize=ReleaseFast
```

Linux では、すぐ使えるバイナリが `zig-out/bin/ghostty` に作成されます。
macOS では、アプリバンドルが `zig-out/Ghostty.app` に作成されます。

<Tip>

Linux ユーザーの方へ: システム全体またはユーザーアカウントにインストールするには、
[インストール先ディレクトリ](#installation-directory)を参照してください。

</Tip>

<Tip>

デバッグビルドには、`-Doptimize=ReleaseFast` フラグを省略します。
デバッグビルドはリリースビルドより**極めて低速**（100 倍以上遅い）なので、開発時にのみ使ってください。

</Tip>

## Linux {/* #linux */}

### 依存関係 {/* #dependencies */}

Linux では、ビルド前に Ghostty の依存関係のヘッダーパッケージをインストールする必要があります。
それ以外はデフォルトで Ghostty が静的にビルドするため、ソースからのビルドで必要な依存関係はわずかです。

必要な依存関係:

- `gtk4`
- `libadwaita`
- `gtk4-layer-shell`
- `pkg-config` または `pkgconf`
- `gettext`

<Important>

Git のチェックアウトを使う場合は、これらの依存関係もインストールする必要があります。

</Important>

<Tip>

お使いのディストリビューションに `gtk4-layer-shell` のパッケージがまだない場合
（Ubuntu 24.04、Debian 12、Linux Mint 22.1、OpenSUSE など）、
`zig build` に `-fno-sys=gtk4-layer-shell` フラグを追加し、Ghostty が `gtk4-layer-shell` をソースからコンパイルできるようにする必要があります。

</Tip>

#### Alpine {/* #alpine */}

```sh
doas apk add \
  gtk4.0-dev \
  libadwaita-dev \
  pkgconf \
  ncurses \
  gettext
```

#### Arch Linux {/* #arch-linux */}

```sh
sudo pacman -S \
  gtk4 \
  gtk4-layer-shell \
  pkgconf \
  libadwaita \
  gettext
```

#### Debian と Ubuntu {/* #debian-and-ubuntu */}

```sh
sudo apt install \
  libgtk-4-dev \
  libgtk4-layer-shell-dev \
  libadwaita-1-dev \
  gettext \
  libxml2-utils
```

Debian unstable/testing では、ビルドに `gcc-multilib` パッケージも必要です。

#### Fedora {/* #fedora */}

Fedora の各バリエーションでは、次を使います。

```sh
sudo dnf install \
  gtk4-devel \
  gtk4-layer-shell-devel \
  zig \
  libadwaita-devel \
  gettext
```

Fedora Atomic の各バリエーションでは、次を使います。

```sh
rpm-ostree install \
  gtk4-devel \
  gtk4-layer-shell-devel \
  zig \
  libadwaita-devel \
  gettext
```

#### Gentoo {/* #gentoo */}

```sh
emerge -av \
  libadwaita \
  gtk \
  blueprint-compiler \
  gettext
```

#### openSUSE Tumbleweed {/* #opensuse-tumbleweed */}

```sh

  gtk4-devel \

  pkgconf \
  ncurses-devel \
  zig \

```

#### openSUSE Leap {/* #opensuse-leap */}

```sh

  gtk4-devel \
```

### インストール先ディレクトリ {/* #installation-directory */}

`zig build` に `-p`（prefix）フラグを指定して、対象ディレクトリに Ghostty をインストールします。
これにより、シェル統合、アイコン、GTK ショートカットなどの機能がすべて動作する、適切な FHS ディレクトリ構造が作成されます。

管理者権限を使わないローカルインストールには、`$HOME/.local` をお勧めします。

```sh
zig build -p $HOME/.local -Doptimize=ReleaseFast
```

一般的な Freedesktop 対応のデスクトップ環境（GNOME、KDE など）では、これによりアプリランチャーから Ghostty を起動できるようになります。
すぐに表示されなければ、ログアウトして再ログインするか、場合によっては再起動が必要です。

アプリランチャーのアイコンから Ghostty を起動できない場合は、`~/.local/bin` が_システムの_ `PATH` に含まれていることを確認してください。
デスクトップ環境自体の `PATH` にそのパスが必要です。
設定方法は、お使いのデスクトップ環境とディストリビューションについて Google で検索してください。

`-fno-sys=gtk4-layer-shell` フラグで Ghostty をビルドした場合は、追加で `LD_LIBRARY_PATH` 環境変数を `$HOME/.local/lib` に設定する必要があるかもしれません。
デスクトップ環境から起動するときに `LD_LIBRARY_PATH` をグローバルに汚染しないようにするには、
`patchelf` でインストール済みの Ghostty ELF を修正するだけで済みます。

```shell-session
patchelf --set-rpath '$ORIGIN/../lib' $HOME/.local/bin/ghostty
```

システム全体へのインストールには、`/usr` をお勧めします（通常は `sudo` が必要です）。

```shell-session
zig build -p /usr -Doptimize=ReleaseFast
```

### Nix でのビルド {/* #building-with-nix */}

Nix ビルド環境には、ほかの [Nix 開発シェル](https://nix.dev/tutorials/first-steps/declarative-shell.html)と同じように、
`nix develop` コマンドで入れます
（[`nix-command` 実験的機能](https://nix.dev/manual/nix/2.24/development/experimental-features#xp-feature-nix-command)を有効にしていなければ `nix-shell` を使います）。

[`nix-direnv`](https://github.com/nix-community/nix-direnv) を使っている場合、Ghostty が提供する `.envrc` ファイルを `direnv allow` で読み込めます。
これにより、Ghostty リポジトリへの出入りに合わせて、開発環境にもシームレスに出入りできます。
Direnv は必須ではありません。

Nix 環境を設定したら、ほかのディストリビューションと同じ `zig build` を実行するか、
次のコマンドで Nix を使ってパッケージをビルドできます。

```sh
nix build .#ghostty
```

バイナリは `./result/bin/ghostty` に作成されます。

Nix でのビルド結果は Zig でのビルドと同じになるはずですが、再現性の保証が高まり、
Ghostty のすべての部分を確実にビルドできるようになります。

## macOS {/* #macos */}

### 依存関係 {/* #dependencies */}

#### Xcode {/* #xcode */}

macOS アプリケーションのビルドには、Xcode がインストールされ、アクティブな開発者ディレクトリが Xcode を指す macOS マシンが必要です。
不明な場合は、`xcode-select
--print-path` の出力を確認してください。

```sh
xcode-select --print-path
/Library/Developer/CommandLineTools        # <-- BAD

sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
xcode-select --print-path
/Applications/Xcode.app/Contents/Developer # <-- GOOD
```

上記の状態は、Xcode をインストールした_後に_ Xcode Command Line Tools をインストールすると発生することがあります。

次に、macOS SDK、iOS SDK、Metal Toolchain がインストールされていることを確認します
（Xcode → Settings → Components から確認できます）。

#### その他の依存関係 {/* #other-dependencies */}

Ghostty には、追加のライブラリ依存関係のインストールも必要です。
インストール方法は自由ですが、Homebrew を使うのが最も簡単です。

```sh
brew install gettext
```

<Note>
  **Nix 開発環境**を使っている場合、これらの依存関係は自動で処理されるため、手動でインストールする必要はありません。
</Note>

### Mac `.app` {/* #mac-.app */}

```sh
zig build -Doptimize=ReleaseFast
```

アプリは `zig-out/Ghostty.app` に出力されます。

作成されるアプリは、Xcode の「ReleaseLocal」ビルド設定を使います。
「ReleaseLocal」はローカルのリリースビルド専用の設定で、コード署名 ID などがなくても実行しやすいように、
「Library Validation」など一部のセキュリティ機能を無効にします。
このビルドは配布用ではありません。すべてのセキュリティ機能を備えたリリースビルドが必要な場合は、
[公式バイナリビルドを使ってください](/download)。
