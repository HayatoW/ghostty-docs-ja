Ghostty 1.4.0 は、パフォーマンスとメモリ使用量の大幅な改善、アニメーションと
相対配置を含む Kitty グラフィックスの完全な実装（Kitty 以外のターミナルでは初）、
SSH 統合の改善に加え、全プラットフォームでさらに数百件の改善と修正を
盛り込んだメジャーリリースです。

このリリースには、**172 人のコントリビューター**による**7 か月分の作業**が
**2,889 件のコミット**として含まれています。リリースの実現に力を貸してくださった
コントリビューター、メンテナー、コミュニティのモデレーター、翻訳者、
パッケージ作成者、ユーザーの皆さんに感謝します。

変更履歴の全文も含め、このリリースノートは Ghostty のメンテナーが人の手で、
丹精を込めて書き上げました。執筆には延べ 16 時間以上かかっています。
どうぞお楽しみください。🥰

## セキュリティ {/* #security */}

- [GHSA-4hwh-wx3w-3fqg](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-4hwh-wx3w-3fqg)。
  貼り付け保護がキャリッジリターンを行末として扱わなかったため、ブラケット付き
  ペーストを使わないプログラムでは、貼り付けによって確認なしにコマンドが
  実行されるおそれがありました。発生にはユーザー操作（コピー＆ペースト）が必要です。
- [GHSA-mhff-mv4q-fp63](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mhff-mv4q-fp63)。
  悪意のある Kitty グラフィックスコマンドによって、Ghostty のクラッシュや
  ハング、大量のメモリ割り当て、また限られた場合には、許可された一時ディレクトリ外の
  ファイルの読み取りや削除が起こるおそれがありました。悪意のある出力の表示だけで発生します。
- [GHSA-hcr9-7hcr-mjm8](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-hcr9-7hcr-mjm8)。
  悪意のあるターミナル出力により、tmux 制御モードを通じて Ghostty がクラッシュし、
  すべてのウィンドウが閉じるおそれがありました。tmux がインストールされていなくても
  発生します。Ghostty 1.3.0 と 1.3.1 が影響を受けます。
- [GHSA-hp9c-qp4q-cpw3](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-hp9c-qp4q-cpw3)。
  サイズがゼロまたは過大なペインを持つ tmux 制御モードのレイアウトで、
  上記と同じ影響が生じます。Ghostty 1.3.0 と 1.3.1 が影響を受けます。
- [GHSA-w9q4-5jvv-mcv4](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-w9q4-5jvv-mcv4)。
  画面の内容をスクロールバックへ送って消去する際、書式やハイパーリンクが設定された
  カーソルを保持するスクロールバックページが削除されると、メモリが破損するおそれが
  ありました。悪意のある出力の表示だけで発生しますが、`scrollback-limit` が
  `0` などの小さな値の場合に限られます。デフォルト値で影響が出ることは確認されていません。
- [GHSA-2r63-vmw6-3m3c](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-2r63-vmw6-3m3c)。
  細工されたディレクトリ名によって、zsh のシェル統合が任意のエスケープシーケンスを
  送信し、たとえば OSC 52 で知らない間にクリップボードを置き換えるおそれが
  ありました。影響はより限定的ですが bash にも及びました。クローンしたリポジトリ
  など、信頼できないコンテンツ内のディレクトリに `cd` で移動するだけで発生します。
- macOS: [GHSA-cw69-wm67-5pv8](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-cw69-wm67-5pv8)。
  細工された OSC 8 ハイパーリンクを Cmd キーを押しながらクリックすると、
  安全でないローカルファイルやカスタム URL スキームが開き、任意のコマンドが
  実行されるおそれがありました。Ghostty は安全でないリンク先を拒否し、
  カスタム URL スキームを開く前に確認するようになりました。発生にはユーザー操作
  （Cmd キーを押しながらのクリック）が必要です。
- macOS: [GHSA-mfw9-xcr3-7gfp](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mfw9-xcr3-7gfp)。
  デフォルトの URL マッチャーも含め、`link` 設定で検出するリンクにも
  上記と同じ問題がありました。発生にはユーザー操作（Cmd キーを押しながらのクリック）が必要です。
- macOS: [GHSA-v8cw-fg4j-jcc4](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-v8cw-fg4j-jcc4)。
  ドラッグ＆ドロップされたテキストには貼り付け保護が適用されず、上記と同じ影響がありました。
  発生にはユーザー操作（ドラッグ＆ドロップ）が必要です。
- macOS: [GHSA-mxqx-236q-wrv7](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mxqx-236q-wrv7)。
  名前に制御文字を含むファイルを開くと、確認ダイアログに表示されたものとは異なる
  コマンドが実行されるおそれがありました。発生には、システム上に細工された
  ファイルが存在し、確認ダイアログで承認する必要があります。

### macOS 27 対応 {/* #macos-27-support */}

関連 PR: GH-12999 GH-13069 GH-13393 GH-14413 GH-14414

Ghostty 1.4 は macOS 27 (Golden Gate) に対応しています。作業の大半は
互換性の修正でした。

- タイトルバー内のタブ（`macos-titlebar-style = tabs`）が再び正しく配置されるようになりました。
- ネイティブのタブバーが、テーマの上にべた塗りの灰色のバーとして表示されなくなりました。
  新しいガラス調のスタイルがターミナルの背景になじむようになりました。
- 「透明度を下げる」が有効でも、`macos-titlebar-style = hidden` が
  ターミナルの上端の行を覆わなくなりました。
- アプリのアイコンに細い枠が出なくなりました。
- Ghostty がウィンドウを開かずに動作している場合、ショートカットの
  「New Window」（新規ウィンドウ）アクションが 2 つのウィンドウを開かなくなりました。

Ghostty 1.4 は macOS 13 (Ventura) 以降の従来の macOS バージョンとも
引き続き完全に互換性があります。詳しくは[システム要件](#system-requirements)をご覧ください。

<Note>
  Ghostty 1.3.1 は macOS 27 で動作しますが、灰色のタブバーなど、
  上記の表示上の問題の一部が発生します。
</Note>

### Kitty グラフィックスのアニメーションと相対配置 {/* #kitty-graphics-animation-and-relative-placements */}

関連 PR: GH-13943 GH-13939 GH-13935 GH-13934 GH-13893 GH-13933 GH-13389
GH-13270 GH-13281

Ghostty は Kitty グラフィックスの
[アニメーション](https://sw.kovidgoyal.net/kitty/graphics-protocol/#animation)と
[相対配置](https://sw.kovidgoyal.net/kitty/graphics-protocol/#relative-placements)に
対応しました。これらは、Ghostty がまだ対応していなかった Kitty グラフィックス
プロトコルの最後の主要機能です。

`kitten icat` でアニメーション GIF を表示する場合など、Kitty プロトコルで
アニメーション画像を表示するプログラムで、静止画 1 枚ではなく実際にアニメーションが
表示されます。フレームの転送、合成、再生制御のすべてに対応し、ターミナルが
非表示の間はアニメーションを一時停止します。相対配置を使うと、ある画像を
別の画像の配置に対して相対的に置けるため、子画像が親画像と一緒に移動します。

また、仕様と Kitty 本体に照らして適合性を全面的に確認し、数十件の動作の違いを
修正しました。たとえば、スクロール領域で画像がテキストと一緒に移動するように
なり（GH-4323）、画像 ID を再送すると古い画像が置き換わります（GH-6711）。
無効な画像データを受け取ったときには、応答せずにクライアントを待たせるのではなく
エラーを返します。全項目は[ターミナルの機能](#terminal-capabilities)に記載しています。

Kitty グラフィックスは高速にもなりました。画像データを 1 バイトずつではなく
SIMD で一括解析するようにしたため、大きな画像の転送データの解析は
ベンチマークで**約 16 倍に高速化**しました（x86_64 Linux、64 MiB の画像データ）。
描画にかかるフレームあたりの処理負荷も大幅に減りました。

Kitty グラフィックスの公開仕様を 100% 実装し、Ghostty（および libghostty）は
Kitty 自体を除いて初めてこれを達成したターミナルとなりました。

### スクロールバックの圧縮とメモリ使用量の削減 {/* #scrollback-compression-and-lower-memory-usage */}

関連 PR: GH-13264 GH-13473 GH-13240 GH-13245 GH-14130 GH-14137 GH-14138
GH-14017

Ghostty は非表示のスクロールバックを透過的に圧縮するようになりました。
テキストが主体の一般的な履歴では、そのページに使う物理メモリを
**70% から 90%** 削減できます。圧縮はターミナルがアイドル状態のときだけ行い、
スクロールバックの表示や検索時に必要なページだけを展開するので、
I/O のスループットに測定可能な影響はありません。

圧縮のおかげで、**スクロールバックのデフォルト上限がターミナルあたり
10 MB から 50 MB に増えました。** 圧縮に対応するプラットフォームでは、
上限まで使っても、一般に従来の 10 MB の上限より物理メモリの使用量が少なくなります。

<Note>
  圧縮で減るのは*常駐*（物理）メモリで、*仮想*メモリではありません。
  測定時は常駐メモリを確認してください。現在は macOS と 64 ビット Linux で利用できます。
</Note>

スクロールバック以外でも、多くの箇所でメモリ使用量が減りました。

- macOS で空のターミナルを新しく開くときに使うターミナルページ用メモリは、
  Ghostty 1.3.1 の 128 KiB から約 **16 KiB** に減りました。
- macOS と Linux では、スクロールバックの消去や切り詰めで解放したメモリを、
  ターミナルを閉じるまで保持せずに OS に返却するようになりました。
- 非表示のタブは GPU リソースを解放します。macOS で表示中のタブが 1 つ、
  非表示のタブが 20 ある場合、GPU メモリは約 385 MiB から 18 MiB に減りました。
  タブが再び表示されたときのリソースの再構築には 1 ミリ秒もかかりません。

### パフォーマンスの改善 {/* #performance-improvements */}

関連 PR: GH-13209 GH-13220 GH-13226 GH-13227 GH-13537 GH-13827 GH-13587
GH-14011 GH-13722 GH-14035 GH-12760

Ghostty 1.4 では多方面でパフォーマンスを改善し、以前のバージョンを大幅に
上回る性能を実現しました。

最も効果が大きかったのは、意外な発見がきっかけでした。macOS のカーネルは、
読み取りバッファのサイズに関係なく、PTY からの 1 回の読み取りを約 1 KiB に
制限していました。以前の Ghostty は読み取りのたびに処理していたため、
1 KiB ごとに読み取りのオーバーヘッドが発生し、解析の間、出力を書き込む
プログラムは待たされていました。現在は、あるスレッドで PTY からデータを
読み取りつつ、別のスレッドで解析します。Ghostty 1.3.x に比べて macOS 上での
I/O 全体のスループットが **25% から 55%** 向上しました（M4 Max、プレーンテキストと Unicode テキスト）。

VT 処理自体も大幅に速くなりました。パーサーのベンチマークでは、プレーンな
ASCII テキストが 128 MB/s から 725 MB/s（5.7 倍）に、CJK テキストが 3.4 倍に
高速化し、[asciinema](https://asciinema.org/) の実際のターミナル録画
2.6 GB の処理は約 25% 速くなりました。これらの変更により、macOS で 150 MB の
テキストファイルを `cat` で出力する時間が 1.5 秒から 566 ミリ秒に短縮されました。

ほかの主な改善です。

- **サイズ変更:** 大きなスクロールバックを持つターミナルのサイズ変更が
  **約 6 倍**に高速化しました（120×80、スクロールバック 10,000 行）。
  CJK テキストや絵文字の多い履歴では 3 倍から 5 倍に高速化しました。
- **描画:** レンダラーが 1 フレームあたりにターミナルのロックを保持する時間を
  **2.7 分の 1 から 11 分の 1** に短縮し、大量出力時に I/O スレッドが
  処理できる時間を増やしました。
- **コピーと検索:** クリップボードへのコピー、`write_screen_file`、
  スクロールバック検索で使われる、ターミナルの内容のプレーンテキスト、
  HTML、VT への整形が 1.5 倍から 8 倍に高速化しました。
- **起動 (macOS):** 起動からウィンドウ表示までが約 15%、最初のフレームの描画までが
  27% 高速化しました。
- **アイドル時の電力消費:** macOS では描画するものがないときに、
  レンダラーのディスプレイリンクを休止します。GTK では macOS と同様、
  非表示のタブの描画を停止します。
- **大きな OSC シーケンス:** OSC 52 のクリップボードデータの解析が**約 30 倍**に、
  タイトル変更のような短いシーケンスでも約 6 倍に高速化しました。

### 新しい OpenGL レンダラー (Linux, FreeBSD) {/* #new-opengl-renderer-(linux-freebsd) */}

関連 PR: GH-14052 GH-14269

GTK 版の描画パイプラインが新しくなり、`GtkGLArea` を使わなくなりました。
レンダラーが専用スレッドで EGL を使って描画し、各フレームを DMABUF として
エクスポートして、表示を担当する GTK に渡します。トリプルバッファリングで
ティアリングを大幅に減らせるはずです。メインスレッドで OpenGL を呼び出さなくなり、
いくつもの回避処理を取り除けました。

最も目に見える成果は、整数倍でないスケーリングでも文字がくっきり表示されることです。
125% や 150% といった表示倍率でテキストや罫線文字がぼやけなくなりました（GH-1938）。
以前一度修正しましたが、上流の GTK の変更で再発していました。Ghostty は
ウィンドウの実際の倍率で描画するため、描画上の 1 ピクセルが画面上の
ちょうど 1 ピクセルに対応します。

新しい描画サーフェスにはシステムの EGL ライブラリが必要です
（[パッケージメンテナー向けの変更](#changes-for-package-maintainers)を参照）。
DMABUF をエクスポートできない GPU ドライバーでは、Ghostty は CPU 経由で
フレームをコピーします。速度は落ちますが、使用は可能です。

### Kitty クリップボードプロトコル {/* #kitty-clipboard-protocol */}

関連 PR: GH-13962 GH-13993 GH-13995 GH-13998 GH-14002 GH-14061

Ghostty は macOS と GTK の両方に
[Kitty クリップボードプロトコル](https://sw.kovidgoyal.net/kitty/clipboard/)
（OSC 5522）を実装しました。Ghostty 1.3 ではプロトコルの解析はできましたが、
実装はしていませんでした。

OSC 52 はプレーンテキストしか読み書きできません。Kitty クリップボードプロトコルにより、
ターミナル内のプログラムが画像や HTML などあらゆる種類のクリップボードデータを
読み書きし、クリップボード上の形式から選べます。プログラムはペーストイベント
（モード 5522）を有効化することもできます。貼り付けデータに含まれる形式が通知されるため、
必要なものを読み取れます。たとえば、ターミナルプログラムが貼り付けた画像を受け取れます。

クリップボードへのアクセスは既存の `clipboard-read` と `clipboard-write` 設定に
従います。デフォルトでは、読み取り時に許可を求め、書き込みは許可します。
許可を求める画面では、画像も含めてクリップボードの内容をプレビューできます。
パスワードを送るプログラムについては、そのターミナルセッションが終了するまで
回答を保持できます。新しい `clipboard-write-limit-bytes` 設定で、1 回あたりの
書き込みサイズを制限します（デフォルトは 64 MiB）。上限を超える書き込みは失敗し、
クリップボードの内容は変わりません。

### 分割のドラッグ＆ドロップ (GTK) {/* #split-drag-and-drop-(gtk) */}

関連 PR: GH-10423 GH-13706

Ghostty 1.3 で macOS に導入した機能と同じように、GTK でもドラッグして分割を
並べ替えられるようになりました。タブに分割が 2 つ以上あると、各分割の上端に
ドラッグハンドルが表示されます。ハンドルをつかみ、別のタブやウィンドウも含め、
ほかの任意の分割にドロップできます。オーバーレイで、移動先の分割のどちら側に
配置されるかが分かります。ターミナルの内容、作業ディレクトリ、実行中のプロセスは
すべて一緒に移動します。

macOS と GTK の両方に、ドラッグハンドルの表示条件を制御する新しい `drag-handle`
設定を追加しました。`auto`（デフォルト）、`always`、`never` から選べます。
`never` では、マウスで分割を並べ替えられません。ハンドルが邪魔なので隠したいという
要望は、ユーザーからよく寄せられていました。

GTK では、分割はほかの分割の上にしかドロップできません。分割を外へドラッグして
新しいタブやウィンドウを作成できるのは macOS だけです。

### ターミナルエミュレーションの精度 {/* #terminal-emulation-accuracy */}

関連 PR: GH-14454 GH-13494 GH-14483 GH-14538 GH-14673 GH-14375 GH-14144

Ghostty 1.4 には、ターミナルエミュレーションの中核部分に数十件の改善が含まれています。
Thomas Dickey のターミナル適合性テストスイートである
[esctest](https://github.com/ThomasDickey/esctest2) を、CI で Ghostty の
ターミナルコアに対して実行するようにしました。それに併せて、マージン内の
カーソル移動、タブストップ、文字セット、モード報告など、xterm との差を多数
修正しました。関連する変更の全一覧は[ターミナルの機能](#terminal-capabilities)をご覧ください。

ソフトターミナルリセット（DECSTR）、拡張カーソル位置報告（DECXCPR）、
後退キーのモード（DECBKM）、文字数単位での画面サイズ報告（`CSI 19 t`）など、
複数の新しいシーケンスにも対応しました。プログラムは
[可視性レポート](https://rockorager.dev/misc/visibility-reports/)（モード 2033）で
ターミナルが表示中かを問い合わせ、非表示の間に描画を止められるようになりました。

キーボードのエンコードも、`modifyOtherKeys` のモード 2 と非 ASCII キーで Alt を
Escape として扱う従来のエンコードを修正し、xterm により近づきました。

リモートマシン上のものも含め、信頼できないプログラムに悪用されるおそれがあるため、
次の 2 つの新しいシーケンスはデフォルトで無効です。

```
# Allow programs to resize the window (CSI 8 t)
vt-window-resize-allowed = true

# Allow programs to request screen checksums (DECRQCRA)
vt-xt-checksum-report = true
```

### `ghostty +ssh` による SSH 統合 {/* #ssh-integration-with-ghostty-+ssh */}

関連 PR: GH-12582 GH-12814 GH-13533 GH-13844 GH-14472 GH-14854

Ghostty 1.2 では[SSH シェル統合機能](/docs/features/ssh)を開発途中の機能として
導入しました。Ghostty 1.4 では、新しい CLI アクション `ghostty +ssh` が
これらの機能を担います。`ssh` の代わりにそのまま使えるラッパーで、
リモートセッションを Ghostty 用に準備し、引数を変更せずに本来の `ssh` を実行します。

```sh
ghostty +ssh user@example.com

# Or alias it so every ssh invocation goes through it
alias ssh='ghostty +ssh --'
```

接続前に、`+ssh` は Ghostty の terminfo をリモートホストにインストールして
`TERM` に適切な値 `xterm-ghostty` を使えるようにし、`COLORTERM`、
`TERM_PROGRAM`、`TERM_PROGRAM_VERSION` を転送します。terminfo の
インストールに失敗した場合（リモート側に `tic` がない場合など）は
`TERM=xterm-256color` にフォールバックします。`--terminfo=false`、
`--forward-env=false`、`--verbose` などのフラグで各段階を制御できます。

明示的に有効にする必要があるシェル統合機能 `ssh-env` と `ssh-terminfo` も、
`+ssh` を呼び出すようになりました。以前はシェルごとにこの処理を実装し、
シェル統合スクリプトのおよそ 3 分の 1 を占めていました。現在は bash、zsh、fish、
elvish、Nushell のすべてで同じように動きます。スクリプトなど、どこからでも
`ghostty +ssh` を直接呼び出せば、同じ動作を利用できます。

terminfo のインストール自体もより確実になりました。リモートに既存の
`xterm-ghostty` があってもそれを使わず、常に Ghostty 同梱の terminfo を
インストールします。Ghostty のアップデートによって terminfo が変われば、
自動で再インストールします。また、ローカルマシンの `infocmp` や Ghostty の
terminfo は不要になりました。インストールはホスト*と*ポートの組み合わせごとに
キャッシュされ、同じアドレスの先にある 2 台のマシンがキャッシュ項目を
共有することはありません。`ssh-env` が `~/.ssh/config` の `SetEnv` の
指定を黙って上書きすることもなくなりました（GH-11518）。

このキャッシュを管理する `+ssh-cache` コマンドは、接続先を位置引数で
受け付けるようになり（`ghostty +ssh-cache user@example.com`）、新しい
`--prune=30d` フラグも加わりました。スクリプトで `+ssh-cache` を使う場合は、
[互換性を壊す変更](#breaking-changes)をご覧ください。

## システム要件 {/* #system-requirements */}

**macOS:** Ghostty 1.4 が必要とする最小 macOS バージョンは、
macOS 13 Ventura のままです。Ghostty は macOS 27 に対応しました。

**GTK:** Ghostty 1.4 には **GTK 4.18** と **libadwaita 1.7** が必要です。
Ghostty 1.3 では GTK 4.14 と libadwaita 1.5 でした。これは
[GTK/Adwaita のバージョン方針](/docs/linux/#supported-gtkadwaita-versions)に
沿った要件です。特に Ubuntu 24.04 LTS はこの要件を満たしません。
古い GTK や Adwaita を使うシステムでは、Ghostty の旧バージョンや
Flatpak パッケージを使うことで、この要件を回避できます。GH-14330

**OpenGL (GTK):** 必要な OpenGL の最低バージョンは 4.3 のままですが、
Ghostty は GTK の OpenGL ウィジェットではなく EGL で描画するようになりました。
ほとんどの方は違いを意識せずに使えるはずですが、EGL エラーで Ghostty が
起動しない場合は、GPU ドライバーが動作する EGL 実装を提供しているか確かめてください。

<Important>
  以前は Ghostty 1.4 で macOS 14 が必要になるとお知らせしました。
  今回のリリースではそうする必要がなかったため、macOS 13 のサポートを残しました。
  **将来のリリースで macOS 13 の対応を終了する予定に変わりはありません。**
  Apple は 2025 年秋に macOS 13 のセキュリティサポートを終了しているため、
  いずれにせよアップグレードをおすすめします。
</Important>

## 互換性を壊す変更 {/* #breaking-changes */}

1.4.0 では、次の動作が変わりました。

- `copy-on-select` を作り直し、`none`、`primary`、`clipboard`、`both` を受け付けます。
  **`clipboard` の意味が変わりました。** 以前は選択クリップボードとシステムクリップボードの
  両方にコピーしていましたが、現在はシステムクリップボードだけにコピーします。
  `copy-on-select = clipboard` を指定していて以前の動作に戻したい場合は、
  `both` に変更してください。GH-12600 GH-12604
- macOS: `copy-on-select` のデフォルトが `true` から `none` になりました。
  デフォルトではテキストを選択してもコピーされず、中クリックによる選択内容の
  貼り付けも機能しません。1.3 の動作に戻すには `copy-on-select = primary` を指定してください。
  なお、macOS で `copy-on-select = true` を明示するとシステムクリップボードに
  選択内容がコピーされ、1.3 の動作とは異なります。GH-12600 GH-12604
- macOS: `cmd+arrow_up` と `cmd+arrow_down` が Terminal.app および Ghostty 1.2 と
  同じように、再び `jump_to_prompt` を実行するようになりました。1.3 では最上部と
  最下部へのスクロールに固定され、再割り当てはできませんでした。1.3 の動作を維持するには、
  `keybind = cmd+arrow_up=scroll_to_top` と
  `keybind = cmd+arrow_down=scroll_to_bottom` を指定してください。GH-12245
- GTK: デフォルトの `ctrl+shift+page_up` と `ctrl+shift+page_down` は、
  Firefox、GNOME Terminal、VS Code と同じように、現在のタブを左右に移動します（`move_tab`）。
  `jump_to_prompt` は `ctrl+shift+arrow_up` と `ctrl+shift+arrow_down` に
  移ったため、ターミナル内で実行するプログラムにはこれらのキー入力が渡らなくなります。
  使用しているプログラムで必要なら、`keybind = ctrl+shift+arrow_up=unbind` と
  `keybind = ctrl+shift+arrow_down=unbind` で割り当てを解除してください。GH-4998 GH-12458

### 非推奨になった項目 {/* #deprecations */}

以下の非推奨になった項目は互換レイヤーによって現時点では動作しますが、
そのまま使い続けると将来のリリースでは動作しなくなる可能性があります。

- 新しい `scrollback-limit-lines` を追加するため、`scrollback-limit` の名前を
  `scrollback-limit-bytes` に変更しました。GH-13473
- `copy-on-select = true` は Linux および FreeBSD では `copy-on-select = primary`、
  macOS では `copy-on-select = clipboard` に置き換わります。
  `copy-on-select = false` は `copy-on-select = none` に置き換わります。
  GH-12600 GH-12604

これらの非推奨項目を削除する時期は未定ですが、将来起こりうる問題を避けるため、
早めに新しい設定へ移行することをおすすめします。

### ローカライズ {/* #localization */}

Ghostty 1.4 ではコマンドパレットが全面的にローカライズに対応し、

- バスク語
- ベラルーシ語
- デンマーク語

ローカライズはボランティアのコントリビューターが維持しています。

ディスカッションを立ち上げてください。Ghostty のローカライズに貢献してくださった
すべてのボランティアの方々に感謝します。

### パッケージメンテナー向けの変更 {/* #changes-for-package-maintainers */}

- Ghostty のビルドには Zig 0.17 が必要になりました。GH-14518 GH-14519
- GTK ビルドの要件を GTK 4.14 と libadwaita 1.5 から **GTK 4.18** と **libadwaita 1.7** に引き上げました。古いヘッダーでビルドするとコンパイル時に失敗し、実行時に古いライブラリが読み込まれると Ghostty は起動時に終了します。GH-14330
- GTK ビルドでは、新しいレンダラー用にシステムの EGL ライブラリ（pkg-config の `egl`。通常は libglvnd または Mesa が提供）をリンクします。実行時には、可能なら GTK の EGL ディスプレイを使用し、不可能な場合はサーフェスレスプラットフォームに対応する EGL ドライバーが必要です。GH-14052 GH-14636
- 新しいビルドオプション `-Dinstalled-exe-path` で、デスクトップファイル、D-Bus サービス、systemd のユーザーサービスに書き込む実行ファイルの絶対パスを指定します。以前はインストールプレフィックスからパスを取得していました。このオプションを省略すると、各ファイルには `ghostty` だけが書き込まれます。systemd が見つけられるのは `/usr/bin` と `/usr/local/bin` にある場合だけなので、それ以外のプレフィックスでは指定してください。GH-14805 GH-14806
- システムの gtk4-layer-shell をリンクする場合（`-fsys=gtk4-layer-shell`）、1.0.4 以降が必要になりました。古いバージョンでも Ghostty がクイックターミナルを無効にしなくなったため、一部のコンポジターでクラッシュする可能性があります。GH-11559

## Libghostty {/* #libghostty */}

1.3 と同じく、libghostty は Ghostty 1.4 のリリースに直接含まれていません。
ただし 1.4 の開発サイクルの多くを libghostty に費やしたので、進捗をお伝えします。

過去 6 か月で、libghostty-vt の C API はパーサーと数個のエンコーダーから、
完全なターミナルエミュレーター API に成長しました。数百万人が利用する、
数十の無償・商用ターミナルエミュレーターに採用されています。
正確に測るのは難しいものの、libghostty ベースのターミナルの利用者は、
Ghostty の GUI の利用者の数倍に上ると見ています。

libghostty-vt は、macOS、Linux、Windows (MSVC と GNU)、FreeBSD、Android、
iOS、WebAssembly 向けにビルドでき、そのすべてを CI で継続的に検証しています。
無理のない範囲でどこでも使えるようにすることが目標なので、ほかのターゲットへの
対応をご希望ならお知らせください。

既存のビルドシステムへの libghostty-vt の組み込みも簡単になりました。
既存の pkg-config ファイルに加えて、CMake のサポート、Nix パッケージ、
xcframework、ソースの tarball がそろっています。
**libghostty-vt に libc++ は不要になり、フリースタンディングでビルドできます。**

API はまだ開発中と明記しており、この開発サイクルでも何度か互換性が壊れました。
タグ付きリリースまでに、さらに互換性を壊す変更が入ると見込んでください。
[API ドキュメント](https://libghostty.tip.ghostty.org/index.html)と、
現在 30 件を超える [Zig、C、C++、Swift、WebAssembly のサンプル](https://github.com/ghostty-org/ghostty/tree/main/example)は、
`main` に合わせて更新しています。

C API を最後にもう一度見直し、ABI の互換性をもう一度壊す変更を加えてから、
おそらくもう間もなく libghostty 1.0 のリリースタグを付ける予定です。

## ロードマップ {/* #roadmap */}

ロードマップでは引き続き、libghostty の機能、安定性、移植性に最も力を入れます。
前回のリリースサイクルでは、libghostty のリリースタグを付けることを目標に
掲げました。まだ実現していませんが、Ghostty 1.5 までにはできると確信しています。

libghostty は引き続き、すべてを底上げするプロジェクトです。libghostty の改善は
Ghostty の GUI だけでなく、同じエコシステムにある数十の大規模プロジェクトの改善に
直接つながります。大規模プロジェクトの採用が増えれば、libghostty に対する
テストや関心も増えやすくなり、その好循環があらゆるターミナルエミュレーターに
最大の恩恵をもたらします。

Ghostty の macOS 版と GTK 版では、有能なメンテナーチームが改善を続けており、
決しておろそかにされてはいません。プロジェクトとして、Ghostty の GUI の
Windows 対応はロードマップから外すことにしました。libghostty は Windows に
完全に対応しており、CI でもテストしています。下流のプロジェクトには
libghostty を使ってもらう、というのが現在の公式見解です。

リリースサイクルは 6 か月のままです。今回のリリースは 1 か月遅れましたが、
Ghostty 1.5 は 2027 年 3 月を予定しています。libghostty は別のリリースサイクルになります。
