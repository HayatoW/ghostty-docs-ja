プレリリースのソフトウェアを使うことに抵抗がなければ、Ghostty のプレリリースビルドを実行して、
最新機能のテストに協力し、最新のバグ修正を利用できます。
新機能へのフィードバックや、一般公開前の潜在的な問題への対処につながり、プロジェクトに大きく貢献できます。

<Note>
Ghostty のプライベートベータ期間中、テスターはこれと同じ手順でプレリリースビルドを日常的に使っていました。
何か月も、あるいは 1 年以上も一度も問題が起きなかった方も多くいました。
プレリリースビルドはおおむね安定していますが、安定性の問題が起こる可能性には常に備えてください。
</Note>

以下にプレリリースビルドのインストール方法の概要を示します。
詳しい説明は、表の後の各セクションを参照してください。

| プラットフォーム | 説明 |
| -------- | ----------- |
| macOS | `auto-update-channel` で最新のプレリリースビルドを取得します |
| Arch Linux | AUR の `ghostty-git` |
| NixOS / ほかのディストリビューション上の Nix | Ghostty リポジトリ内の Flake |
| ほかの Linux ディストリビューション | [ソースからビルド](/docs/install/build) |

## macOS {/* #macos */}

macOS 向けには、Ghostty プロジェクトが `main` ブランチの最新コミットから署名・公証済みのビルドを提供しています。
[GitHub Releases](https://github.com/ghostty-org/ghostty/releases/tag/tip) のほか、
macOS 標準の自動更新の仕組みでも取得できます。

リリースビルドを使っている場合は、[`auto-update-channel`](/docs/config/reference#auto-update-channel) を `tip` に設定すると、プレリリースチャネルに切り替えられます。

```ini
auto-update-channel = tip
```

<Tip>
`auto-update-channel` を変更したら、忘れずに Ghostty を再起動してください！
この設定は Ghostty を再起動するまで反映されません。
</Tip>

<Warning>
この設定はいつでも `stable` に戻せますが、より新しい安定版が利用可能になったときに初めて反映されます。
以前の安定版にダウングレードするには、Ghostty を[再ダウンロード](/download)する必要があります。
</Warning>

<Note>
**なぜ「tip」という設定名なのですか？** 「tip」は、Git でブランチの最新コミットを指す一般的な用語です。
プレリリースビルドは `main` ブランチの最新コミットからビルドするため、
最新のプレリリースビルドを「nightly」などではなく「tip」と呼んでいます。
</Note>

### Homebrew {/* #homebrew */}

Homebrew でも、`@tip` バージョンを使ってプレリリースビルドをインストールできます。

```shell-session
brew install --cask ghostty@tip
```

<Warning>
こちらはコミュニティによって保守されています。
`auto-update-channel` 設定は公式の配布チャネルです。
</Warning>

## Linux {/* #linux */}

### AUR {/* #aur */}

<Warning>

AUR パッケージはコミュニティによって保守されています。
パッケージ化やビルド手順に関する問題は、まず AUR のメンテナーに報告し、その後 Ghostty プロジェクトに報告してください。

</Warning>

Arch User Repository（AUR）の [`ghostty-git`] パッケージを使うと、
Ghostty の最新プレリリース版を簡単に自動ビルドしてインストールできます。

[`ghostty-git`]: https://aur.archlinux.org/packages/ghostty-git

インストールには AUR ヘルパーを使うか、[通常の AUR の手順](https://wiki.archlinux.org/title/Arch_User_Repository#Installing_and_upgrading_packages)に従ってソースからビルドできます。

```sh
# Install Ghostty git
yay -S ghostty-git
```

### Nix Flake {/* #nix-flake */}

Ghostty リポジトリには、開発版（「tip」）の Ghostty を再現可能な方法でビルド、実行、インストールできる Flake が付属しています。
Ghostty のメンテナー自身が、主要な開発・CI 環境として直接使用し、テスト・保守しています。

```sh
# Build and run the latest tip version of Ghostty without installing
nix run github:ghostty-org/ghostty
```

<Note>

Nix エコシステムの制限により、この Flake は現在 macOS ビルドに対応していません。
詳しくは、「ビルド済みバイナリとパッケージ」ページの [Nix（macOS バイナリ）](/docs/install/binary#nix-(macos-binary))を参照してください。

</Note>

<Warning>

NixOS 以外のシステムに Flake をインストールする場合は、Nix でビルドした OpenGL プログラムを NixOS 以外で実行する際の
[重要な注意事項](/docs/install/binary#nix-on-other-distros)を必ずお読みください。
そこで説明する回避策なしでは、Ghostty は**起動に失敗する**可能性が高いです。

</Warning>

NixOS ユーザーは、`packages.<system>.default` のパッケージを直接インストールするか
（`<system>` は `x86_64-linux` など、現在のホストシステムです）、`overlays.default` のオーバーレイを使用できます。

```nix
{
  pkgs,
  inputs,
}:
{
  # Installing the package directly
  users.users.somebody.packages = [
    inputs.ghostty.packages.${pkgs.stdenv.hostPlatform.system}.default
  ];

  # Alternatively, using overlays:
  nixpkgs.overlays = [
    inputs.ghostty.overlays.default
  ];
  users.users.somebody.packages = [
    pkgs.ghostty
  ];
}
```

Flake は、異なる最適化設定でコンパイルした Ghostty も公開しています。
`ghostty-debug`、`ghostty-releasefast`、`ghostty-releasesafe` があり、デフォルトは `releasefast` です。
`debug` はパフォーマンスと引き換えに詳しいデバッグ情報を提供し、`releasesafe` はほとんど使われません。

`debug` と `releasefast` は、それぞれ `overlays.debug` と `overlays.releasefast` のオーバーレイとしても利用できます。
