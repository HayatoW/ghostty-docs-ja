Ghostty は、高速、多機能、ネイティブであることを特徴とするターミナルエミュレーターです。
優れたターミナルエミュレーターは数多くありますが、どれも速度、機能、ネイティブ UI のいずれかを選ばなければなりません。
Ghostty はこの 3 つすべてを提供します。

すべての分野において、Ghostty が最高（つまり、最速、最多機能、最もネイティブ）だと主張するつもりはありません。
しかし、Ghostty を作り始めたとき、どのターミナルでもこれらの分野から最大 2 つしか選べないと感じていました。
3 つすべての分野で競争力のあるターミナルを作りたいと思い、Ghostty はその目標を達成していると考えています。

詳細に入る前に、Ghostty は [Mitchell Hashimoto](https://mitchellh.com)
（私です！）が情熱から始めたプロジェクトであることもお伝えしておきます。
自由な時間に取り組んでいる、愛情を注いだ活動です。このプロジェクトに関わる際は、このことを忘れないでください。
素晴らしい貢献者の皆さんとともに、優れたものを作ろうと最善を尽くしていますが、私たちの誰にとってもフルタイムの仕事ではありません。

## ネイティブ {/* #native */}

「ネイティブ」の大きな意味は、Ghostty が、皆さんのデスクトップ環境でアプリケーションに期待する見た目、使い心地、動作になるよう設計されているということです。

重要なのは、Ghostty が macOS と Linux 向けのネイティブアプリケーションであるという点です。
macOS では、GUI は Swift で書かれ、AppKit と SwiftUI を使用しています。
Linux では、GUI は Zig で書かれ、GTK4 C API を使用しています[^1]。
これらの GUI は、私たちが「libghostty」と呼ぶ、Zig で書かれた共通のコアと連携します。
Zig をご存じない方のために説明すると、ネイティブの機械語にコンパイルされるシステムプログラミング言語です。

その一環として、タブ、分割、エラーメッセージなどの機能にネイティブ UI コンポーネント[^2]を使用しています。
これは、テキスト UI やカスタムウィジェットを使用したり、そもそもこれらの機能をサポートしていなかったりする、多くのほかのターミナルエミュレーターとは対照的です。

もう 1 つは、すでに使い慣れている標準的なキーボードとマウスのショートカットを使用することです。
Ghostty は、各プラットフォームの慣習に合わせ、macOS と Linux で異なるデフォルトのキーバインドを使用します。

そして 3 つ目は、実行しているプラットフォーム固有のシステム機能と統合することです。
たとえば macOS では、Ghostty は Quick Look、感圧タッチ、macOS のセキュア入力 API、
再起動時の組み込みウィンドウ状態復元などをサポートしています。
これらはすべて macOS が提供するネイティブ API であり、Linux デスクトップ環境には同等のものがありません。

## 多機能 {/* #feature-rich */}

Ghostty は、日常的な使用に役立つ豊富な機能の提供を目指しています。
これらは、ターミナル機能とアプリケーション機能の 2 つに分類できます。

ターミナル機能には、ターミナル内で実行されるプログラムが利用できる機能が含まれます。
たとえば、Ghostty は Kitty グラフィックスプロトコル、ライトモード・ダークモードの通知、ハイパーリンクなどをサポートしています。
これにより、Neovim や Zellij などのターミナルアプリケーションは、ほかのターミナルエミュレーターよりも多くのことを実現できます[^3]。

アプリケーション機能とは、ターミナルエミュレーター自体を操作する際に役立つ、より高水準の機能です。
たとえば、Ghostty はネイティブのタブ、分割、macOS のドロップダウンターミナル、
システムのダークモード・ライトモードに応じたテーマの切り替えなどをサポートしています。

## 高速 {/* #fast */}

Ghostty は高速であることを目指しています。

パフォーマンスは議論が白熱しがちな分野なので、私が主張するのは、Ghostty が最速のターミナルエミュレーターと同じクラスを目指しているということだけです。
ベンチマークによって速い場合も遅い場合もありますが、いずれの場合も Ghostty が遅いとは言えないはずです。

「高速」という言葉も、人によって異なる意味を持つため、一筋縄ではいきません。
たとえば、「高速」になり得るものを少し挙げるだけでも、起動時間、スクロール速度、
IO スループット、制御シーケンスのスループット、フレームレートなどがあります。

将来的には、さまざまなパフォーマンス分野で Ghostty がどのように動作するかについて、詳細なベンチマークと説明を提供したいと考えています。
最初の一般公開リリースでは、Ghostty は上記の意味で「高速」を目指している、とだけ述べておきます。

ターミナルエミュレーターにとって速度はそれほど重要ではないと考える人が多いことは承知しています。
しかし、Ghostty を使い始めたユーザーからは、日常の使用で速度の向上をはっきりと感じられることにとても驚いたと、繰り返し聞きました。
皆さんにも同じように感じていただければ幸いです。

## libghostty {/* #libghostty */}

Ghostty は、そのアーキテクチャも特徴です。
Ghostty のコアは、`libghostty` というクロスプラットフォームの C ABI 互換ライブラリです。
`libghostty` は、ターミナルエミュレーション、フォント処理、レンダリングの中核機能を提供します。

Ghostty の GUI アプリケーションは `libghostty` を利用します。
macOS アプリは Swift で書かれ、AppKit と SwiftUI を使用し、`libghostty` の C API にリンクします。
Linux アプリは Zig で書かれ、GTK4 C API を使用し、同じく `libghostty` にリンクします[^4]。

このアーキテクチャにより、ターミナルエミュレーションと GUI を明確に分離できます。
これは、Ghostty が[ネイティブ](#native)であるという目標を達成するための重要なアーキテクチャです。

Ghostty プロジェクトは、共通のコアの上にほかのターミナルエミュレータープロジェクトを構築できるようにすることも目指しており、このアーキテクチャが Ghostty を独自のものにしています。
これにより、中核となるターミナルエミュレーションを再実装することなく、より高水準の機能や UI に注力できる、多様なターミナルエミュレーターのエコシステムが実現します。

<Note>
最初の一般公開リリース時点では、`libghostty` の API はまだ安定しておらず、独立した安定版ライブラリとしてもリリースされていません。
ただし、macOS と Linux の GUI アプリケーションではすでに使用されています。
将来的には API を安定させ、独立したライブラリとしてリリースすることを目指しています。
</Note>

[^1]: Linux には macOS のような「ネイティブ」の GUI ツールキットはありませんが、
GTK4 は既存の GUI ツールキットの中で標準に最も近いものです。
何よりも、カスタムウィジェットを描画しないため、Ghostty は皆さんのデスクトップ環境に自然になじみます。

[^2]: Linux では GTK4 と（任意で）Adwaita を使用するため、Ghostty は GTK4 アプリケーションらしい見た目と使い心地になります。
これが「ネイティブ」かどうかは、デスクトップ環境と「ネイティブ」の定義によって異なります。
注 1 も参照してください。

[^3]: たとえば、Neovim はフレーム間のティアリングを防ぐために同期レンダリングを使用します。

[^4]: GTK4 アプリは Zig で書かれているため、従来の意味でのリンクは行いません。
代わりに、公開された `libghostty` API を使用し、単一の Zig コンパイル単位としてコンパイルします。
