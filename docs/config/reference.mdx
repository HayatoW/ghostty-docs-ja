Ghostty のすべての設定オプションのリファレンスです。これらのオプションは、おおむね使用頻度順に並べ、関連するオプションごとにまとめています。目的のオプションを探すには、ブラウザーの検索機能を使うことをおすすめします。

将来的には、これらのオプションをより使いやすい形で表示・整理できるようにする予定です。

## `language`

Ghostty のグラフィカルユーザーインターフェースの言語を、システムのデフォルト言語以外に設定します。たとえば、次のように指定します。

```
language = de
```

この設定では、Ghostty のグラフィカルユーザーインターフェースの文字列が、システムのデフォルト言語ではなくドイツ語になります。

これは、Ghostty の*内部で*実行するプログラムが使う言語には影響しません。それらは引き続きシステムのデフォルト言語を使います。また、Ghostty には翻訳されていない非 GUI 要素も多数あり、この設定はそれらには影響しません。

<Warning>
 この設定は実行時に再読み込みできません。言語を変更するには、Ghostty を完全に再起動する必要があります。
</Warning>

GTK のみ。
1.3.0 以降で利用可能です。

## `font-family`
## `font-family-bold`
## `font-family-italic`
## `font-family-bold-italic`

使用するフォントファミリーです。

CLI を使って有効な値の一覧を生成できます。

```
ghostty +list-fonts
```

この設定を複数回指定すると、要求されたコードポイントが主フォントにない場合に使う、優先的なフォールバックフォントを指定できます。これは、多言語や記号フォントなどで特に便利です。

特に絵文字についての注意点として、Ghostty はデフォルトで macOS では常に Apple Color Emoji を、Linux では常に Noto Emoji を使います。ここで絵文字のグリフを含むフォントファミリーを指定すると、この動作を上書きできます。

個別のスタイル（太字、斜体、太字斜体）を明示的に設定する必要はありません。スタイルが設定されていない場合、標準スタイル（font-family）から対応するスタイルのバリエーションを探します。バリエーションが見つからない場合、Ghostty は標準スタイルを使います。これにより、太字などのスタイルを得るためだけに別のフォントファミリーへフォールバックすることを防ぎます。これは、スタイルに対してフォントファミリーを明示的に指定した場合も同様です。たとえば、`font-family-bold = FooBar` と設定しても「FooBar」が見つからない場合、Ghostty は `font-family` に設定されたフォントを太字スタイルに使います。

最後に、サポートされていないスタイルは合成される場合があります。たとえば、フォントに斜体スタイルがなく、代替の斜体フォントも指定されていない場合、Ghostty は標準スタイルを傾けて斜体スタイルを合成します。これらの合成スタイルを無効にしたい場合は、後述の `font-style` 設定を使えます。

`font-style` の一連の設定を使うと、スタイルを完全に無効にできます。詳しくは、`font-style` のドキュメントを参照してください。

フォールバックを追加するのではなく、以前設定した値を上書きしたい場合は、値に `""`（空文字列）を指定して一覧をリセットしてから、新しい値を設定します。例を示します。

```
font-family = ""
font-family = "My Favorite Font"
```

これらを CLI 引数として設定すると、設定ファイルで指定した値は自動的に消去されるため、新しい値を設定する前に `--font-family=""` を指定する必要はありません。設定ファイル内で以前設定した値を消去する場合は設定ファイル内で、CLI で設定した値を消去する場合は CLI でのみ、この指定が必要です。

## `font-style`
## `font-style-bold`
## `font-style-italic`
## `font-style-bold-italic`

要求された各ターミナルフォントスタイルに使用する、名前付きのフォントスタイルです。フォント自体が公開しているフォントスタイル文字列を使って、スタイルを検索します。たとえば、「Iosevka Heavy」のスタイルは「Heavy」です。

これらのフィールドを使って、フォントスタイルを完全に無効にすることもできます。以下の設定の値をリテラルの `false` にすると、そのフォントスタイルが無効になります。ターミナルで実行中のプログラムが無効なフォントスタイルを要求した場合は、代わりに標準のフォントスタイルを使います。

これらは、対応する font-family も指定されている場合にのみ有効です。font-family が指定されていない場合、フォントスタイルを無効にする場合を除き、font-style は無視されます。

## `font-synthetic-style`

指定された font-family に要求されたスタイルがない場合に、Ghostty がスタイルを合成するかどうかを制御します。

Ghostty は、フォントに特定のスタイルがない場合に、太字、斜体、太字斜体を合成できます。太字では、グリフの周囲に太さを変えた輪郭を描画します。斜体では、グリフを傾けます。太字斜体では、これらの両方を適用します。

合成スタイルは完全ではなく、通常、そのスタイルを本来備えたフォントほど見栄えはよくありません。ただし、フォントにそのスタイルがない場合に、スタイル付きのテキストを表示するのに役立ちます。

「false」または「true」に設定すると、合成スタイルをすべて無効または有効にできます。「no-bold」、「no-italic」、「no-bold-italic」を使うと、特定のスタイルを無効にできます。カンマで区切ると、複数のスタイルを無効にできます。たとえば、「no-bold,no-italic」です。

使用できるスタイルキーは、`bold`、`italic`、`bold-italic` です。

合成スタイルが無効の場合、要求されたスタイルがなければ、代わりに標準スタイルを使います。フォントに要求されたスタイルがある場合、それは合成ではないため、そのまま使います。

<Warning>
 よくある間違いは、`bold` や `italic` を無効にしても、`bold-italic` を無効にしないことです。`bold` や `italic` だけを無効にしても、`bold-italic` スタイルのどちらの要素も無効にはなりません。`bold-italic` を無効にするには、明示的に無効にする必要があります。`bold-italic` を部分的に無効にすることはできません。
</Warning>

デフォルトでは、合成スタイルは有効です。

## `font-feature`

フォント機能を適用します。複数のフォント機能を有効にするには、この設定を複数回指定するか、機能設定をカンマ区切りで指定します。

機能設定の構文は次のとおりです。`feat` は機能を表します。

  * 機能を有効にする例は、`feat`、`+feat`、`feat on`、`feat=1` です。
  * 機能を無効にする例は、`-feat`、`feat off`、`feat=0` です。
  * 機能の値を設定する例は、`feat=2`、`feat = 3`、`feat 4` です。
  * 機能名を引用符で囲むこともできるため、この設定は CSS の `font-feature-settings` プロパティと構文上互換性があるはずです。

構文はかなり柔軟ですが、無効な設定は通知なく無視されます。

フォント機能は Ghostty が描画するすべてのフォントに適用されます。将来の機能拡張で、特定のフェイスを対象にできるようになる予定です。

プログラミング用の合字を無効にするには、`-calt` を使います。これは、プログラミング用の合字に一般的に使われる機能名です。フォントにどのような機能があり、それらが何をするかを調べるには、[fontdrop.info](https://fontdrop.info) などのフォント検査ツールを使ってください。

大半の合字を全般的に無効にするには、`-calt, -liga, -dlig` を使います。

## `font-size`

ポイント単位のフォントサイズです。整数でない値も指定でき、最も近い整数のピクセルサイズが選ばれます。1pt = 2px の高 DPI ディスプレイでは、0.5 ポイント刻みで指定することで、奇数のピクセルサイズにできます。

たとえば、13.5pt × 2px/pt = 27px です。

実行時にこの設定を変更した場合、既存のターミナルのうち、フォントサイズを何らかの方法で手動調整（拡大や縮小など）していないものだけが影響を受けます。フォントサイズを手動調整したターミナルは、そのサイズを維持します。それ以外の既存のターミナルでは、再読み込み時にフォントサイズが更新されます。

GTK を使う Linux では、ディスプレイ全体とテキスト専用の両方の倍率に応じて、フォントサイズが拡大縮小されます。これらは多くの場合、デスクトップ環境で管理されます（GNOME のディスプレイ倍率や大きな文字の設定など）。

## `font-variation`
## `font-variation-bold`
## `font-variation-italic`
## `font-variation-bold-italic`

バリアブルフォントの 1 つ以上のバリエーション値を設定する、複数回指定可能な設定です。バリアブルフォントとは、通常ファイル名が `-VF.ttf` または `-VF.otf` で終わる単一のフォントで、太さや傾きなどを設定するための軸を 1 つ以上含みます。すべてのフォントがバリエーションに対応しているわけではなく、バリアブルフォントであると明示されているフォントだけが使えます。

形式は `id=value` で、`id` は軸の識別子です。軸の識別子は、`wght` のような常に 4 文字の文字列です。対応する軸の一覧を確認するには、フォントのドキュメントを参照するか、フォント検査ツールを使ってください。

無効な識別子や値は通常無視されます。たとえば、フォントが 100 から 700 までの太さにしか対応していない場合、`wght=800` を設定しても何も起こりません（700 に制限されることもありません）。対応する値は、フォントのドキュメントで確認する必要があります。

一般的な軸には、`wght`（太さ）、`slnt`（傾き）、`ital`（斜体）、`opsz`（オプティカルサイズ）、`wdth`（幅）、`GRAD`（グラデーション）などがあります。

## `font-codepoint-map`

単一または範囲指定の Unicode コードポイントを、特定の名前付きフォントに強制的に割り当てます。特殊記号に対応したい場合や、使用するフォントでより適切に表示される特定のグリフを使いたい場合に便利です。

構文は `codepoint=fontname` で、`codepoint` は単一のコードポイントまたは範囲です。コードポイントは、`U+ABCD` のように完全な Unicode の 16 進数値で指定する必要があります。コードポイントの範囲は `U+ABCD-U+DEFG` と指定します。`U+ABCD-U+DEFG,U+1234-U+5678=fontname` のようにカンマで区切ると、同じフォントに複数の範囲を指定できます。フォント名は、`font-family` で使うものと同じ値です。

この設定を複数回指定すると、複数のコードポイントの割り当てを指定できます。

実行時にこの設定を変更した場合、新しいウィンドウやタブなど、新規のターミナルだけに影響します。

## `clipboard-codepoint-map`

テキストをクリップボードにコピーするときに、特定の Unicode コードポイントを置換後の値に割り当てます。

この設定を使うと、ターミナルの内容をクリップボードにコピーするときに、特定の Unicode 文字を別の文字や文字列に置換できます。ターミナル固有の特殊記号を互換性の高い文字に変換し、他のアプリケーションへ貼り付ける場合に便利です。

構文は `font-codepoint-map` と似ています。
- 単一のコードポイント: `U+1234=U+ABCD` または `U+1234=replacement_text`
- コードポイントの範囲: `U+1234-U+5678=U+ABCD`

例:
- `clipboard-codepoint-map = U+2500=U+002D`（罫線の横線 → ハイフン）
- `clipboard-codepoint-map = U+2502=U+007C`（罫線の縦線 → パイプ）
- `clipboard-codepoint-map = U+03A3=SUM`（ギリシャ文字のシグマ → 「SUM」）

この設定を複数回指定すると、複数の割り当てを指定できます。範囲が重複する場合、後のエントリーが前のエントリーより優先されます。

<Note>
 これはテキストのコピー操作だけに適用され、URL のコピーには適用されません。
</Note>

## `font-thicken`

対応している場合、フォントの線を太く描画します。現在は macOS でのみサポートされています。

## `font-thicken-strength`

`font-thicken` が有効な場合の、線を太くする強さです。

有効な値は `0` から `255` までの整数です。`0` は太くする処理を*行わない*という意味ではなく、利用できる最も弱い強さに対応します。

`font-thicken` が `false` の場合は効果がありません。

現在は macOS でのみサポートされています。

## `font-shaping-break`

フォントのシェーピングを複数のランに分割する位置です。

「ラン」とは、一緒にシェーピングされる連続したテキストの区間です。「シェーピング」とは、テキスト（コードポイント）をグリフ（描画可能な文字）に変換する処理です。合字の形成などがこの処理で行われます。たとえば、コーディング用フォントが「!=」を単一のグリフに変換するには、「!」と「=」が同じラン内で隣接している必要があります。ランが分割されると、テキストは別々にシェーピングされます。この例でいえば、「!」があるランの末尾にあり、「=」が次のランの先頭にある場合、合字は形成されません。

Ghostty は、読みやすさや使いやすさを向上させるために、特定の位置でランを分割します。たとえば、デフォルトではカーソルの下でランを分割し、テキスト編集時に合字ではなく個々の文字を確認できるようにします。この設定で、その動作を設定できます。

値をカンマで区切ると、複数のオプションを設定できます。オプションに「no-」を付けると無効になります。有効化と無効化は同時に指定できます。

利用可能なオプション:

  * `cursor` - カーソルの下でランを分割します。

1.2.0 以降で利用可能です。

## `alpha-blending`

アルファブレンディングの実行時に使う色空間です。

テキストと、透明度を持つ画像の外観に影響します。また、カスタムシェーダーには、設定した色空間の色が渡されます。

macOS でのデフォルトは `native`、その他のプラットフォームでのデフォルトは `linear-corrected` です。

有効な値:

* `native` - OS のネイティブ色空間でアルファブレンディングを行います。macOS では Display P3、Linux では sRGB に対応します。

* `linear` - 線形空間でアルファブレンディングを行います。特定の色の組み合わせ（赤と緑など）で特に目立つ、テキストの縁が暗くなるアーティファクトを解消しますが、暗いテキストは通常よりかなり細く、明るいテキストはかなり太く見えます。「ガンマ補正」と呼ばれることもあります。

* `linear-corrected` - `linear` と同じですが、テキストに補正処理を適用し、暗くなるアーティファクトを発生させずに、`native` とほぼ同じ、または完全に同じ外観にします。

1.1.0 以降で利用可能です。

## `adjust-cell-width`
## `adjust-cell-height`

これらの設定はいずれも、フォントによって決まる各種のメトリクスを調整します。値には整数（1、-1 など）またはパーセンテージ（20%、-15% など）を指定できます。どちらの場合も、元の値からの変更量を表します。

たとえば、`1` は値を 1 増やします。値そのものを 1 に設定するわけではありません。`20%` は値を 20% 増やします。他の値も同様です。

これらの値はほとんど、またはまったく検証されないため、不適切な値（`-100%` など）を指定するとターミナルが使用不能になることがあります。慎重に、妥当な値を指定してください。

一部の値には下限や上限があります。このため、特定の値が無視されているように見えることがあります。たとえば、多くの `*-thickness` 調整は 1px 未満にはできません。

`adjust-cell-height` には、次のような追加の動作があります。

  * フォントはセル内で上下中央に配置されます。

  * カーソルはフォントと同じサイズを維持しますが、`adjust-cursor-height` で個別に調整できます。

  * ステータス行などの配置が引き続き揃って見えるように、Powerline のグリフもセルの高さに合わせて調整されます。

## `adjust-font-baseline`

セルの下端からテキストのベースラインまでの距離を、ピクセル単位またはパーセンテージで調整します。値を増やすとベースラインが上に移動し、減らすと下に移動します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-underline-position`

セルの上端から下線の上端までの距離を、ピクセル単位またはパーセンテージで調整します。値を増やすと下線が下に移動し、減らすと上に移動します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-underline-thickness`

下線の太さをピクセル単位で指定します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-strikethrough-position`

セルの上端から取り消し線の上端までの距離を、ピクセル単位またはパーセンテージで調整します。値を増やすと取り消し線が下に移動し、減らすと上に移動します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-strikethrough-thickness`

取り消し線の太さを、ピクセル単位またはパーセンテージで調整します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-overline-position`

セルの上端から上線の上端までの距離を、ピクセル単位またはパーセンテージで調整します。値を増やすと上線が下に移動し、減らすと上に移動します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-overline-thickness`

上線の太さを、ピクセル単位またはパーセンテージで調整します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-cursor-thickness`

棒状カーソルと輪郭のみの矩形カーソルの太さを、ピクセル単位またはパーセンテージで調整します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-cursor-height`

カーソルの高さを、ピクセル単位またはパーセンテージで調整します。現在は、棒状、矩形、輪郭のみの矩形というすべてのカーソルの種類に適用されます。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-box-thickness`

罫線文字の太さを、ピクセル単位またはパーセンテージで調整します。調整についての注意事項は `adjust-cell-width` を参照してください。

## `adjust-icon-height`

Nerd Font アイコンの最大の高さを、ピクセル単位またはパーセンテージで調整します。

正（負）の値を指定すると、アイコンの最大の高さが増加（減少）します。すべてのアイコンに同じように影響するとは限りません。効果は、アイコンのデフォルトサイズが高さによって制限されているかどうかに依存し、それはアイコンと主フォントの両方の縦横比によって決まります。

Powerline 記号など、罫線やターミナルグラフィックス用に設計された一部のアイコンは、このオプションの影響を受けません。

調整についての注意事項は `adjust-cell-width` を参照してください。

1.2.0 以降で利用可能です。

## `grapheme-width-method`

書記素クラスターのセル幅を計算する方法です。デフォルト値は `unicode` で、Unicode 標準に従って書記素の幅を決定します。これにより書記素の幅が正しくなりますが、`wcswidth` のような従来の方法を使うプログラム（シェルなど）では、カーソル位置のずれが発生することがあります。

有効な値は次のとおりです。

* `legacy` - wcswidth などの従来の方法で書記素の幅を決定します。従来のプログラムとの互換性を最大限に確保しますが、肌の色付き絵文字や英語以外の文字など、一部の書記素の幅が正しくなくなることがあります。

  より具体的な名前ではなく「legacy」と呼ぶのは、動作が未定義であり、変更できる余地を残しておくためです。たとえば、現在または将来において、libc の `wcswidth` を使うことも使わないこともあります。

* `unicode` - Unicode 標準に従って書記素の幅を決定します。

実行中のプログラムがターミナルモード 2027 を明示的に有効にした場合、この設定にかかわらず `unicode` の幅が強制されます。モード 2027 がリセットされると、この設定が再び使われます。

この設定は実行時に変更できますが、既存のターミナルには影響しません。新しいターミナルだけが新しい設定を使います。

## `freetype-load-flags`

有効にする FreeType の読み込みフラグです。有効にするフラグをカンマ区切りの一覧で指定します。フラグの前に `no-` を付けると無効になります。フラグを省略するとデフォルト値が使われるため、不要なフラグは明示的に無効にする必要があります。`true` または `false` を使って、すべてのフラグを有効または無効にすることもできます。

この設定は FreeType を使う Ghostty のビルドにのみ適用されます。通常は Linux ビルドだけが該当します。macOS は CoreText を使い、同等の設定はありません。

利用可能なフラグ:

  * `hinting` - ヒンティングを有効または無効にします。デフォルトでは有効です。

  * `force-autohint` - フォント本来のヒンターの代わりに、常に FreeType の自動ヒンターを使います。デフォルトでは無効です。

  * `monochrome` - レンダラーに 1 ビットのモノクロ描画を指示します。アンチエイリアスが無効になるため、ピクセルフォントを使っていない限り、見栄えはあまりよくないでしょう。デフォルトでは無効です。

  * `autohint` - FreeType の自動ヒンターを有効にします。デフォルトでは有効です。

  * `light` - グリフの形をより忠実に保つ、軽いヒンティングスタイルを使います。これは GTK アプリで最も一般的な設定であるため、Ghostty でもデフォルトになっています。`monochrome` が有効な場合は効果がありません。デフォルトでは有効です。

例: `hinting`、`no-hinting`、`force-autohint`、`no-force-autohint`

## `theme`

使用するテーマです。組み込みテーマ名、カスタムテーマ名、またはカスタムテーマファイルの絶対パスを指定できます。Ghostty は、ライトモードとダークモードで異なるテーマを指定することもサポートしています。それぞれの指定方法を以下で説明します。

テーマが絶対パスの場合、Ghostty はそのファイルをテーマとして読み込もうとします。ファイルが存在しないかアクセスできない場合は、エラーがログに記録され、他のディレクトリは検索されません。

テーマが絶対パスでない場合、テーマに一致する名前のファイルを 2 つのディレクトリで検索します。ファイルシステムが大文字と小文字を区別するシステムでは、ここでも区別されます。絶対パスでないテーマ名にパス区切り文字を含めると、エラーになります。

最初のディレクトリは、Ghostty 設定ディレクトリ内の `themes` サブディレクトリです。これは `$XDG_CONFIG_HOME/ghostty/themes` または `~/.config/ghostty/themes` です。

2 つ目のディレクトリは、Ghostty リソースディレクトリ内の `themes` サブディレクトリです。Ghostty には多数のテーマが付属しており、このディレクトリにインストールされます。macOS では `Ghostty.app/Contents/Resources/ghostty/themes` ディレクトリにあります。Linux では、Ghostty の「share」ディレクトリのインストール先にある `share/ghostty/themes` ディレクトリにあります。

利用可能なテーマの一覧を見るには、`ghostty +list-themes` を実行します。

テーマファイルは、通常の Ghostty 設定ファイルと同じものです。構文も設定オプションも共通です。テーマは有効な設定オプションをどれでも設定できるため、信頼できない提供元のテーマファイルは使わないでください。組み込みテーマは、安全な設定オプションだけを設定するように監査されています。

一部のオプションはテーマファイル内で設定できません。対応していない理由は自明でしょう。テーマファイルでは `theme` や `config-file` を設定できません。執筆時点では、テーマファイルにこれらのオプションを設定しても Ghostty は警告やエラーを表示せず、通知なく無視します。

background、foreground、palette などで追加指定した色は、テーマで指定された色を上書きします。

ライトモードとダークモードで異なるテーマを指定するには、`light:theme-name,dark:theme-name` という構文を使います。例は `light:Rose Pine Dawn,dark:Rose Pine` です。すべての値の前後の空白は取り除かれ、light と dark の順序は問いません。この形式では、light と dark の両方を指定する必要があります。使用するテーマは、現在のデスクトップ環境のテーマに基づいて決まります。

ライトモードとダークモードのテーマには、いくつか既知の不具合があります。これらは今後の更新で修正する予定です。

  - macOS: テーマを切り替えてもタイトルバーのタブのスタイルが更新されません。

## `background`

ウィンドウの背景色です。16 進数（`#RRGGBB` または `RRGGBB`）、または X11 の色名で指定します。

## `foreground`

ウィンドウの前景色です。16 進数（`#RRGGBB` または `RRGGBB`）、または X11 の色名で指定します。

## `background-image`

ターミナルの背景画像です。

PNG または JPEG ファイルのパスを指定します。他の画像形式にはまだ対応していません。

現在、背景画像はウィンドウ単位ではなくターミナル単位です。分割を多用する場合、分割ごとに背景画像が繰り返されます。今後の Ghostty の改善で対処する予定です。

<Warning>
 現在、背景画像はターミナルごとに VRAM 内で複製されます。画像が大きい場合、メモリ使用量（特に VRAM 使用量）が大幅に増える可能性があります。今後の Ghostty の改善で、ターミナル間で画像テクスチャを共有して解決する予定です。
</Warning>

1.2.0 以降で利用可能です。

## `background-image-opacity`

背景画像の不透明度です。

`background-opacity` の値に対する相対値です。

`1.0`（デフォルト）の場合、背景画像が全体の背景色の上に配置され、その合成結果が `background-opacity` で指定した不透明度に調整されます。

`1.0` 未満の場合、背景画像が全体の背景色と混合された後、その合成結果が設定された `background-opacity` に調整されます。

`1.0` より大きい場合、背景画像の不透明度が全体の背景色より高くなります。たとえば、`background-opacity` が `0.5`、`background-image-opacity` が `1.5` の場合、背景画像の最終的な不透明度は `0.5 * 1.5 = 0.75` になります。

1.2.0 以降で利用可能です。

## `background-image-position`

背景画像の位置です。

有効な値は次のとおりです。
  * `top-left`
  * `top-center`
  * `top-right`
  * `center-left`
  * `center`
  * `center-right`
  * `bottom-left`
  * `bottom-center`
  * `bottom-right`

デフォルト値は `center` です。

1.2.0 以降で利用可能です。

## `background-image-fit`

背景画像のサイズ調整方法です。

有効な値は次のとおりです。

 * `contain`

   縦横比を維持したまま、ターミナル内に収まる最大のサイズに背景画像を拡大縮小し、画像全体が見えるようにします。

 * `cover`

   縦横比を維持したまま、ターミナル全体を覆える最小のサイズに背景画像を拡大縮小します。画像の 1 つ以上の端が、ターミナルの端で切り取られる場合があります。

 * `stretch`

   縦横比を維持せず、背景画像をターミナル全体のサイズに引き伸ばします。

 * `none`

   背景画像を拡大縮小しません。

デフォルト値は `contain` です。

1.2.0 以降で利用可能です。

## `background-image-repeat`

背景画像を繰り返すかどうかです。

true に設定すると、背景画像がターミナル領域を完全に埋めず、周囲に空白ができる場合に、画像を繰り返します。

デフォルト値は `false` です。

1.2.0 以降で利用可能です。

## `selection-foreground`
## `selection-background`

選択範囲の前景色と背景色です。未設定の場合、ウィンドウの背景色と前景色を反転した色になります（セルの背景色・前景色とは異なることに注意してください）。16 進数（`#RRGGBB` または `RRGGBB`）、または X11 の色名で指定します。バージョン 1.2.0 以降では、`cell-foreground` を指定してセルの前景色に合わせるか、`cell-background` を指定してセルの背景色に合わせることもできます。

## `selection-clear-on-typing`

入力時にテキストの選択を解除するかどうかです。デフォルトは `true` です。これは、ほとんどのターミナルエミュレーターやテキスト入力欄で一般的な動作です。`false` に設定すると、入力時にテキストの選択が解除されません。

ここでの「入力」は、ターミナル内で実行中のアプリケーション（シェルなど）に送るデータを生成する、修飾キー（shift、control、alt など）以外のキー押下と定義します。また、日本語などの入力時に、変換前の入力や文字の組み立てが始まった場合も、選択が解除されます。

`false` の場合も、1 回クリックするか `escape` を押すと、手動で選択を解除できます。

1.2.0 以降で利用可能です。

## `selection-clear-on-copy`

コピー後にテキストの選択を解除するかどうかです。デフォルトは `false` です。

`true` に設定すると、`copy_to_clipboard` キーバインドを呼び出すコピー操作の後に、選択が自動的に解除されます。重要な点として、`copy-on-select` によるコピーでは選択は解除されません。

`false` に設定すると、コピー後も選択範囲が表示されたままになるため、コピーした内容を確認したり、同じ選択範囲に追加の操作を行ったりできます。

## `selection-word-chars`

ダブルクリックなどのテキスト選択操作で、単語の境界とする文字です。単語の選択時には、これらの文字のいずれかで選択が止まります。

これは zsh の `WORDCHARS` 環境変数と似ていますが、単語を構成する文字ではなく境界文字を指定する点が異なります。デフォルトには、コードや文章で単語を区切る一般的な区切り文字や句読点が含まれます。

この文字列の各文字が単語の境界になります。マルチバイトの UTF-8 文字に対応していますが、指定できるのは単一のコードポイントだけです。複数のコードポイントからなる並び（絵文字など）には対応していません。

ヌル文字（U+0000）は常に境界として扱われるため、この設定に含める必要はありません。

デフォルト: `` \t'"│`|:;,()[]{}<>$ ``

特定の文字を追加または削除するには、独自の値を設定できます。たとえば、セミコロンを単語の一部として扱う場合は、次のように指定します。

```
selection-word-chars = " \t'\"│`|:,()[]{}<>$"
```

1.3.0 以降で利用可能です。

## `minimum-contrast`

前景色と背景色の最小コントラスト比です。コントラスト比は 1 から 21 までの値です。1 にすると、コントラストがない状態（黒地に黒など）を許容します。この値は、[WCAG 2.0 仕様](https://www.w3.org/TR/WCAG20/) で定義されたコントラスト比です。

見えないテキスト（背景と同じ色）を避けたい場合は、1.1 が適切です。読みにくいテキストを避けたい場合は、3 以上が適切です。値が高いほど、テキストが黒または白になりやすくなります。

この値は絵文字や画像には適用されません。

## `palette`

多くのターミナルアプリケーションが使う、256 色形式のカラーパレットです。この設定の構文は `N=COLOR` です。`N` は 0 から 255 までの値（ターミナルのカラーテーブルの 256 色に対応）、`COLOR` は `#AABBCC` や `AABBCC` のような一般的な RGB カラーコード、または X11 の色名です。たとえば、`palette = 5=#BB78D9` は「紫」の色を設定します。

パレットのインデックスは、10 進数、2 進数、8 進数、16 進数で指定できます。接頭辞を付けなければ 10 進数として扱われます。2 進数は `0b`、8 進数は `0o`、16 進数は `0x` を付けます。

色のインデックスの定義と、標準的に対応する色については、[こちらのチートシートを参照してください](https://www.ditig.com/256-colors-cheat-sheet)。

ほとんどのテーマでは、パレットの残り（16–255）はデフォルトで自動生成されるため、最初の 16 色（0–15）だけを設定すれば十分です（詳しくは `palette-generate` を参照してください）。

## `palette-generate`

基本の 16 の ANSI 色から、拡張 256 色パレット（インデックス 16–255）を自動生成するかどうかです。

テーマの作成者は基本の 16 色だけを指定し、パレットの残りを一貫した美しい配色で自動生成できます。

有効にすると、基本パレットの補間から 6×6×6 の色立方体と 24 段階のグレースケールを生成し、より統一感のある外観にします。`palette` で明示的に設定した色は上書きされません。

256 色パレットを使う従来のプログラムの多くは、各色の内容を決め打ちしている（主に xterm の 256 色パレットを想定している）ため、デフォルト値は false（無効）です。それでも、256 色すべてを指定せずにパレットをカスタマイズしたいテーマ作成者やユーザーには、とても便利なツールです。

生成の仕組みについて詳しくは、以下を参照してください。
https://gist.github.com/jake-stewart/0a8ea46159a7da2c808e5be2177e1783

1.3.0 以降で利用可能です。

## `palette-harmonious`

`palette-generate` が有効な場合に生成されるパレットの色を反転し、逆順にします。パレットが常に比較的良好な配色になるため、パレットを使うアプリケーションがライトモードとダークモードの両方でうまく動作します。

従来のターミナルアプリケーションの一部は、パレットのインデックス 16–231 が暗い色から明るい色の順に並んでいると決め打ちしており、有効にすると読めなくなるため、デフォルトでは無効です。これは一般に適切な前提ではなく、最新のターミナルアプリケーションでは、インデックスをより意味に即した方法で使うことを推奨します。

`palette-generate` が無効な場合は効果がありません。

詳しくは `palette-generate` を参照してください。

1.3.0 以降で利用可能です。

## `cursor-color`

カーソルの色です。未設定の場合は、デフォルトの色が選ばれます。

色を直接指定する場合は、16 進数（`#RRGGBB` または `RRGGBB`）、または X11 の色名で指定できます。

また、次の特別な値を使うと、実行時に他の色と一致するように設定できます。

  * `cell-foreground` - セルの前景色に合わせます。
    （1.2.0 以降で利用可能です。）

  * `cell-background` - セルの背景色に合わせます。
    （1.2.0 以降で利用可能です。）

## `cursor-opacity`

カーソルの不透明度（透明度の逆）です。1 は完全に不透明、0 は完全に透明です。0 未満または 1 より大きい値は、最も近い有効な値に制限されます。0.3 のような十分に小さい値では、実質的に見えなくなり、カーソルを見つけにくくなることがあります。

## `cursor-style`

カーソルのスタイルです。デフォルトのスタイルを設定します。実行中のプログラムは、エスケープシーケンス（`CSI
q` など）を使って、引き続きカーソルスタイルを明示的に要求できます。シェルの設定によって、特定のカーソルスタイルが要求されることはよくあります。

シェル統合は、この設定にかかわらず、プロンプトでカーソルを自動的に棒状にする点に注意してください。`shell-integration-features = no-cursor` を指定するか、シェル統合を完全に無効にすると、この動作を無効にできます。

有効な値は次のとおりです。

  * `block`
  * `bar`
  * `underline`
  * `block_hollow`

## `cursor-style-blink`

カーソルのデフォルトの点滅状態を設定します。これはあくまでデフォルトの状態であり、実行中のプログラムは `DECSCUSR`（`CSI
q`）を使ってカーソルスタイルを上書きできます。

未設定の場合、カーソルはデフォルトで点滅します。ただし、後述のとおり、これは「true」の値と同じではありません。

まったく設定されていない場合（`null`）、Ghostty は点滅を切り替える別の方法として DEC モード 12（AT&T カーソル点滅）に従います。null 以外の値に設定されている場合、DEC モード 12 は無視されますが、`DECSCUSR` には引き続き従います。

有効な値は次のとおりです。

  * ` `（空白）
  * `true`
  * `false`

## `cursor-text`

カーソルの下にあるテキストの色です。未設定の場合は、デフォルトの色が選ばれます。16 進数（`#RRGGBB` または `RRGGBB`）、または X11 の色名で指定します。バージョン 1.2.0 以降では、`cell-foreground` を指定してセルの前景色に合わせるか、`cell-background` を指定してセルの背景色に合わせることもできます。

## `cursor-click-to-move`

プロンプトのテキスト内の位置をクリックして、プロンプトのカーソルを移動できるようにします。

この機能にはシェル統合、特に `OSC 133` によるプロンプトのマーク付けが必要です。Fish（v4）や Nu（0.111 以降）など一部のシェルは標準で対応していますが、それ以外では、追加の設定や Ghostty のシェル統合機能の有効化が必要な場合があります。

シェルに応じて、クリック位置を一連の擬似的な矢印キー操作に変換するか、クリックイベントを直接シェルに送信します。どちらの場合も、特殊な状況では予期しない動作が発生する可能性があります。

## `mouse-hide-while-typing`

入力時にマウスポインターを即座に非表示にします。マウス操作（ボタン、移動など）を行うと再び表示されます。プラットフォーム固有の動作によって、他の状況でも表示される場合があります。たとえば macOS では、新しいウィンドウ、タブ、分割を作成すると再び表示されます。

## `scroll-to-bottom`

サーフェスを最下部にスクロールするタイミングです。有効にするオプションをカンマ区切りの一覧で指定します。オプションの前に `no-` を付けると無効になります。省略したオプションにはデフォルト値が使われます。

利用可能なオプション:

- `keystroke` 有効にすると、PTY にデータが送られるキーをユーザーが押したときに、サーフェスを最下部にスクロールします（基本的には、修飾キーと Ghostty が処理するキーバインド以外のすべてです）。

- `output` 有効にすると、表示する新しいデータがある場合（ターミナルに新しい行が出力されたときなど）に、サーフェスを最下部にスクロールします。

デフォルトは `keystroke, no-output` です。

## `mouse-shift-capture`

実行中のプログラムが、マウスクリックと同時に押された shift キーを検出できるかどうかを決めます。通常、shift キーはマウスの選択範囲を拡張するために使います。

デフォルト値の `false` では、shift キーはマウスプロトコルで送信されず、選択範囲を拡張します。この値は、実行中のプログラムが `XTSHIFTESCAPE` シーケンスで条件付きで上書きできます。

`true` では、shift キーをマウスプロトコルで送信しますが、実行中のプログラムは `XTSHIFTESCAPE` でこの動作を上書きできます。

`never` は `false` と同じですが、実行中のプログラムは `XTSHIFTESCAPE` でこの動作を上書きできません。`always` は `true` と同じですが、実行中のプログラムは `XTSHIFTESCAPE` でこの動作を上書きできません。

プログラムが別の動作を要求しても、常に shift キーでマウスの選択範囲を拡張したい場合は、`never` に設定してください。

有効な値は次のとおりです。

  * `true`
  * `false`
  * `always`
  * `never`

## `mouse-reporting`

マウスレポートを有効または無効にします。`false` に設定すると、ターミナルアプリケーションが要求してもマウスイベントは通知されません。これにより、アプリケーションにマウス入力を取得されることなく、常に選択やターミナル UI の他の操作にマウスを使えます。

`true`（デフォルト）に設定すると、ターミナルアプリケーションはマウスレポートを要求でき、要求したモードに従ってマウスイベントを受け取ります。

これは、`toggle_mouse_reporting` キーバインドアクションを使って実行時に切り替えられます。

## `mouse-scroll-multiplier`

マウスホイールのスクロール距離の倍率です。

`precision:` または `discrete:` という接頭辞を使うと、特定の種類のデバイスによるスクロールだけに倍率を設定できます。`precision:0.1,discrete:3` のようにカンマで区切ると、両方の種類の倍率を同時に設定できます。接頭辞を使わない場合、倍率はすべてのスクロールデバイスに適用されます。接頭辞の指定は Ghostty 1.2.1 で導入されました。

値は [0.01, 10,000] の範囲に制限されます。どちらも極端な値であり、端の値に設定すると使いにくくなる可能性が高いです。

デフォルト値は、離散デバイスでは「3」、高精度デバイスでは「1」です。

## `background-opacity`

背景の不透明度（透明度の逆）です。1 は完全に不透明、0 は完全に透明です。0 未満または 1 より大きい値は、最も近い有効な値に制限されます。

macOS では、ターミナルがネイティブのフルスクリーンに入ると、背景の不透明度は無効になります。背景が灰色になり、ウィジェットが透けて見えることがあり、通常は望ましくないためです。

macOS では、この設定の変更には Ghostty の完全な再起動が必要です。

## `background-opacity-cells`

背景色が明示的に設定されたセルにも、背景の不透明度を適用します。

通常、`background-opacity` はウィンドウの背景だけに適用されます。セルに赤などの背景色が明示的に設定されている場合、その背景色は完全に不透明になります。このため、Neovim や Tmux など、ターミナルの背景色を塗り直す一部のターミナルアプリケーションでは、`background-opacity` が反映されないことがあります（意図した動作です）。

`true` に設定すると、背景色が明示的に設定されているかどうかにかかわらず、すべてのセルに `background-opacity` を適用します。

1.2.0 以降で利用可能です。

## `background-blur`

`background-opacity` が 1 未満の場合に、背景をぼかすかどうかです。

有効な値は次のとおりです。

  * *ぼかしの強さ*を指定する、0 以上の整数
  * `false` は、ぼかしの強さ 0 に相当します。
  * `true` は、デフォルトのぼかしの強さ 20 に相当し、見栄えのよいぼかしに適した値です。強さを大きくすると、描画の異常やパフォーマンスの問題が発生することがあります。

macOS 26.0 以降では、macOS ネイティブのガラス効果を使うための、次の特別な値も設定できます。

  * `macos-glass-regular` - ある程度の不透明度を持つ標準のガラス効果
  * `macos-glass-clear` - 透明度の高いガラス効果

macOS 用の値を設定した場合、macOS 以外のプラットフォームでは `background-blur = true` として扱われます。

macOS と、以下を含む一部の Linux デスクトップ環境でサポートされています。

  * KDE Plasma（Wayland と X11）

<Warning>
 KDE Plasma では、ぼかしの強さの具体的な値は*無視*され、`true` または任意の正の値に設定しても同じ効果になります。これは、Plasma のウィンドウコンポジターである KWin には全体に適用するぼかし設定が 1 つしかなく、アプリケーションごとのぼかし設定を指定できないためです。
</Warning>

KWin 全体のぼかしを設定するには、システム設定を開き、「アプリとウィンドウ」>「ウィンドウの管理」>「デスクトップ効果」に移動して、「ぼかし」プラグインを選択します。無効になっている場合は、左のチェックボックスをオンにして有効にします。次に「設定」ボタンをクリックすると、2 つのスライダーが表示され、Ghostty を含むすべてのアプリの背景のぼかしとノイズの強さを設定できます。

その他の Linux デスクトップ環境には、現時点では対応していません。背景のぼかしを行うための統一されたインターフェースがないため、環境固有の設定やサードパーティー製プラグインのインストールが必要になる場合があります。

## `unfocused-split-opacity`

フォーカスされていない分割の不透明度（透明度の逆）です。デフォルトでは、フォーカスされていない分割を少し薄く表示し、どの分割にフォーカスがあるかを分かりやすくします。この機能を無効にするには、値を 1 に設定します。

## `unfocused-split-fill`

デフォルトでは背景色になります。

## `split-divider-color`

## `split-preserve-zoom`

## `command`

実行するコマンドです。通常はシェルです。絶対パスでない場合は、`PATH` から検索します。未設定の場合は、システムからデフォルトを検索します。デフォルトの検索には、次の順序を使います。

  * `SHELL` 環境変数

  * `passwd` エントリー（ユーザー情報）

コマンドの実行時に渡す追加の引数を含めることができます。追加の引数を指定すると、シェルの引数展開を委譲するために、`/bin/sh -c` を使ってコマンドを実行します。

シェル展開を完全に避けるには、`direct:nvim foo` のように、コマンドの前に `direct:` を付けます。これにより `/bin/sh` を経由しなくなりますが、空白を含む引数、`~` を含むファイルパス、グロブなど、シェルによる解析も一切サポートされなくなります。（1.2.0 以降で利用可能です。）

コマンドの前に `shell:` を明示的に付けると、常にシェルでコマンドを実行できます。適切なモードを選ぶヒューリスティックが誤っている場合に、それを使わないようにするために利用できます。（1.2.0 以降で利用可能です。）

このコマンドは、新しいウィンドウやタブなど、すべての新しいターミナルサーフェスで使われます。Ghostty の起動時に作成される最初のターミナルサーフェスでだけコマンドを実行したい場合は、`initial-command` 設定を使ってください。

Ghostty は、引数付きのコマンドを実行するための一般的な `-e` フラグをサポートしています。たとえば、`ghostty -e fish --with --custom --args` です。このフラグは `initial-command` 設定を指定します。詳しくはそちらを参照してください。

## `initial-command`

「command」と同じですが、Ghostty の起動時に作成される最初のターミナルサーフェスだけに適用されます。それ以降のターミナルサーフェスは `command` 設定を使います。

最初のターミナルサーフェスが作成された（または閉じられた）後に、この初期コマンドを再び自動実行する方法はありません。そのため、実行時の設定は可能ですが、次のターミナルサーフェスが初めて作成されるものである場合にのみ影響します。

`ghostty` CLI を使う場合、引数付きで直接設定するためのショートカットとして、`-e` フラグも使えます。例は `ghostty -e
fish --with --custom --args` です。`-e` フラグは、次の動作も自動的に強制します。

  * 入力は呼び出し元（`ghostty -e` コマンドを入力したシェルなど）ですでにシェル展開されていると想定するため、シェル展開を無効にします。

  * `gtk-single-instance=false` - 新しいインスタンスを起動し、CLI 引数が反映されるようにします。

  * `quit-after-last-window-closed=true` - コマンドの終了時に Ghostty プロセスも終了するようにします。また、`quit-after-last-window-closed-delay` の設定を解除します。

  * `shell-integration=detect`（`none` でない場合）- 設定されたシェル統合をコマンドの環境に強制的に注入しないようにします。`-e` でシェルを実行することは非常にまれであり、シェル統合を強制すると問題が起きやすくなります（コマンドをシェルで包む、環境変数を設定するなど）。これは予期しない動作を防ぐための安全策です。`-e` で実行したコマンドにシェル統合を使いたい場合は、バイナリに適切な名前を付けるか、シェル統合スクリプトを手動で読み込む必要があります。

## `notify-on-command-finish`

コマンドの完了通知を送信するタイミングを制御します。3 つのオプションがあります。

* `never` - 通知を送信しません（デフォルト）。
* `unfocused` - コマンドを実行しているサーフェスにフォーカスがない場合だけ通知を送信します。
* `always` - 常に通知を送信します。

コマンドの完了通知には、シェル統合が有効であるか、シェルがコマンドの開始と終了をマークする OSC 133 エスケープシーケンスを送信する必要があります。

GTK には、`never` と `unfocused` の設定を上書きして、単一のコマンドの完了通知を有効にするコンテキストメニュー項目があります。

1.3.0 以降で利用可能です。

## `notify-on-command-finish-action`

コマンドの完了通知が有効な場合、ユーザーへの通知方法を制御します。

利用可能なオプション:

* `bell` - デフォルトでは有効です。
* `notify` - デフォルトでは無効です。

オプションをカンマ区切りで列挙すると、組み合わせることができます。前に `no-` を付けると、そのオプションを無効にできます。たとえば、`no-bell,notify` です。

1.3.0 以降で利用可能です。

## `notify-on-command-finish-after`

コマンドの完了通知が有効な場合、通知の対象となるコマンドの最短実行時間を制御します。デフォルトは 5 秒です。

期間は、数値の後に時間の単位を付けたものを並べて指定します。数値と単位の間に空白を入れられます。それぞれの数値と単位を合算したものが、合計の期間になります。

使用できる時間の単位は次のとおりです。

  * `y` - 365 SI 日、8760 時間、または 31536000 秒です。うるう年やうるう秒による調整は行いません。
  * `d` - 1 SI 日、または 86400 秒です。
  * `h` - 1 時間、または 3600 秒です。
  * `m` - 1 分、または 60 秒です。
  * `s` - 1 秒です。
  * `ms` - 1 ミリ秒、または 0.001 秒です。
  * `us` または `µs` - 1 マイクロ秒、または 0.000001 秒です。
  * `ns` - 1 ナノ秒、または 0.000000001 秒です。

例:
  * `1h30m`
  * `45s`

単位は繰り返し指定でき、その場合は合算されます。つまり、`1h1h` は `2h` と同じです。紛らわしいため、このような指定は避けてください。将来の更新で禁止される可能性があります。

最大値は `584y 49w 23h 34m 33s 709ms 551µs 615ns` です。これを超える値は最大値に制限されます。

1.3.0 以降で利用可能です。

## `env`

ターミナルサーフェスで起動するコマンドに渡す追加の環境変数です。形式は `env=KEY=VALUE` です。

`env = foo=bar`
`env = bar=baz`

`env` を空文字列に設定すると、マップ全体がデフォルト（空）にリセットされます。

`env =`

キーの値を空文字列に設定すると、そのキーと対応する値がマップから削除されます。

`env = foo=bar`
`env = foo=`

この場合、起動するコマンドに `foo` は渡されません。

同じキーを複数回設定すると、前のエントリーが上書きされます。

`env = foo=bar`
`env = foo=baz`

この場合、起動するコマンドに `foo=baz` が渡されます。

これらの環境変数は、Ghostty が設定した既存の環境変数を上書きします。たとえば、`GHOSTTY_RESOURCES_DIR` を設定すると、ここで設定した値が、通常 Ghostty が自動的に注入する値を上書きします。

これらの環境変数は、ブラウザーで URL を開くための `open` や `xdg-open` など、Ghostty が別の目的で実行するコマンドには*渡されません*。

1.2.0 以降で利用可能です。

## `input`

起動時にコマンドへの入力として送信するデータです。

設定された `command` が通常の規則で起動した後、他の入力が渡される前に、ここで指定したデータが pty に書き込まれます。

バイト列は追加のエンコードなしでそのまま送信されます。そのため、制御文字を含む可能性のある入力には注意してください。シェルでプログラムを実行するために利用できるためです。

値の形式は次のとおりです。

  * `raw:<string>` - 生のテキストをそのまま送信します。Zig の文字列リテラル構文を使うため、制御文字や標準的なエスケープを指定できます。

  * `path:<path>` - ファイルパスを読み込み、その内容を送信します。有限の長さを持つファイルのパスを指定する必要があります。たとえば、`/dev/stdin` や `/dev/urandom` などのデバイスを使うと、ターミナルの起動が無期限にブロックされるため、使わないでください。過剰なメモリ使用を防ぐため、ファイルサイズは 10MB に制限されています。これより大きいファイルを使う場合は、ファイルを読み込んでターミナルに送信するスクリプトを作成してください。

有効な接頭辞がない場合は、`raw:` 入力と見なします。これは使いやすさのための設計で、すべての値に `raw:` を付けなくても、よく使う形式である `input = "Hello, world!"` と簡単に書けるようにしています。

複数回指定して、さらにデータを送信できます。データは区切り文字なしで直接連結されます（改行などは入りません）。

入力元のいずれかが存在しない場合、入力は一切送信されません。入力元はターミナルの起動時まで検証されないため、存在しないパスは設定の検証では検出されません。

実行時にこの設定を変更した場合、新しいターミナルだけに影響します。

1.2.0 以降で利用可能です。

## `wait-after-command`

true の場合、コマンド終了後もターミナルを開いたままにします。通常は、実行中のコマンド（シェルなど）が終了するとターミナルウィンドウは閉じます。true にすると、何らかのキーが押されるまでターミナルウィンドウを開いたままにします。

主にスクリプトやデバッグに役立ちます。

## `abnormal-command-exit-runtime`

プロセスの終了を異常と見なす、実行時間のしきい値をミリ秒単位で指定します。実行時間がこの値より短い場合に異常と見なし、プロセスが早すぎるタイミングで終了したときにエラーメッセージを表示するために使います。

Linux では、終了コードが 0 以外であることも必要です。macOS では、login コマンドを介してシェルプロセスを起動する仕組みのため、すべての終了コードが対象になります。

## `scrollback-limit`

スクロールバックバッファーのサイズをバイト単位で指定します。現在の画面も含まれます。設定値にかかわらず、表示中の画面に必要なメモリは常に確保され、残りがスクロールバックの上限になります。

この上限に達すると、スクロールバックから最も古い行が削除されます。

現在、スクロールバックはすべてメモリ上に保持されます。そのため、値を大きくするほど、メモリ使用量も大きくなる可能性があります。スクロールバックのメモリはこの上限まで必要に応じて確保されるため、非常に大きな値を設定しても、すぐに大量のメモリを消費するわけではありません。

このサイズはアプリケーション全体ではなく、ターミナルサーフェスごとの値です。

現在、スクロールバックバッファーを無制限にすることはできません。今後追加を予定している機能です。

実行時に変更できますが、新しいターミナルサーフェスだけに影響します。

## `scrollbar`

スクロールバックバッファーをスクロールするためのスクロールバーを、いつ表示するかを制御します。

デフォルト値は `system` です。

有効な値:

  * `system` - スクロールバーの表示タイミングに関するシステム設定に従います。たとえば macOS では、システムの「スクロールバーの表示」設定に従い、通常のデフォルトでは、スクロール中またはスクロールバーの領域にポインターを合わせたときだけ表示します。

## `link-url`

URL の照合を有効にします。control（Linux）または command（macOS）を押しながらポインターを合わせると URL を照合し、リンク先 URL に対応するシステムのデフォルトアプリケーションで開きます。

URL の照合は、設定されたすべてのリンクの中で常に最も優先度が低くなります（`link` を参照）。URL の照合をカスタマイズしたい場合は、`link` を使い、この設定を無効にしてください。

## `link-previews`

一致した URL のリンクプレビューを表示します。

true の場合、一致したすべての URL でリンクプレビューを表示します。false の場合、リンクプレビューを表示しません。「osc8」に設定すると、OSC 8 シーケンスで作成されたハイパーリンクだけにリンクプレビューを表示します（この場合、リンクテキストとリンク先が異なることがあります）。

1.2.0 以降で利用可能です。

## `maximize`

ウィンドウを最大化した状態で起動するかどうかです。新しいウィンドウに適用され、タブや分割などには適用されません。ただし、最初のウィンドウだけでなく、すべての新しいウィンドウに適用されます。

1.1.0 以降で利用可能です。

## `fullscreen`

新しいウィンドウをフルスクリーンで起動します。新しいウィンドウに適用され、タブや分割などには適用されません。ただし、最初のウィンドウだけでなく、すべての新しいウィンドウに適用されます。

指定できる値は次のとおりです。

  * `false` - フルスクリーンで起動しません（デフォルト）。
  * `true` - ネイティブのフルスクリーンで起動します。
  * `non-native` - （macOS のみ）メニューバーを隠し、非ネイティブのフルスクリーンで起動します。アニメーションを使わないため、ネイティブのフルスクリーンより高速です。macOS 以外では `true` と同じ動作になります。
  * `non-native-visible-menu` - （macOS のみ）メニューバーを表示したまま、非ネイティブのフルスクリーンで起動します。macOS 以外では `true` と同じ動作になります。
  * `non-native-padded-notch` - （macOS のみ）メニューバーを隠し、対応するデバイスではノッチ用の余白を設けて、非ネイティブのフルスクリーンで起動します。macOS 以外では `true` と同じ動作になります。

重要: 非ネイティブのフルスクリーンモードでは、タブは動作しません。非ネイティブのフルスクリーンではタイトルバーがなくなりますが、macOS ネイティブのタブにはタイトルバーが必要です。タブを使う場合は、代わりに `true`（ネイティブ）を使ってください。

macOS のネイティブフルスクリーンにはウィンドウ装飾が必要なため、`window-decoration` が `false` の場合、`true`（ネイティブフルスクリーン）は動作しません。

## `title`

Ghostty がウィンドウに使うタイトルです。ウィンドウのタイトルを常にこの値に固定し、プログラム（Neovim など）が送信するタイトル設定用のエスケープシーケンスを無視します。

タイトルを空白にしたい場合は、値を引用符で囲み、1 つ以上の空白を設定します。たとえば、`title = " "` です。これにより、実質的にタイトルを非表示にできます。空の値を設定すると、実行中のプログラムのデフォルトのタイトルにリセットされるため、この指定が必要です。

この設定は実行時に再読み込みできます。値が設定されていれば、すべてのウィンドウのタイトルが更新されます。設定を解除した場合、次のタイトル変更エスケープシーケンスには従いますが、過去の変更は遡って適用されません。後者の場合、新しいタイトルを反映するには、Neovim などのプログラムの再起動が必要になることがあります。

## `class`

アプリケーションクラスの値を変更する設定です。

X11 で実行する場合の `WM_CLASS` X11 プロパティの class フィールド、Wayland で実行する場合の Wayland アプリケーション ID、および Ghostty が DBus への接続に使うバス名を制御します。

`gtk-single-instance=true` で実行する場合、起動ごとにこの値を変えると、別個の Ghostty インスタンスが新たに作成される点に注意してください。詳しくは、そのオプションを参照してください。

システムは Ghostty が起動時にデフォルトの `class` で DBus に接続することを想定しているため、この値を変更すると、`.desktop` ファイル、DBus アクティベーション、systemd ユーザーサービスから Ghostty を起動できなくなる場合があります。

クラス名は、[GTK ドキュメント](https://docs.gtk.org/gio/type_func.Application.id_is_valid.html)で定義された要件に従う必要があります。

デフォルトは `com.mitchellh.ghostty` です。

GTK ビルドだけに影響します。

## `x11-instance-name`

X11 で実行する場合の `WM_CLASS` X11 プロパティのインスタンス名フィールドを制御します。それ以外では効果がありません。

デフォルトは `ghostty` です。

GTK ビルドだけに影響します。

## `working-directory`

コマンドの起動後に移動するディレクトリです。

この設定より `window-inherit-working-directory` 設定が優先されます。同じプロセスに既存の Ghostty ターミナルがある場合は、`window-inherit-working-directory` が優先されます。それ以外では、この設定を使います。通常、この設定は最初のウィンドウだけで使われます。

以下の特別な場合を除き、デフォルトは `inherit` です。macOS では、launchd（ダブルクリック）または `open` からの起動を検出できた場合、デフォルトは `home` になります。GTK を使う Linux では、デスクトップランチャーからの起動を検出できた場合、デフォルトは `home` になります。

値には絶対パス、`~/` で始まるパス（チルダはユーザーのホームディレクトリに展開されます）、または以下の特別な値のいずれかを指定する必要があります。

  * `home` - 実行ユーザーのホームディレクトリです。

  * `inherit` - 起動元プロセスの作業ディレクトリです。

## `keybind`

キーバインドです。形式は `trigger=action` です。トリガーが重複すると、以前に設定した値を上書きします。アクションの一覧は、ドキュメントまたは `ghostty +list-actions` コマンドで確認できます。

トリガー: キーと修飾キーを `+` で区切った一覧です。例は `ctrl+a`、`ctrl+shift+b`、`up` です。

キーが単一の Unicode コードポイントの場合、そのコードポイントを生成するすべてのキー押下に一致します。これはキーボードレイアウトの影響を受けます。たとえば、`a` は QWERTY キーボードでは `a` キーに一致しますが、AZERTY キーボードでは `q` キーに一致します（US の物理配列を想定）。

Unicode コードポイントでは、修飾キーの組み合わせと修飾前のコードポイントを比較して照合します。修飾前のコードポイントは、他のソフトウェアでは「シフト前の文字」と呼ばれることもありますが、shift だけでなくすべての修飾キーを考慮します。たとえば、`ctrl+a` は `a` に一致しますが、`ctrl+shift+a`（US キーボードでは `A`）には一致しません。

さらに、コードポイントの照合では大文字と小文字を区別せず、修飾前のコードポイントを常にケースフォールディングして比較します。そのため、`ctrl+A` を設定しても、`ctrl+a` の押下に一致します。このため、キーボードレイアウトによっては指定できないキーの組み合わせがある点に注意してください。たとえば、US キーボードで `ctrl+_` は実現できません。`_` は `shift+-` であり、`ctrl+shift+-` は `ctrl+_` と等しくないためです（修飾キーが一致しません）。実現できないキーの組み合わせについて詳しくは、Qt 開発者による以下の優れた資料を参照してください。
https://doc.qt.io/qt-6/qkeysequence.html#keyboard-layout-issues

物理キーコードは、[W3C 仕様](https://www.w3.org/TR/uievents-code/)で定義されている任意のキーコードを使って指定できます。たとえば、`KeyA` はキーボードレイアウトにかかわらず、US 標準キーボードの物理的な `a` キーに一致します。これらは大文字と小文字を区別します。

見た目上の理由から、W3C コードはスネークケースにも対応しています。たとえば、`key_a` は `KeyA` と同じです。例外はファンクションキーだけで、たとえば `F1` は `f1`（アンダースコアなし）です。これは内部コードがスネークケースを使っているためですが、意図的にサポートしテストしているので、安全に使えます。すべて小文字のキーバインドを記述でき、こちらの方が見た目がよいと考えています。

`insert`、`up`、`f5` などの機能キーも、先ほどリンクした W3C 仕様のキーで指定します。

物理キーは Unicode コードポイントより常に優先されます。そのため、`a` と `KeyA` の両方を指定した場合、設定順にかかわらず、常に物理キーが使われます。

特別なキー `catch_all` は、他のキーバインドがないすべてのキーに一致します。修飾キーと組み合わせることもでき、たとえば `ctrl+catch_all` は、`ctrl` と同時に押された、他のキーバインドがない任意のキーに一致します。Ghostty はキーバインドの検索時に、まず修飾キー付きの `catch_all` との照合を試みます。一致するものがなく、イベントに修飾キーがある場合は、修飾キーなしの `catch_all` にフォールバックします。

有効な修飾キーは `shift`、`ctrl`（別名: `control`）、`alt`（別名: `opt`、`option`）、`super`（別名: `cmd`、`command`）です。修飾キー名と別名のどちらも使えます。キーバインドのデバッグ時には、出力では常に別名ではない修飾キー名を使います。

<Note>
 キーボードの fn キーや「地球儀」キーは、修飾キーとしてサポートされていません。これは、Ghostty が使う OS と GUI ツールキットの制約です。
</Note>

トリガーに関する補足:

  * 修飾キーは重複できません。`ctrl+ctrl+a` は無効です。

  * 修飾キーとキーは任意の順序で指定できます。`shift+a+ctrl` は*奇妙*ですが、有効です。

  * 入力キーは 1 つだけ指定できます。`ctrl+a+b` は無効です。

複数のトリガーを `>` で区切って指定し、アクションの実行にトリガーの連続入力を要求することもできます。たとえば、`ctrl+a>n=new_window` は、ユーザーが `ctrl+a` に続けて別途 `n` を押した場合だけ、`new_window` アクションを実行します。他のソフトウェアでは、リーダーキー、キーチョード、キーテーブルなどと呼ばれることもあります。シーケンスの要素数に固定の上限はありません。

<Warning>
 `ghostty` の CLI 引数でシーケンスを定義する場合、ほとんどのシェルでは `>` が特殊文字のため、おそらくキーバインドを引用符で囲む必要があります。例: ghostty --keybind='ctrl+a>n=new_window'
</Warning>

トリガーシーケンスには、次の特別な処理があります。

  * Ghostty は、シーケンスの次のキーを無期限に待ちます。タイムアウトは指定できません。接頭キーを強制的に出力するには、そのキーを明示的に出力する別のキーバインド（`ctrl+a>ctrl+a=text:foo` など）を割り当てるか、未割り当てのキーを押して両方のキーをプログラムに送信する必要があります。

  * シーケンスの途中で未割り当てのキーを押し、その入力を `ignore` する `catch_all` キーバインドがある場合、シーケンス全体を破棄し、何も起こりません。それ以外では、キーバインドがない場合と同様に、シーケンス全体をエンコードして実行中のプログラムに送信します。

  * シーケンスの接頭部分に既存のキーバインドがある場合、シーケンスはそのキーバインドを上書きします。たとえば、`ctrl+a` に `new_window`、`ctrl+a>n` に `new_tab` を割り当てると、`ctrl+a` を押しても何も起こりません。

  * 上記に加えて、既存のシーケンスの接頭部分を、新しいシーケンスではないキーバインドに使うと、既存のシーケンス全体の割り当てが解除されます。たとえば、`ctrl+a>n` と `ctrl+a>t` を割り当てた後に `ctrl+a` を直接割り当てると、`ctrl+a>n` と `ctrl+a>t` の両方が未割り当てになります。

  * `global:` または `all:` が付いたトリガーでは、トリガーシーケンスを使えません。この制約は将来解消される可能性があります。

アクションは、トリガーの条件が満たされたときに実行する操作です。形式は `action` または `action:param` です。後者は、アクションにパラメーターが必要な場合だけ有効です。

  * `ignore` - 何もせず、キー入力を無視します。特定の入力を破棄し、効果をなくすために使えます。

  * `unbind` - 割り当てを削除します。以前のアクションが削除され、印字可能なキーなら子コマンドに送信されます。一致するトリガーはすべて削除され、接頭辞を指定しなくても `physical:` 付きのトリガーも削除されます。

  * `csi:text` - CSI シーケンスを送信します。たとえば、`csi:A` は「カーソルを上へ」を送信します。

  * `esc:text` - エスケープシーケンスを送信します。たとえば、`esc:d` は右側の単語の末尾まで削除します。

  * `text:text` - 文字列を送信します。Zig の文字列リテラル構文を使います。たとえば、`text:\x15` は Ctrl-U を送信します。

  * その他すべてのアクションは、ドキュメントまたは `ghostty +list-actions` コマンドで確認できます。

アクションに関する注意事項:

  * パラメーターは `:` の後をそのまま使います。二重引用符などの仕組みも文字として含まれ、解析されません。空白を含む文字列を送信したい場合は、トリガーとアクション全体を二重引用符で囲んでください。例: `--keybind="up=csi:A B"`

キーバインドには、次の特別な値も指定できます。

  * `keybind=clear` は設定済みのキーバインドをすべて消去します。警告: デフォルトのキーバインドを含め、それまでのすべてのキーバインドが削除されます。

キーバインドのトリガーの前に特別な値を付けると、動作を変更できます。次の値があります。

 * `all:`

   キーバインドをすべてのターミナルサーフェスに適用します。デフォルトでは、フォーカスされたターミナルサーフェスだけに適用されます。有効な場合、キーバインドはすべてのターミナルサーフェスに送信されます。これはサーフェス固有のアクションだけに適用されます。すでにグローバルなアクション（`quit` など）では、この接頭辞は効果がありません。

   1.0.0 以降で利用可能です。

 * `global:`

   キーバインドをグローバルにします。デフォルトでは、Ghostty 内の適切な条件下（アプリケーションにフォーカスがある、場合によってはターミナルにフォーカスがある、など）だけで動作します。システム全体で（Ghostty にフォーカスがない場合などにも）キーバインドを使いたい場合は、この接頭辞を指定してください。`all:` も暗黙に適用されます。

   注意: すべての環境で動作するわけではありません。詳しくは後述の補足を参照してください。

   macOS では 1.0.0、GTK では 1.2.0 以降で利用可能です。

 * `unconsumed:`

   入力を消費しません。デフォルトでは、キーバインドは入力を消費し、対応するエンコード結果があってもターミナル内で実行中のプログラムに送信しません。エンコードした値をプログラムに送信したい場合は、キーバインド全体の前に `unconsumed:` を付けてください。例: `unconsumed:ctrl+a=reload_config`。`global:` と `all:` が付いたキーバインドは、この設定にかかわらず常に入力を消費します。特定のターミナルサーフェスに関連付けられていないため、エンコードされることはありません。

   1.0.0 以降で利用可能です。

 * `performable:`

   アクションを実行できる場合だけ入力を消費します。たとえば、`copy_to_clipboard` アクションは、コピーする選択範囲がある場合だけ入力を消費します。選択範囲がなければ、Ghostty はキーバインドが未設定の場合と同じように動作します。`global:` または `all:` 付きのキーバインドには効果がありません。キーシーケンスの場合、アクションを実行できなければシーケンスをリセットします（キーバインドがまったく設定されていない場合と同じ動作です）。

   実行可能な場合だけ動作するキーバインドは、アプリケーションメニューのショートカットとして表示されません。メニューのショートカットは、ターミナルの状態にかかわらずアクションを強制実行するためです。この種類のキーバインドも引き続き動作しますが、メニューにショートカットのラベルが表示されないだけです。

   1.1.0 以降で利用可能です。

キーバインドのトリガーは、接頭辞の組み合わせごとに別のものにはなりません。たとえば、`ctrl+a` と `global:ctrl+a` は別々のキーバインドではありません。後で設定したキーバインドが、先に設定したものを上書きします。この場合、`global:` のキーバインドが使われます。

複数の接頭辞を指定できます。たとえば、`global:unconsumed:ctrl+a=reload_config` は、キーバインドをグローバルにし、入力を消費せずに設定を再読み込みします。

<Note>
 `global:` は macOS と一部の Linux プラットフォームだけでサポートされています。
</Note>

macOS では、この機能には Ghostty へのアクセシビリティ権限の付与が必要です。`global:` キーバインドが指定された状態で Ghostty を起動または再読み込みすると、Ghostty は権限の要求を試みます。権限が付与されなければ、キーバインドは動作しません。macOS では、システム設定 -> プライバシーとセキュリティ -> アクセシビリティで権限を確認できます。

Linux では、XDG デスクトッププロトコルの実装の一部として [Global Shortcuts](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) プロトコルを実装するデスクトップ環境が必要です。グローバルショートカットへの対応状況が分かっているデスクトップ環境には、次のものがあります。

 - KDE Plasma（[5.27](https://kde.org/announcements/plasma/5/5.27.0/#wayland) 以降）と GNOME（[48](https://release.gnome.org/48/#and-thats-not-all) 以降）では、ほとんど、またはまったく設定せずにグローバルショートカットを使えるはずです。

 - Hyprland では、手動の設定がいくらか必要です。[Hyprland Wiki](https://wiki.hyprland.org/Configuring/Binds/#dbus-global-shortcuts) の手順に従って、グローバルショートカットを正しく設定してください。（重要: [`xdg-desktop-portal-hyprland`](https://wiki.hyprland.org/Hypr-Ecosystem/xdg-desktop-portal-hyprland/) もインストールする必要があります。）

 - 特に、Sway のような wlroots ベースのコンポジターには、グローバルショートカットが実装されていません（[上流の issue](https://github.com/emersion/xdg-desktop-portal-wlr/issues/240) を参照）。

## アクションの連鎖 {/* #chained-actions */}

キーバインドでは、後続のアクションに `chain` キーワードを使うことで、複数のアクションを指定できます。キーバインドが有効になると、連鎖したすべてのアクションが順番に実行されます。構文は次のとおりです。

```ini
keybind = ctrl+a=new_window
keybind = chain=goto_split:left
```

この設定では、`ctrl+a` に、まず新しいウィンドウを開き、次に左の分割へフォーカスを移す操作を割り当てます。各 `chain` エントリーは、直前に定義されたキーバインドにアクションを追加します。任意の数のアクションを連鎖させられます。

```ini
keybind = ctrl+a=new_window
keybind = chain=goto_split:left
keybind = chain=toggle_fullscreen
```

連鎖したアクションに `global:` や `unconsumed:` のような接頭辞は付けられません。元のキーバインドのフラグが連鎖全体に適用されます。

アクションの連鎖はキーシーケンスでも使えます。例を示します。

```ini
keybind = ctrl+a>n=new_window
keybind = chain=goto_split:left
````

キーシーケンスでの連鎖は、シーケンス内で最後に指定されたキーバインドに適用されます。

キーバインドの連鎖は Ghostty 1.3.0 以降で利用可能です。

## キーテーブル {/* #key-tables */}

「キーテーブル」と呼ばれる、名前付きのキーバインドの集合も作成できます。キーバインドを使うには、キーテーブルを明示的に有効にする必要があります。これにより、「コピーモード」や「vim モード」などの機能を実装できます。一般的には、モードを持つキーボード入力を実装できます。

キーテーブルは `<table>/<binding>` という構文で定義します。`<binding>` は、上で説明したキーバインドの指定全体です。`<table>` はキーテーブルの名前です。テーブル名には `/`、`=`、`+`、`>` 以外の任意の文字を含められます。`+` と `>` は、キーバインド構文（修飾キーの組み合わせとキーシーケンス）用に予約されています。たとえば、`foo/ctrl+a=new_window` は、`foo` という名前のテーブル内にキーバインドを定義します。

テーブルは、キーバインドアクション `activate_key_table:<name>` と `deactivate_key_table` で有効化・無効化します。他にもテーブル関連のキーバインドアクションがあります。完全な一覧はドキュメントを参照してください。これらがキーテーブルを操作する主な方法です。

キーバインドの検索は最も内側のテーブルから外側へ進むため、内側のテーブルで明示的に割り当てを解除しない限り、デフォルトのテーブルのキーバインドも引き続き使えます。

キーテーブルには、次の特別な構文と処理があります。

  * `<name>/`（キーバインドなし）は、テーブルを定義して消去し、すべてのキーバインドと設定をリセットします。

  * すでに最も内側にあるテーブルを有効にすることはできず、そのような要求は無視されます。ただし、最も内側でない限り、同じテーブルがスタック内に複数回現れることは可能です（たとえば、`A -> B -> A -> B` は有効ですが、`A -> B -> B` は無効です）。

  * `activate_key_table_once:<name>` を使うと、テーブルをワンショットモードで有効にできます。ワンショットテーブルは、catch-all 以外のキーバインドが呼び出されると自動的に無効になります。

  * テーブル内でもキーシーケンスが使えます。例は `foo/ctrl+a>ctrl+b=new_window` です。無効なキーが押されるとシーケンスは終了しますが、テーブルは有効なままです。

  * テーブル内でもアクションを連鎖させられます。`chain` キーワードは、テーブル内で最後に定義したキーバインドに適用されます。たとえば、`table/ctrl+a=new_window` を設定した場合、`chain=text:hello` で連鎖させられます。重要: chain 自体にはテーブル名を付けません。いずれかのテーブルで最後に定義したキーバインドに適用されるためです。

  * テーブル内でも `global:` などの接頭辞を使えます。例は `foo/global:ctrl+a=new_window` です。

キーテーブルは Ghostty 1.3.0 以降で利用可能です。

## `key-remap`

Ghostty 内で修飾キーを再割り当てします。システム全体の設定に影響を与えずに、アプリケーション単位で修飾キーの交換や再割り当てができます。

形式は `from=to` で、`from` と `to` はどちらも修飾キー名です。`ctrl`、`alt`、`shift`、`super`（macOS では `cmd`/`command`）のような汎用名や、`left_ctrl`、`right_alt` など左右を指定する名前を使えます。

Ghostty 外部のキーボードレイアウトやキーのエンコードは変更しません。たとえば macOS では、`option` を `ctrl` に再割り当てしても、`option+a` は引き続き `å` を生成することがあります。通常、デスクトップ環境は Ghostty がキーイベントを受け取るよりずっと前に、キー配列を処理するためです。

例:

```
key-remap = ctrl=super
key-remap = left_control=right_alt
```

重要な注意事項:

* これは一方向の再割り当てです。`ctrl=super` とすると、物理的な Ctrl キーは Super として動作しますが、Super キーは Super のままです。

* 再割り当ては推移しません。`ctrl=super` と `alt=ctrl` を指定した場合、Alt を押すと Ctrl になり、Super にはなりません。

* キーバインドの照合とターミナル入力のエンコードの両方に影響します。キーボードレイアウトや、Ghostty が受信する前のキーの解釈には影響しません。たとえば macOS では、`option` を `ctrl` に再割り当てしても、`option+a` は引き続き `å` を生成することがあります。

* 汎用の修飾キー（`ctrl` など）は、左右両方の物理キーに一致します。片側だけを再割り当てするには、左右を指定する名前（`left_ctrl` など）を使ってください。

他にも、期待どおりに見えなくても、この機能の設計上は意図した動作である特殊な状況があります。

* macOS では、メインメニューのキーバインドは再割り当ての前に実行されます。macOS 自体がメニューの実行を処理し、それは Ghostty がキーイベントを受け取る前に行われるためです。回避するには、メニュー項目のキーバインドを解除し、希望する修飾キーで再度割り当ててください。

この設定を繰り返し指定すると、複数の再割り当てを指定できます。

## `window-padding-x`

ウィンドウの水平方向の余白です。ターミナルのセルとウィンドウの左右の境界の間に余白を設けます。値の単位はポイントで、画面の DPI に合わせて適切に拡大縮小されます。

値を大きくしすぎると、余白によってグリッドが完全に押しつぶされ、画面に何も描画されなくなります。妥当な値を選ぶのはユーザーの責任です。不適切な値を選ぶと、ログに警告が表示されます。

実行時にこの設定を変更した場合、新しいウィンドウやタブなど、新しいターミナルだけに影響します。

左右で異なる余白を設定するには、2 つの数値をカンマで区切って指定します。たとえば、`window-padding-x = 2,4` は左の余白を 2、右の余白を 4 にします。両方の余白を同じ値にする場合は、値を 1 つだけ指定できます。たとえば、`window-padding-x = 2` は両方の余白を 2 にします。

## `window-padding-y`

ウィンドウの垂直方向の余白です。ターミナルのセルとウィンドウの上下の境界の間に余白を設けます。値の単位はポイントで、画面の DPI に合わせて適切に拡大縮小されます。

値を大きくしすぎると、余白によってグリッドが完全に押しつぶされ、画面に何も描画されなくなります。妥当な値を選ぶのはユーザーの責任です。不適切な値を選ぶと、ログに警告が表示されます。

実行時にこの設定を変更した場合、新しいウィンドウやタブなど、新しいターミナルだけに影響します。

上下で異なる余白を設定するには、2 つの数値をカンマで区切って指定します。たとえば、`window-padding-y = 2,4` は上の余白を 2、下の余白を 4 にします。両方の余白を同じ値にする場合は、値を 1 つだけ指定できます。たとえば、`window-padding-y = 2` は両方の余白を 2 にします。

## `window-padding-balance`

通常、ビューポートの寸法はセルサイズで割り切れません。この場合、列の末端や最後の行の下に余分な余白ができることがあります。`true` の場合、この余分な余白を四辺に自動的に振り分け、片側への偏りを抑えます。`false` の場合、左上のグリッドセルは、他の `window-padding` オプションで指定した余白を除き、常に余白なしで端に接します。

他の `window-padding` フィールドが設定されていても、これが `true` なら適用されます。他の余白を先に適用し、それによって実際のグリッドセル数が変わることがあります。その後、指定のビューポートとグリッドセルのサイズに対して余白の均衡を取るため、最後にこの設定を適用します。

## `window-padding-color`

ウィンドウの余白領域の色です。有効な値は次のとおりです。

* `background` - `background` で指定した背景色です。
* `extend` - 最も近いグリッドセルの背景色を拡張します。
* `extend-always` - 「extend」と同じですが、後述する拡張を無効にするヒューリスティックを適用せず、常に拡張します。

「extend」は、特定の状況では無効になります。通常画面を使うアプリケーション（Neovim のようなものではないもの）では、次のいずれかに該当すると、色を垂直方向に拡張しません。

* 最も近い行に、デフォルトの背景色のセルが含まれている場合です。この場合、余白の色もデフォルトの背景色で問題ないという考え方です。
* 最も近い行がプロンプト行の場合です（シェル統合が必要です）。プロンプトには、拡張すると見栄えが悪くなる Powerline のグリフが含まれることが多いためです。
* 最も近い行に、ぴったり収まる Powerline 文字が含まれる場合です。これらは拡張すると見栄えが悪くなります。

## `window-vsync`

描画を画面のリフレッシュレートに同期させます。true の場合、ティアリングを抑え、画面に合わせて再描画しますが、入力遅延が生じる可能性があります。false の場合、再描画頻度を最大化しますが、ティアリングが発生する可能性があり、高負荷時には CPU と電力の使用量が増えることがあります。

macOS で同期しない描画を行うと、カーネルパニック（macOS 14.4 以降）や、DisplayLink など一部のハードウェア経由の外部ディスプレイでパフォーマンスの問題が起こるため、デフォルトは true です。入力遅延を最小限にしたい場合は、上記のリスクを理解したうえで false に設定してください。

実行時にこの値を変更した場合、新しいターミナルだけに影響します。

現在、この設定は macOS でのみサポートされています。

## `window-inherit-working-directory`

true の場合、新しいウィンドウは、直前にフォーカスされていたウィンドウの作業ディレクトリを引き継ぎます。以前にフォーカスされたウィンドウがなければ、デフォルトの作業ディレクトリ（`working-directory` オプション）を使います。

## `tab-inherit-working-directory`

true の場合、新しいタブは、直前にフォーカスされていたタブの作業ディレクトリを引き継ぎます。以前にフォーカスされたタブがなければ、デフォルトの作業ディレクトリ（`working-directory` オプション）を使います。

## `split-inherit-working-directory`

true の場合、新しい分割ペインは、直前にフォーカスされていた分割の作業ディレクトリを引き継ぎます。以前にフォーカスされた分割がなければ、デフォルトの作業ディレクトリ（`working-directory` オプション）を使います。

## `window-inherit-font-size`

true の場合、新しいウィンドウとタブは、直前にフォーカスされていたウィンドウのフォントサイズを引き継ぎます。以前にフォーカスされたウィンドウがなければ、デフォルトのフォントサイズを使います。false の場合、`font-size` 設定で指定したデフォルトのフォントサイズを使います。

## `window-decoration`

ウィンドウ装飾の希望を設定します。この設定はあくまで*希望*を指定するもので、実際の OS、デスクトップ環境、ウィンドウマネージャーなどが上書きする場合があります。Ghostty は可能な限り従いますが、常に実現できるとは限りません。

有効な値:

 * `none`

   すべてのウィンドウ装飾を無効にします。タイトルバーや境界線などは表示されません。macOS では、タブも無効になります（システムによる制約です）。

 * `auto`

   現在の OS とデスクトップ環境で検出した設定に基づき、クライアント側またはサーバー側の装飾を自動的に選びます。このオプションにすると、通常はデスクトップに最も「ネイティブ」な見た目になります。

 * `client`

   クライアント側の装飾を優先します。

   1.1.0 以降で利用可能です。

 * `server`

   サーバー側の装飾を優先します。これは GTK を使う Linux だけに関係し、X11、または `org_kde_kwin_server_decoration` プロトコルをサポートするコンポジター上の Wayland が対象です（KDE Plasma などですが、GNOME 以外のほぼすべてのデスクトップがこのプロトコルに対応しています）。

   `server` を設定しても、環境がサーバー側の装飾に対応していなければ、代わりにクライアント側の装飾を使います。

   1.1.0 以降で利用可能です。

デフォルト値は `auto` です。

後方互換性と利便性のため、ブール値の true と false も指定できます。`true` は `auto` と同じです。`false` は `none` と同じです。クライアント側とサーバー側の装飾を区別しないシステム（macOS や Windows など）を主に使うユーザーに便利です。

「toggle_window_decorations」キーバインドアクションで、この設定を実行時に切り替えるキーバインドを作成できます。

macOS: ネイティブのウィンドウ境界や角丸を残したままタイトルバーを隠すには、代わりに `macos-titlebar-style = hidden` を使ってください。

## `window-title-font-family`

アプリケーションのウィンドウとタブのタイトルに使うフォントです。

未設定の場合は、システムのデフォルトフォントを使います。

<Note>
 システムで利用できる任意のフォントを使えます。等幅フォントである必要はありません。
</Note>

macOS では 1.0.0、GTK では 1.1.0 以降で利用可能です。

## `window-subtitle`

ウィンドウのサブタイトルに表示するテキストです。有効な値は次のとおりです。

  * `false` - サブタイトルを無効にします。
  * `working-directory` - サーフェスの作業ディレクトリをサブタイトルにします。

この機能は GTK でのみサポートされています。

1.1.0 以降で利用可能です。

## `window-theme`

ウィンドウに使うテーマです。有効な値は次のとおりです。

  * `auto` - 設定されたターミナルの背景色に基づいてテーマを決定します。「theme」設定でライトとダークのテーマを個別に指定している場合は効果がありません。その場合、「auto」は「system」と同じ動作になります。
  * `system` - システムのテーマを使います。
  * `light` - システムのテーマにかかわらず、ライトテーマを使います。
  * `dark` - システムのテーマにかかわらず、ダークテーマを使います。
  * `ghostty` - Ghostty の設定で指定した背景色と前景色を使います。Linux ビルドでのみサポートされています。

macOS では、`macos-titlebar-style` が `tabs` または `transparent` の場合、ターミナルの背景色の明るさに基づいてウィンドウのテーマを自動設定します。これはターミナルウィンドウだけに適用されます。Ghostty 内のターミナル以外のウィンドウには、引き続きこの設定が適用されます。

現在、macOS と Linux でのみサポートされています。

## `window-colorspace`

ターミナルの色を解釈する際に使う色空間です。「ターミナルの色」とは、設定で指定された色と、直接色指定の SGR シーケンスが生成する色を指します。

有効な値:

  * `srgb` - sRGB 色空間で色を解釈します。デフォルトです。
  * `display-p3` - Display P3 色空間で色を解釈します。

現在、この設定は macOS でのみサポートされています。

## `window-height`
## `window-width`

ウィンドウの初期サイズです。デフォルトではターミナルのグリッドセル単位です。有効にするには、両方の値を設定する必要があります。片方だけを設定しても無視されます。

現在、ピクセル単位のサイズ指定には対応していませんが、将来の変更で対応する可能性があります。未指定の場合、アプリケーションのランタイムがデフォルトのサイズを決定します。

ウィンドウマネージャーがサイズを制限したり、上書きしたりする場合があります。たとえば、タイル型ウィンドウマネージャーは、グリッドに収まるようにウィンドウを特定のサイズにすることがあります。Ghostty は可能な限り対応しますが、これを制御することはできません。

画面サイズを超えるサイズは、画面サイズに制限されます。これを利用して、デフォルトで最大化されたウィンドウサイズを指定できます。

新しいタブや分割、その他の入れ子のターミナル要素には影響しません。新しいウィンドウの初期サイズだけに影響します。作成後にこの値を変更しても、ウィンドウのサイズは変わりません。初期サイズだけに使われます。

不具合: GTK を使う Linux では、ウィンドウサイズの計算でウィンドウ装飾が正しく考慮されません。そのため、グリッドの寸法はこの設定と完全には一致しません。ウィンドウ装飾を無効にすると（`window-decoration` を参照）、期待どおりに動作します。

幅 10、高さ 4 より小さいウィンドウは指定できません。

## `window-position-x`
## `window-position-y`

ウィンドウの初期位置です。単位はピクセルで、プライマリーモニターの左上隅を基準にします。有効にするには、両方の値を設定する必要があります。片方だけを設定しても無視されます。

ウィンドウマネージャーが位置を制限したり、上書きしたりする場合があります。たとえば、タイル型ウィンドウマネージャーは、グリッドに収まるようにウィンドウを特定の位置に配置することがあります。Ghostty は可能な限り対応しますが、これを制御することはできません。

負の値を使えるかどうかも、OS とウィンドウマネージャー次第です。一部のウィンドウマネージャーは、画面外へのウィンドウ配置を許可しません。

無効な位置の扱いはランタイムによって異なりますが、通常は最も近い有効な位置に制限されます。

macOS では、表示可能な画面領域の左上隅を基準にします。つまり、メニューバーが表示されている場合、ウィンドウはその下に配置されます。

<Note>
 macOS でのみサポートされています。ウィンドウが自身の位置を指定できるのは X11 だけで Wayland では許可されないため、GTK ランタイムではウィンドウ位置の設定をサポートしていません。
</Note>

## `window-save-state`

ウィンドウ状態の保存と復元を有効にするかどうかです。状態には、位置、サイズ、タブ、分割などが含まれます。作業ディレクトリの維持など、一部の状態にはシェル統合が必要です。詳しくは `shell-integration` を参照してください。

この設定には、3 つの有効な値があります。

  * `default` はシステムのデフォルトの動作を使います。macOS では、アプリケーションが強制終了した場合、または Settings.app でシステム全体に設定している場合だけ、状態を保存します。

  * `never` はウィンドウ状態を保存しません。

  * `always` は Ghostty の終了時に常にウィンドウ状態を保存します。

Ghostty が動作していないときに値を `never` に変更すると、次回起動時にはウィンドウ状態を復元しません。

Ghostty が動作していないときに値を `default` に変更し、前回終了時に状態を保存していた場合、次回起動時もウィンドウ状態を復元します。前回の保存が強制的なものだったかどうかを Ghostty は判断できないためです（macOS はこの情報を提供しません）。

Ghostty が動作していないときに、ウィンドウ状態を保存する設定へ変更しても、以前のウィンドウ状態は復元されません。有効な場合だけ、終了時に状態を保存するためです。

デフォルト値は `default` です。

現在、macOS でのみサポートされています。Linux では効果がありません。

## `window-step-resize`

フォーカスされたサーフェスのセルサイズを単位として、ウィンドウサイズを段階的に変更します。無効な場合、サーフェスはピクセル単位でサイズ変更されます。現在は macOS でのみサポートされています。

## `window-new-tab-position`

新しいタブを作成する位置です。有効な値は次のとおりです。

  * `current` - 現在フォーカスされているタブの後ろに新しいタブを挿入します。フォーカスされたタブがない場合は末尾に挿入します。

  * `end` - タブ一覧の末尾に新しいタブを挿入します。

## `window-show-tab-bar`

タブバーを表示するかどうかです。

有効な値:

 - `always`

   タブが 1 つだけでも、常にタブバーを表示します。

   1.2.0 以降で利用可能です。

 - `auto` *（デフォルト）*

   タブバーを自動的に表示・非表示にします。タブが 2 つ以上ある場合だけ表示します。

 - `never`

## `config-file`

追加で読み込む設定ファイルです。繰り返し指定して、複数の設定ファイルを読み込めます。設定ファイル自体から、さらに他の設定ファイルを読み込むこともできます。パスは `config-file` ディレクティブを含むファイルからの相対パスです。コマンドライン引数では、現在の作業ディレクトリからの相対パスになります。

ファイルパスの前に ? を付けると、ファイルが存在しない場合のエラーを抑制します。名前がリテラルの ? で始まるファイルを読み込みたい場合は、パスを二重引用符（"）で囲んでください。

循環参照は許可されません。循環を検出すると、エラーをログに記録し、その設定ファイルを無視します。

設定ファイルは、それを指定した設定の後に、定義された順序で読み込まれます。**これは非常に微妙ですが重要な点です。** 言い換えると、設定ファイルは、設定全体の読み込みが終わるまで有効になりません。たとえば、次の設定の場合です。

```
config-file = "foo"
a = 1
```

「foo」に `a = 2` が含まれている場合、`a` の最終的な値は 2 になります。入れ子の `config-file` 値を指定した設定ファイルの後に、`foo` が読み込まれるためです。

## `config-default-files`

true の場合、デフォルトの設定ファイルパスを読み込みます。現在のデフォルトは、XDG 設定パス（$XDG_CONFIG_HOME/ghostty/config.ghostty）だけです。

false の場合、デフォルトの設定パスは読み込みません。外部からの影響を最小限にして CLI から Ghostty を使うことを直接の目的としています。

これは CLI 専用の設定です。設定ファイル内で指定しても効果はありません。エラーにはなりませんが、何もしません。CLI 引数でのみ設定できます。

## `confirm-close-surface`

## `quit-after-last-window-closed`

macOS では、アプリケーションの標準的な動作に合わせて、デフォルトは `false` です。Linux では、一般的に期待される動作に合わせて、デフォルトは `true` です。

## `undo-timeout`

期間は、数値の後に時間の単位を付けたものを並べて指定します。数値と単位の間に空白を入れられます。それぞれの数値と単位を合算したものが、合計の期間になります。

使用できる時間の単位は次のとおりです。

  * `y` - 365 SI 日、8760 時間、または 31536000 秒です。うるう年やうるう秒による調整は行いません。
  * `d` - 1 SI 日、または 86400 秒です。
  * `h` - 1 時間、または 3600 秒です。
  * `m` - 1 分、または 60 秒です。
  * `s` - 1 秒です。
  * `ms` - 1 ミリ秒、または 0.001 秒です。
  * `us` または `µs` - 1 マイクロ秒、または 0.000001 秒です。
  * `ns` - 1 ナノ秒、または 0.000000001 秒です。

例:
  * `1h30m`
  * `45s`

単位は繰り返し指定でき、その場合は合算されます。つまり、`1h1h` は `2h` と同じです。紛らわしいため、このような指定は避けてください。将来の更新で禁止される可能性があります。

この設定は macOS でのみサポートされています。Linux は取り消し操作自体に対応していないため、この設定は効果がありません。

## `quick-terminal-size`

クイックターミナルのサイズです。

画面の寸法（高さ・幅）に対する割合、またはピクセル単位の絶対サイズで指定できます。割合には `%`（`20%` など）、ピクセル値には `px`（`300px` など）を付けます。接尾辞のない値は設定エラーになります。

中央配置以外では、最初の値とカンマ（`,`）で区切ってもう 1 つのサイズを指定しない限り、*副軸*は最大化されます。割合とピクセルを混在させることもできます。たとえば、上部に配置するクイックターミナルに `50%,500px` を指定すると、高さは画面の半分、幅は 500 ピクセルになります。

## `shell-integration`

シェル統合の自動注入を有効にするかどうかです。シェル統合は、次のような多数の機能によって、ターミナルの使い勝手を大幅に向上させます。

  * 作業ディレクトリを報告し、新しいタブや分割が前のターミナルの作業ディレクトリを引き継げるようにします。

  * プロンプトをマークし、「jump_to_prompt」キーバインドを使えるようにします。

  * プロンプトで待機中の場合、ターミナルを閉じるときに確認しません。

  * 複雑なプロンプトがあるときのウィンドウサイズ変更で、通常は描画が大幅に改善します。

指定できる値は次のとおりです。

  * `none` - 自動注入を行いません。手動でシェルを設定して統合を有効にすることはできます。

  * `detect` - ファイル名からシェルを検出します。

  * `bash`、`elvish`、`fish`、`nushell`、`zsh` - 指定したシェルの注入方式を使います。

デフォルト値は `detect` です。

## `shell-integration-features`

有効にするシェル統合機能です。shell-integration による自動読み込み、または手動で、Ghostty のシェル統合が読み込まれている必要があります。

有効にする機能をカンマ区切りの一覧で指定します。機能の前に `no-` を付けると無効になります。省略するとデフォルト値が使われるため、不要な機能は明示的に無効にする必要があります。`true` または `false` ですべての機能を有効または無効にすることもできます。

例: `cursor`、`no-cursor`、`sudo`、`no-sudo`、`title`、`no-title`

利用可能な機能:

  * `cursor` - プロンプトでカーソルを棒状にします。

  * `sudo` - terminfo を維持する sudo ラッパーを設定します。

  * `title` - シェル統合でウィンドウのタイトルを設定します。

  * `ssh-env` - SSH の環境変数の互換性を有効にします。リモートホストへの接続時に TERM を `xterm-ghostty` から `xterm-256color` に自動変換し、COLORTERM、TERM_PROGRAM、TERM_PROGRAM_VERSION を引き渡します。リモートホストがこれらの変数を受け入れるかどうかは、sshd_config で許可されているかどうかによります。
    （1.2.0 以降で利用可能です。）

  * `ssh-terminfo` - リモートホストへの terminfo の自動インストールを有効にします。Ghostty の terminfo エントリーがないホストへの接続時に、`infocmp` と `tic` を使ってインストールを試みます。ローカルで `infocmp`、リモートホストで `tic` が利用できる必要があります。リモートホストに一度インストールすると、再インストールを避けるために自動的に「キャッシュ」します。必要に応じて、`+ssh-cache` CLI アクションの各種引数を使い、インストールキャッシュを手動管理できます。
    （1.2.0 以降で利用可能です。）

  * `path` - Ghostty のバイナリのディレクトリを PATH に追加します。シェルの初期化スクリプトが PATH をリセットしても、シェルで `ghostty` コマンドを使えるようにします。システムスクリプトが PATH を上書きすることの多い macOS で特に便利です。まだ含まれていない場合だけ追加します。

SSH 機能は独立して動作し、組み合わせることで最適な使い勝手を得られます。`ssh-env` と `ssh-terminfo` の両方を有効にすると、Ghostty はリモートホストに terminfo をインストールし、TERM に `xterm-ghostty` を使います。インストールに失敗した場合は、環境変数とともに `xterm-256color` へフォールバックします。

## `command-palette-entry`

コマンドパレットのカスタムエントリーです。

各エントリーには、タイトル、対応するアクション、任意の説明を指定します。各フィールドは、フィールド名、コロン（`:`）、指定する値の順に記述します。アクションの構文は、キーバインドアクションと同じです。フィールド間の空白は無視されます。

値にカンマなどの特殊文字を含めたい場合は、二重引用符で囲むと Zig の文字列リテラルとして解釈されます。値の先頭や末尾に空白を含める場合にも便利です。文字列リテラルについて詳しくは、[Zig のドキュメント](https://ziglang.org/documentation/master/#Escape-Sequences)を参照してください。複数行の文字列リテラルには対応していません。

フィールド名を二重引用符で囲むことはできません。

```ini
command-palette-entry = title:Reset Font Style, action:csi:0m
command-palette-entry = title:Crash on Main Thread,description:Causes a crash on the main (UI) thread.,action:crash:main
command-palette-entry = title:Focus Split: Right,description:"Focus the split to the right, if it exists.",action:goto_split:right
command-palette-entry = title:"Ghostty",description:"Add a little Ghostty to your terminal.",action:"text:\xf0\x9f\x91\xbb"
```

デフォルトでは、対話的な場面で便利であっても、簡単に使えたり覚えられたりするショートカットがないアクションの多くが、コマンドパレットに登録されています。空の値を設定すると、デフォルトのエントリーを消去できます。

```ini
command-palette-entry =
```

1.2.0 以降で利用可能です。

## `osc-color-report-format`

色情報を要求する OSC シーケンスの報告形式を設定します。現在、Ghostty は OSC 10（前景色）、OSC 11（背景色）、OSC 4（256 色パレット）の問い合わせに対応しており、デフォルトでは、各成分を 16 ビットに拡大した RGB 値を報告します。これは、ほとんどのターミナルが使う報告形式です。ただし、一部の古いアプリケーションには、拡大していない 8 ビット成分が必要な場合があります。報告を完全に無効にすることもできます。成分は小文字の 16 進数です。

指定できる値は次のとおりです。

  * `none` - OSC 4/10/11 の問い合わせに応答しません。

  * `8-bit` - 成分を拡大せずに返します。例は `rr/gg/bb` です。

  * `16-bit` - 成分を拡大して返します。例は `rrrr/gggg/bbbb` です。

デフォルト値は `16-bit` です。

## `vt-kam-allowed`

true の場合、ターミナル内で「KAM」モード（ANSI モード 2）を使うことを許可します。KAM は、アプリケーションの要求に応じてキーボード入力を無効にします。一般的な機能ではなく、有効にすることは推奨しません。KAM が必要だと分かる人には説明不要なので、これ以上は説明しません。必要かどうか分からないのであれば、必要ありません。

## `custom-shader`

デフォルトのシェーダーの後に実行するカスタムシェーダーです。すべてのプラットフォームで、GLSL 構文のシェーダーのファイルパスを指定します。

<Warning>
 無効なシェーダーは、ウィンドウ全体を真っ黒にするなどして Ghostty を使用不能にすることがあります。その場合は、この設定を解除してシェーダーを無効にできます。
</Warning>

カスタムシェーダーのサポートは Shadertoy シェーダーに基づき、互換性があります。シェーダーには `mainImage` 関数を指定してください。利用可能な uniform は、おおむね Shadertoy と一致しますが、一部に注意点と Ghostty 固有の拡張があります。

シェーダーで利用できる uniform 値は次のとおりです。

 * `sampler2D iChannel0` - 入力テクスチャです。

   現在のターミナル画面を含むテクスチャです。複数のカスタムシェーダーを指定すると、前のシェーダーの出力がこのテクスチャに書き込まれ、複数の効果を組み合わせられます。

 * `vec3 iResolution` - 出力テクスチャのサイズ、`[width, height, 1]`（ピクセル単位）です。

 * `float iTime` - 最初のフレームの描画からの経過時間を秒単位で示します。

 * `float iTimeDelta` - 前のフレームの描画からの経過時間を秒単位で示します。

 * `float iFrameRate` - 平均フレームレートです。（現在は未対応）

 * `int iFrame` - これまでに描画したフレーム数です。

 * `float iChannelTime[4]` - 動画または音声入力の現在時刻です。（該当なし）

 * `vec3 iChannelResolution[4]` - 4 つの入力サンプラーの解像度です。

   現在は `iChannel0` だけが存在し、`iChannelResolution[0]` は `iResolution` と同じです。

 * `vec4 iMouse` - マウスの入力情報です。（現在は未対応）

 * `vec4 iDate` - 日付・時刻情報です。（現在は未対応）

 * `float iSampleRate` - 音声のサンプルレートです。（該当なし）

Ghostty 固有の拡張:

 * `vec4 iCurrentCursor` - ターミナルカーソルの情報です。

   - `iCurrentCursor.xy` は、現在のカーソルの -X、+Y 側の隅です。
   - `iCurrentCursor.zw` は、現在のカーソルの幅と高さです。

 * `vec4 iPreviousCursor` - 前のターミナルカーソルの情報です。

 * `vec4 iCurrentCursorColor` - ターミナルカーソルの色です。

 * `vec4 iPreviousCursorColor` - 前のターミナルカーソルの色です。

 * `vec4 iCurrentCursorStyle` - ターミナルカーソルのスタイルです。

   各カーソルスタイルを簡単に使うためのマクロが定義されています。

   - `CURSORSTYLE_BLOCK` または `0`
   - `CURSORSTYLE_BLOCK_HOLLOW` または `1`
   - `CURSORSTYLE_BAR` または `2`
   - `CURSORSTYLE_UNDERLINE` または `3`
   - `CURSORSTYLE_LOCK` または `4`

 * `vec4 iPreviousCursorStyle` - 前のターミナルカーソルのスタイルです。

 * `vec4 iCursorVisible` - ターミナルカーソルの表示状態です。

 * `float iTimeCursorChange` - ターミナルカーソルが変化した時刻です。

   カーソルの位置または色が変わると、`iTime` uniform と同じ時刻に設定されます。これを `iTime` から引くことで、変化からの経過時間を計算できます。

 * `float iTimeFocus` - サーフェスが最後に iFocus を得た時刻です。

   サーフェスがフォーカスを得ると、`iTimeCursorChange` と同様に、現在の `iTime` の値が設定されます。`iTime - iTimeFocus` を計算することで、フォーカスを得た、または失った時点からの経過時間を計算できます。ターミナルがフォーカスを取り戻したときに再開するアニメーションに使えます。

 * `int iFocus` - サーフェスの現在のフォーカス状態です。

   フォーカスがある場合は 1.0、ない場合は 0.0 です。シェーダーはこれにより非フォーカス状態を検出し、まれに発生する「見かけ上のフレーム」（修飾キーの押下や、フォーカスされていない分割ペイン内のリンクへのホバーなど）による大きな時間差が引き起こす、アニメーションの乱れを防げます。`iFocus > 0` で、現在フォーカスされているかどうかを判定できます。

 * `vec3 iPalette[256]` - ターミナルの 256 色パレットです。

   パレットの全 256 色の RGB 値を [0.0, 1.0] に正規化したものです。インデックス 0–15 は ANSI 色、16–231 は 6×6×6 の色立方体、232–255 はグレースケールです。

 * `vec3 iBackgroundColor` - ターミナルの背景色（RGB）です。

 * `vec3 iForegroundColor` - ターミナルの前景色（RGB）です。

 * `vec3 iCursorColor` - ターミナルのカーソル色（RGB）です。

 * `vec3 iCursorText` - ターミナルのカーソル部分のテキスト色（RGB）です。

 * `vec3 iSelectionBackgroundColor` - 選択範囲の背景色（RGB）です。

 * `vec3 iSelectionForegroundColor` - 選択範囲の前景色（RGB）です。

シェーダーのコンパイルに失敗すると、そのシェーダーは無視されます。コンパイルは設定の読み込み後、専用の描画スレッドで行われるため、関連するエラーは設定エラーとして表示されず、ログだけに記録されます。対話的な開発には [shadertoy.com](https://shadertoy.com) を使ってください。

繰り返し指定して複数のシェーダーを読み込めます。指定した順序で実行されます。

実行時に変更でき、開いているすべてのターミナルに影響します。

## `custom-shader-animation`

`true`（デフォルト）の場合、カスタムシェーダーを使っているとき、フォーカスされたターミナルサーフェスでアニメーションループを実行します。CPU 使用量は少し増えますが（通常 10% 未満）、シェーダーをアニメーションさせられます。カスタムシェーダーがあり、ターミナルにフォーカスがある場合だけ実行します。

`false` の場合、ターミナルとカスタムシェーダーは、ターミナルが更新されたときだけ描画されます。より効率的ですが、シェーダーはアニメーションしません。

`always` に設定すると、フォーカスの有無にかかわらず常にアニメーションループを実行します。この場合も、カスタムシェーダーを使っているときだけ実行します。ターミナルサーフェスごとの CPU 使用量が増え、シェーダーやターミナルの使い方によっては、かなりの負荷になる点に注意してください。

実行時に変更でき、開いているすべてのターミナルに影響します。

## `bell-features`

ランタイムがベルに対応している場合に有効にするベル機能です。すべてのランタイムですべての機能を使えるわけではありません。有効にする機能をカンマ区切りの一覧で指定します。前に `no-` を付けると無効になります。省略した機能にはデフォルト値を使います。

有効な値は次のとおりです。

 * `system`

   システムの組み込み機能でユーザーに通知するよう指示します。音や視覚効果、通知など、さまざまな結果になる可能性があります。効果を変更するには、GNOME の「サウンド > 警告音」や KDE Plasma の「アクセシビリティ > システムベル」など、システムの設定を変更する必要があります。

   macOS では、システムの警告音を再生します。

 * `audio`

   カスタムの音を再生します。（macOS では 1.3.0 以降で利用可能です。）

 * `attention` *（デフォルトで有効）*

   Ghostty にフォーカスがない場合、再びフォーカスされるまでユーザーの注意を引くよう要求します。macOS では、Dock のアプリアイコンが 1 回跳ねます。Linux では、デスクトップ環境やウィンドウマネージャー、コンポジターによって動作が異なります。

   - KDE では、タスクバーのデスクトップアイコンの背景が強調表示されます。

   - GNOME では、クリックすると Ghostty ウィンドウにフォーカスが移る通知が表示される場合があります。

   - Sway では、ウィンドウに目立つ色の境界線が付く場合があります。

   - その他のシステムでは、効果がないこともあります。

 * `title` *（デフォルトで有効）*

   ターミナルが再びフォーカスされるか、キーボード入力などの操作を受けるまで、通知対象のサーフェスのタイトルの先頭にベルの絵文字（🔔）を付けます。

 * `border`

   ターミナルが再びフォーカスされるか、キーボード入力などの操作を受けるまで、通知対象のサーフェスの周囲に境界線を表示します。

   GTK では 1.2.0、macOS では 1.2.1 以降で利用可能です。

例: `audio`、`no-audio`、`system`、`no-system`

1.2.0 以降で利用可能です。

## `bell-audio-path`

ベル機能の `audio` が有効な場合、音声ファイルのパスを指定します。絶対パスでなければ、参照元の設定ファイルのディレクトリからの相対パス、CLI フラグの場合は現在の作業ディレクトリからの相対パスとして扱います。先頭に `~/` を付けると、ユーザーのホームディレクトリを参照できます。

GTK では 1.2.0、macOS では 1.3.0 以降で利用可能です。

## `bell-audio-volume`

ベル機能の `audio` が有効な場合、音声ファイルの再生音量をシステム音量に対する相対値で指定します。0.0（無音）から 1.0（最大音量）までの浮動小数点数です。デフォルトは 0.5 です。

GTK では 1.2.0、macOS では 1.3.0 以降で利用可能です。

## `app-notifications`

Ghostty が表示するアプリ内通知を制御します。

Linux（GTK）では、アプリ内通知はトーストとして表示されます。トーストはターミナルウィンドウの上に重なって表示され、重大ではなくても重要な可能性のある情報を伝えます。

指定できる通知は次のとおりです。

  - `clipboard-copy`（デフォルト: true）- テキストをクリップボードにコピーしたときに通知します。
  - `config-reload`（デフォルト: true）- 設定を再読み込みしたときに通知します。

有効にするには通知名を指定します。無効にするには、名前の前に `no-` を付けます。たとえば、`clipboard-copy` を無効にするには `no-clipboard-copy`、有効にするには `clipboard-copy` を設定します。

カンマで区切ると、複数の通知を有効または無効にできます。

「false」はすべての通知を無効にし、「true」はすべての通知を有効にします。

この設定は GTK だけに適用されます。

1.1.0 以降で利用可能です。

## `macos-non-native-fullscreen`

false 以外の場合、macOS のネイティブフルスクリーンを使わず、アニメーションと新しい操作スペースを使わずにウィンドウをフルスクリーンにします。アニメーションがないため、ネイティブのフルスクリーンより高速です。

重要: このモードではタブは動作しません。非ネイティブのフルスクリーンではタイトルバーがなくなりますが、macOS ネイティブのタブにはタイトルバーが必要です。タブを使う場合、このモードは使わないでください。

タブのあるウィンドウをフルスクリーンにすると、現在フォーカスされたタブがフルスクリーンになり、他のタブは背面の別ウィンドウに残ります。command+tilde など、通常のウィンドウ切り替えキーバインドで、そのウィンドウへ移動できます。フルスクリーンを解除すると、以前のタブ付きの状態に戻ります。

指定できる値は次のとおりです。

  * `true` - 非ネイティブの macOS フルスクリーンを使い、メニューバーを隠します。
  * `false` - ネイティブの macOS フルスクリーンを使います。
  * `visible-menu` - 非ネイティブの macOS フルスクリーンを使い、メニューバーを表示したままにします。
  * `padded-notch` - 非ネイティブの macOS フルスクリーンを使い、メニューバーを隠しますが、対応デバイスではノッチにウィンドウが隠れないようにします。現在、ノッチ周辺は透明のままですが、将来はウィンドウの背景色で塗りつぶす可能性があります。

実行時に変更できますが、次にウィンドウをフルスクリーンにしたときから適用されます。すでにフルスクリーンの場合、解除するまでは以前の設定を維持します。

## `macos-window-buttons`

macOS のタイトルバーにウィンドウボタンを表示するかどうかです。ウィンドウボタンは、ほとんどの macOS アプリの左上にある色付きのボタンで、信号機とも呼ばれます。ウィンドウを閉じる、しまう、拡大する操作ができます。

`window-decoration = none` または `macos-titlebar-style = hidden` の場合、ウィンドウボタンは常に非表示になるため、この設定は効果がありません。

有効な値は次のとおりです。

  * `visible` - ウィンドウボタンを表示します。
  * `hidden` - ウィンドウボタンを隠します。

デフォルト値は `visible` です。

実行時の変更は、新しいウィンドウだけに適用されます。

1.2.0 以降で利用可能です。

## `macos-titlebar-style`

macOS のタイトルバーのスタイルです。指定できる値は「native」、「transparent」、「tabs」、「hidden」です。

「native」は、カスタマイズしない macOS ネイティブのタイトルバーを使います。タイトルバーはウィンドウのテーマに一致します（`window-theme` を参照）。

「transparent」は「native」と同じですが、タイトルバーを透明にし、ウィンドウの背景色が透けて見えるようにします。より一体感のある外観になりますが、macOS アプリとしてはやや一般的でない見た目になり、テーマによってはうまく合わないことがあります。

「transparent」は、OSC 11 などによるウィンドウ背景色の動的な変化にもリアルタイムで追従します。見栄えをよくするため、ウィンドウの上端に接するウィンドウ、タブ、分割のターミナルの場合だけ追従します。これにより、タイトルバーの色だけが変わり、最上部のターミナルと一致しない、ちぐはぐな外観を防ぎます。

「tabs」は、タブバーを統合した完全に独自のタイトルバーです。常にターミナルの背景色に一致します。このスタイルには制約があります。macOS 13 以前では、保存したウィンドウ状態からタブが正しく復元されません。macOS 14 にはこの問題はありませんが、その他の macOS バージョンはテストしていません。

「hidden」はタイトルバーを隠します。ただし、`window-decoration = none` と異なり、ウィンドウの枠を削除したり、角を四角くしたりはしません。実行時にこのオプションへ切り替えたり、他の値へ戻したりすると、既存のウィンドウに不具合が生じる可能性があります。

「hidden」では、上部のタイトルバー領域を使ってウィンドウをドラッグできなくなります。代わりに、枠のサイズ変更可能な領域を option+click してドラッグできます。これは macOS の標準動作で、Ghostty が有効にするものではありません。

デフォルト値は「transparent」です。主観的な選択ですが、最も見栄えがよく、ほとんどの場合に適していると考えています。

実行時の変更は、新しいウィンドウだけに適用されます。

## `macos-titlebar-proxy-icon`

macOS タイトルバーのプロキシアイコンを表示するかどうかです。プロキシアイコンは、現在の作業ディレクトリのフォルダーを表すアイコンです。macOS 組み込みの Terminal.app のタイトルバーで、はっきり確認できます。

プロキシアイコンは、macOS ネイティブのタイトルバースタイルでのみ表示されます。

有効な値は次のとおりです。

  * `visible` - プロキシアイコンを表示します。
  * `hidden` - プロキシアイコンを隠します。

デフォルト値は `visible` です。

実行時に変更でき、現在開いているすべてのウィンドウに影響しますが、次に作業ディレクトリが変わってから反映されます。そのため、設定変更後に反映するには、通常、別のディレクトリへ `cd` したり、エディターで別のファイルを開いたりする必要があります。

## `macos-dock-drop-behavior`

macOS の Dock の Ghostty アイコンにファイルやフォルダーをドロップしたときの、ウィンドウの動作を制御します。

有効な値は次のとおりです。

  * `new-tab` - 現在のウィンドウに新しいタブを作成します。ウィンドウがなければ、新しいウィンドウを開きます。
  * `new-window` - 無条件に新しいウィンドウを作成します。

デフォルト値は `new-tab` です。

この設定は macOS でのみサポートされ、他のプラットフォームでは効果がありません。

## `macos-option-as-alt`

macOS には独立した「alt」キーがなく、代わりに動作が少し異なる「option」キーがあります。デフォルトでは、option キーと文字を組み合わせると、Unicode 文字が生成される場合があります。たとえば、US 標準配列では option-b は「∫」を生成します。ターミナルプログラムやシェルのキーバインドで「option」を「alt」として使いたい場合、これは望ましくないことがあります。

この設定では、option を alt として扱うように動作を変更できます。

デフォルトの動作（未設定時）は、現在のキーボードレイアウトによって決まります。以下のレイアウトの場合、デフォルト値は「true」です。それ以外は「false」です。デフォルト値が「true」のキーボードレイアウトは次のとおりです。

  - U.S. Standard
  - U.S. International

*Option* のシーケンスが印字可能な文字を生成しない場合、この設定にかかわらず *Alt* として扱われます（`alt+ctrl+a` など）。

明示的に設定できる値:

`true` の場合、*Option* キーを *Alt* として扱います。これにより、*Alt* を想定するターミナルシーケンスが正しく動作しますが、*Alt* キーによる macOS の Unicode 入力シーケンスは使えなくなります。

`false` にすると、macOS の *Alt* キーによる Unicode シーケンスを復元できますが、*Alt* を想定するターミナルシーケンスが動作しなくなります。

`left` または `right` は、それぞれ左または右の *Option* キーに対して有効にします。

## `macos-window-shadow`

macOS のウィンドウの影を有効にするかどうかです。デフォルト値は true です。ウィンドウマネージャーやウィンドウの透明度の設定によっては、false の方が見栄えがよい場合があります。

## `macos-hidden`

true の場合、Dock とアプリ切り替えの macOS アイコンを隠します。主にクイックターミナルモードを使うユーザーを想定しています。

true にすると、キーボードレイアウトの変更が自動で行われなくなる点に注意してください。

macOS アプリを Dock とアプリ切り替えから除外し、「非表示」状態にするかどうかを制御します。主にクイックターミナルモードを使うユーザーを想定していますが、どのような用途にも使える一般的な設定です。

利用可能な値:

  * `never` - macOS アプリを非表示にしません。
  * `always` - macOS アプリを常に非表示にします。

<Note>

</Note>

## `macos-auto-secure-input`

true の場合、macOS の Ghostty は、パスワードプロンプトの表示を検出すると「セキュア入力」を自動的に有効にします。

「セキュア入力」は、アプリケーションによるキーボードイベントの読み取りを防ぐ macOS のセキュリティ機能です。`Ghostty > Secure Keyboard Entry` メニュー項目を使って、いつでも手動で有効にできます。

パスワードプロンプトの自動検出はヒューリスティックに基づくため、常に期待どおり動くとは限りません。特に SSH 接続では動作せず、他にも動作しない場合があるかもしれません。

セキュア入力はすべてのアプリケーションによるキーボードイベントの読み取りを防ぐため、正当なアクセシビリティソフトウェア（またはアクセシビリティ API を使うソフトウェア）に干渉する場合は、この機能を無効にする理由になります。

## `macos-secure-input-indication`

true の場合、セキュア入力が有効なときに、Ghostty は視覚的な表示を出します。有効かどうかを把握するため、通常はこの表示を推奨します。

通常、セキュア入力はパスワードプロンプトの表示中、または手動で（通常は一時的に）有効にしたときだけ動作します。ただし、常に有効にしている場合、表示が気になることがあるため、無効にしたいかもしれません。

## `macos-applescript`

false の場合、すべての AppleScript 操作を無効にします。AppleScript コマンドや、ウィンドウ、タブ、ターミナルの AppleScript オブジェクト検索も含まれます。

デフォルトは true です。

## `macos-icon`

macOS アプリのアイコンをカスタマイズします。

Dock やアプリ切り替えなどに表示されるアイコンだけに影響します。Finder のアイコンは、署名済みアプリケーションバンドル内の固定値で制御され、実行時に変更できないため影響しません。正確な対象について詳しくは、Apple の `NSApplication.icon` のドキュメントを参照してください。アイコンの設定にはこの API を使っています。

</Warning>

その他の注意点:

  * 更新ダイアログのアイコンは、常に公式アイコンです。更新ダイアログは別のフレームワークで管理されており、多大な労力なしにはカスタマイズできないためです。

## `macos-shortcuts`

Ghostty は、ショートカットからの操作や連携を可能にする多数のアクションを公開しています。新しいターミナルの作成、ターミナルへのテキスト送信、コマンドの実行、任意のキーバインドアクションの呼び出しなどが含まれます。

強力な機能ですが、悪意のあるショートカットがインストールされ実行されると、セキュリティ上のリスクになります。そのため、この設定で無効にできます。

有効な値は次のとおりです。

* `allow` - 確認せずにショートカットによる Ghostty の操作を許可します。

* `deny` - ショートカットによる Ghostty の操作を拒否します。

1.2.0 以降で利用可能です。

## `linux-cgroup`

各サーフェス（タブ、分割、ウィンドウ）を、一時的な `systemd` スコープに入れます。

これにより、サーフェスごとのリソース管理ができます。たとえば、シェルプログラムがメモリを使いすぎた場合、OOM モニターは Ghostty プロセス全体ではなく、そのシェルだけを終了します。同様に、CPU を使いすぎた場合も、そのサーフェスだけを CPU スロットリングの対象にします。

起動時間が長くなる（100 ミリ秒程度）ため、デフォルト値は「single-instance」です。シングルインスタンスモードでは Ghostty のインスタンスが 1 つだけ動作するため（gtk-single-instance を参照）、起動時間の負担は一度だけです。また、シングルインスタンスの Ghostty は、多数のウィンドウやタブなどを持つ可能性が高く、cgroup による分離が大きな利点になります。

この機能には `systemd` が必要です。`systemd` がなければ、cgroup の初期化に失敗します。デフォルトでは、これによって Ghostty が動作しなくなることはありません（`linux-cgroup-hard-fail` を参照）。

値を変更して設定を再読み込みしても、既存のサーフェスには影響しません。

有効な値は次のとおりです。

  * `never` - cgroup を使いません。
  * `always` - 常に cgroup を使います。
  * `single-instance` - シングルインスタンスのアプリケーションとして起動した Ghostty インスタンスだけで、cgroup を有効にします（gtk-single-instance を参照）。

## `linux-cgroup-memory-limit`

個々のターミナルプロセス（タブ、分割、ウィンドウなど）のメモリ上限をバイト単位で指定します。未設定の場合、メモリ上限は設定しません。

一時的な `systemd` スコープの `MemoryHigh` を設定するものであり、ソフトリミットです。メモリの逼迫を引き起こすプロセスを終了するには、`systemd-oom` などを設定してください。

値を変更して設定を再読み込みしても、既存のサーフェスには影響しません。

詳しくは、`systemd.resource-control` のマニュアルページを参照してください。
https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html

## `linux-cgroup-processes-limit`

個々のターミナルプロセス（タブ、分割、ウィンドウなど）のプロセス数の上限です。未設定の場合、上限は設定しません。

一時的な `systemd` スコープの `TasksMax` を設定するものであり、ハードリミットです。

値を変更して設定を再読み込みしても、既存のサーフェスには影響しません。

詳しくは、`systemd.resource-control` のマニュアルページを参照してください。
https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html

## `linux-cgroup-hard-fail`

false の場合、`linux-cgroup` 用の一時的な `systemd` スコープの作成失敗を許容し、無視します。`systemd` API が失敗してもサーフェスの作成は失敗しないため、cgroup による分離を必須のリソース管理機能ではなく、あると便利なものと考える場合に役立ちます。

true の場合、一時的な `systemd` スコープの作成に失敗すると、サーフェスの作成も失敗します。

値を変更して設定を再読み込みしても、既存のサーフェスには影響しません。

## `gtk-single-instance`

`true` の場合、Ghostty GTK アプリケーションはシングルインスタンスモードで動作します。すでに動作中のプロセスがあれば、新しく起動した各 `ghostty` プロセスは新しいウィンドウを開きます。

`false` の場合、新しい ghostty プロセスはそれぞれ別のアプリケーションを起動します。

`detect` の場合、次のいずれかに該当しなければ、true（シングルインスタンス）と見なします。

1. TERM_PROGRAM 環境変数が空でない場合です。この場合、グラフィカルなターミナルセッションから Ghostty を起動しており、専用のインスタンスを望んでいると見なします。

2. CLI 引数がある場合です。この場合、独自の Ghostty 設定を渡していると見なします。シングルインスタンスモードは起動時の設定を引き継ぐため、新しい設定を読み込むにはシングルインスタンスを無効にする必要があります。

これらが誤検出になる場合は、希望する動作を明示的に設定できます。

1.2 より前の `desktop` オプションは非推奨になりました。`detect` に置き換えてください。

デフォルト値は `detect` です。

Ghostty のデバッグビルドには別のシングルインスタンス ID があるため、リリースビルドと競合せずにテストできます。

ターミナル内の太字テキストに使う色を変更します。

`background` や `foreground` と同じ形式で、特定の色を指定できます（`#RRGGBB` などですが、他の形式も利用できます。前述のドキュメントを参照してください）。色を指定すると、デフォルトの太字テキスト色には常にその色を使います。他の太字の色は `bright` に設定します。

`bright` に設定すると、太字テキストに明るいカラーパレットを使います。たとえば、赤いテキストの太字には明るい赤を使います。ターミナルのパレットは `palette` で設定しますが、アプリケーション自体も OSC 4 などのエスケープシーケンスで上書きできます。（Ghostty 1.2.0 以降、以前の `bold-is-bright` 設定は非推奨となり、この使い方に置き換わりました。）

Ghostty 1.2.0 以降で利用可能です。

## `faint-opacity`

薄いテキストの不透明度（透明度の逆）です。1 は完全に不透明、0 は完全に透明です。0 未満または 1 より大きい値は、最も近い有効な値に制限されます。

Ghostty 1.2.0 以降で利用可能です。

## `term`

`TERM` 環境変数の設定に使います。
暫定対処: vim が `xterm` 接頭辞を使ってキープロトコルなどの機能を有効にするため、この接頭辞を付けています（具体的には `modifyOtherKeys` が有効になります）。vim にはこれを変更するオプション `:set
keyprotocol=ghostty:kitty` がありますが、実装の不具合で正しく動作しません。https://github.com/vim/vim/pull/13211 で修正されます。

## `enquiry-response`

実行中のコマンドから `ENQ`（`0x05`）を受信したときに送信する文字列です。未設定の場合、デフォルトは空文字列です。

## `async-backend`

非同期 IO やイベント処理などに使う低レベル API を設定します。

ほとんどのユーザーは `auto` のままにしてください。API が使えない状況（セキュリティを強化した特定のカーネル上の `io_uring` など）を自動検出し、別の API にフォールバックします。ただし、何らかの理由で特定のバックエンドを強制したい場合は、ここで設定できます。

各種ベンチマークでは、メモリ、CPU、遅延に関して、バックエンド間に統計的に有意な差は見つかっていません。バックエンドの選択は、主に互換性と機能のためのものです。

利用可能なオプション:

  * `auto` - 利用可能な選択肢に基づき、そのプラットフォームで最適なバックエンドを自動選択します。
  * `epoll` - `epoll` API を使います。
  * `io_uring` - `io_uring` API を使います。

選択したバックエンドがプラットフォームで利用できなければ、利用可能なものを自動選択してフォールバックします。

変更を反映するには、アプリケーションの完全な再起動が必要です。

複数の選択肢があるプラットフォームは Linux だけなので、Linux でのみサポートされています。macOS では常に `kqueue` を使います。

1.2.0 以降で利用可能です。

## `auto-update`

Ghostty の自動更新機能を制御します。Linux ビルドは Ghostty が一元管理していないパッケージマネージャー経由で配布するため、現在は macOS でのみサポートされています。

更新の確認やダウンロードで、基盤となるプロトコルが必須とする標準的なネットワーク情報以外の情報を、プロジェクトに送信することはありません。言い換えると、Ghostty は更新処理に明示的な追跡機能を追加しません。最新バージョンの情報をダウンロードし、クライアント側で現在のバージョンと比較します。

有効な値は次のとおりです。

 * `off` - 自動更新を無効にします。
 * `check` - 更新を確認して、利用可能な更新があれば通知しますが、自動でダウンロードやインストールはしません。
 * `download` - 更新を確認して自動ダウンロードし、ユーザーに通知しますが、自動インストールはしません。

未設定の場合、標準のユーザーデフォルト（`defaults(1)`）に保存された設定に従う、Sparkle のデフォルト動作を使います。

実行時に変更でき、少し遅れて反映されます。

## `auto-update-channel`

自動更新に使うリリースチャンネルです。

デフォルト値は、現在動作中の Ghostty のリリースチャンネルと一致します。プレリリース版をダウンロードした場合は `tip` になり、プレリリースの更新を受け取ります。安定版をダウンロードした場合は `stable` になり、安定版の更新を受け取ります。

有効な値は次のとおりです。

 * `stable` - 「1.0.0」のような、タグ付きの安定版リリースです。
 * `tip` - main ブランチへの各コミットから生成されるプレリリース版です。非公開期間中に使われていたバージョンです。
