## 設定不要という考え方 {/* #zero-configuration-philosophy */}

Ghostty は、ほとんどのユーザーが設定なしですぐに使えるように設計されています。
適切なデフォルト値、埋め込みのデフォルトフォント（JetBrains Mono）、組み込みの Nerd Fonts などを備えています。
プロジェクトとして、Ghostty を使うために*必要な設定*をなくすことに常に取り組んでいます。

そのため、テーマのように好みが大きく分かれるもの以外で設定が必要になり、
それをデフォルトにするべきだと思った場合は、
[ディスカッションを作成](https://github.com/ghostty-org/ghostty/discussions)してください。

また、ターミナルには設定が必要だと感じるのが当たり前になっている方も、
まずは設定なしで Ghostty を試してみてください。驚くかもしれません！

## 設定形式 {/* #configuration-format */}

Ghostty の設定には、テキスト形式の設定ファイルを使います。

<Note>
  将来的には、ネイティブ UI を重視する考え方に沿って、設定用のネイティブ GUI もサポートする予定です。
  これはテキスト形式の設定に加えて提供するものです。
  現在、Ghostty を設定する方法はテキスト形式の設定のみです。
</Note>

### ファイルの場所 {/* #file-location */}

設定ファイルの名前は `config.ghostty`（1.2.3 より前は `config`）で、
次の場所から以下の順序で読み込まれます。

#### XDG 設定パス（全プラットフォーム）: {/* #xdg-configuration-path-(all-platforms): */}
- `$XDG_CONFIG_HOME/ghostty/config.ghostty`
- `$XDG_CONFIG_HOME/ghostty/config`
- **XDG_CONFIG_HOME** が未定義の場合、デフォルトは `$HOME/.config` です。

#### macOS 固有のパス（macOS のみ）: {/* #macos-specific-path-(macos-only): */}
- `$HOME/Library/Application\ Support/com.mitchellh.ghostty/config.ghostty`.
- `$HOME/Library/Application\ Support/com.mitchellh.ghostty/config`.
- macOS は、前述の XDG 設定パスもサポートしています。

両方の場所にファイルが存在する場合、上記の順に読み込まれ、
値が競合すると後のファイルが前のファイルを上書きします。
設定は任意で、設定ファイルが見つからなければ Ghostty はデフォルト値を使います。
すべての macOS 固有のファイルは、すべての XDG ファイルの*後に*読み込まれることに注意してください。

### 構文 {/* #syntax */}

Ghostty は独自の、とても単純な `key = value` 構文を使います。
以下の設定ファイルの例では、コメントで構文を説明しています。

```ini
# The syntax is "key = value". The whitespace around the
# equals doesn't matter.
background = 282c34
foreground = ffffff

# Comments start with a `#` and are only valid on their own line.
# Blank lines are ignored!

keybind = ctrl+z=close_surface
keybind = ctrl+d=new_split:right

# Empty values reset the configuration to the default value
font-family =
```

構文に関するその他の注意点は次のとおりです。

- キーは大文字と小文字を区別します。`background` と `Background` は同じではありません。
  Ghostty のキーは常に小文字です。

- 値は引用符で囲んでも囲まなくてもかまいません。`font-family = "JetBrains Mono"`
  は `font-family = JetBrains Mono` と同じです。

- すべての設定キーは、コマンドラインから Ghostty を起動するときの CLI フラグとしても使えます。
  たとえば、`background` キーは `ghostty --background=282c34` で設定できます。
  また、`font-family` キーは `ghostty --font-family="JetBrains Mono"` で設定できます。

### 複数ファイルへの分割 {/* #splitting-into-multiple-files */}

設定ファイル内の `config-file` キーを使うことで、設定を複数のファイルに分割できます。
このキーは読み込む別の設定ファイルのパスを指定し、複数回指定できます
（循環参照は検出され、警告が表示されます）。

`config-file` キーは、現在のファイルの*最後*に処理されることに注意してください。
つまり、`config-file` キーより後にあるキーでも、読み込んだファイルに同じキーが設定されていれば、それを上書きしません。

値が相対パスの場合、`config-file` キーを含む設定ファイルからの相対パスになります。

値の先頭に `?` を付けると、そのファイルは任意となり、存在しなければ無視されます。
プラットフォーム固有やマシン固有の設定ファイルに特に便利です。
（何らかの厄介な理由で、実際に `?` で始まるファイルを読み込みたい場合は、
値全体を二重引用符で囲んでエスケープできます。）

上記の要素をすべて組み合わせた例です。

```ini
config-file = some/relative/sub/config
config-file = ?optional/config
config-file = /absolute/path/config
```

## 設定の再読み込み {/* #reloading-the-configuration */}

`ctrl+shift+,`（Linux）または `cmd+shift+,`（macOS）を押すと、実行中に設定を再読み込みできます。
これらはデフォルトのキーバインドですが、`reload_config` アクションを使って独自のキーバインドも定義できます。

<Note>
設定オプションによっては、実行中に再読み込みできないものや、新しく作成したターミナルにしか適用されないものがあります。
詳しくは、各設定オプションを参照してください。
</Note>

## オフラインのリファレンスドキュメント {/* #offline-reference-documentation */}

設定オプションのドキュメントは、ウェブサイト以外にも複数の場所で確認できます。
どれも内容は同じです（すべて同じソースから生成されています）。

<Tip>
オンラインのリファレンスドキュメントは
[こちらです](/docs/config/reference)。
</Tip>

1. `$prefix/share/ghostty/docs` ディレクトリに HTML 形式と Markdown 形式のドキュメントがあります。
   このディレクトリは Ghostty のビルド時またはインストール時に作成されます。
   ソースからビルドする場合、`$prefix` は `zig-out`（または `--prefix` フラグで指定した値）です。
   macOS では、`$prefix` は `.app` バンドルの `Contents/Resources` サブディレクトリです。

2. `$prefix/share/man` ディレクトリに man ページがあります。
   このディレクトリは Ghostty のビルド時またはインストール時に作成されます。

3. CLI では、`ghostty +show-config --default --docs` を実行できます。
   デフォルト設定全体とドキュメントが標準出力に出力されるため、ページャーやエディターなどにパイプするとよいでしょう。

4. ソースコードでは、[Config 構造体](https://github.com/ghostty-org/ghostty/blob/main/src/config/Config.zig)で設定の構造を確認できます。
   使用可能なキーはそこに記載されているとおりで、指定可能な値は通常コメントに記載されています。

5. 厳密にはドキュメントではありませんが、多くの Ghostty ユーザーの
   [公開設定ファイル](https://github.com/search?q=path%3Aghostty%2Fconfig&type=code)を検索して、例やヒントを得ることもできます。

<Note>
`font-family =` のような、一見奇妙な空の設定を見かけることがあります。
これはデフォルトの動作（値なし）を指定する有効な構文です。
`+show-config` は、そのキーがデフォルトであることを明確にし、ドキュメントコメントの付与先にもするために、この形式で出力します。
</Note>
