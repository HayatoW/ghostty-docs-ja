---
title: トリガーシーケンス
description: |-
  複数のキー入力イベントの連続を必要とするトリガーです。
---

Ghostty は、アクションを実行するために連続したトリガーを必要とするキーバインドをサポートしています。
たとえば、`ctrl+a` に続けて `n` を押すことで新しいウィンドウを開くようにできます。
ほかのソフトウェアでは、「リーダーキー」「キーの組み合わせ（key chord）」「キーテーブル」などと呼ばれることがあります。

トリガーシーケンスを指定するには、
[通常のトリガー構文](/docs/config/keybind#trigger)を使用し、
シーケンス内のトリガーを `>` で区切ります。
以下に例を示します。

```ini
keybind = ctrl+a>n=new_window
```

<Warning>
 `ghostty` の CLI 引数としてシーケンスを定義する場合、
ほとんどのシェルで `>` は特殊文字なので、キーバインドを引用符で囲む必要があるでしょう。
例: ghostty --keybind='ctrl+a>n=new_window'
</Warning>

トリガーシーケンスには、次のような特別な処理があります。

  * Ghostty はシーケンス内の次のキーを無期限に待ちます。
    タイムアウトは指定できません。プレフィックスキーを強制的に出力するには、
    そのキーを明示的に出力する別のキーバインド（例: `ctrl+a>ctrl+a=text:foo`）を割り当てるか、
    未割り当てのキーを押して両方のキーをプログラムに送信する必要があります。

  * シーケンス内のプレフィックスに既存の割り当てがある場合、シーケンスがその割り当てを上書きします。
    たとえば、`ctrl+a` が `new_window` に、`ctrl+a>n` が `new_tab` に割り当てられている場合、
    `ctrl+a` を押しても何も起こりません。

  * さらに、既存のシーケンスのプレフィックスをシーケンスではない新しい割り当てに使用すると、
    既存のシーケンス全体の割り当てが解除されます。たとえば、`ctrl+a>n` と
    `ctrl+a>t` を割り当ててから `ctrl+a` を直接割り当てると、`ctrl+a>n` と
    `ctrl+a>t` の両方の割り当てが解除されます。

  * `global:` または `all:` プレフィックス付きのトリガーでは、トリガーシーケンスは使用できません。
    この制限は将来なくなる可能性があります。
