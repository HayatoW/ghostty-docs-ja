Ghostty は、[`keybind` 設定オプション](/docs/config/reference#keybind)を通じて、
柔軟なカスタムキーバインドをサポートしています。
このオプションの詳細は設定リファレンスに記載されていますが、
このページでは Ghostty でキーバインドを指定する方法の概要を説明します。

<Note>
CLI コマンド `list-keybinds` を使うと、Ghostty で利用可能なすべてのキーバインドを一覧表示できます。
デフォルトのキーバインドは、次のコマンドで確認できます。
```sh
ghostty +list-keybinds --default
```
</Note>

キーバインド設定の基本構文は次のとおりです。

```ini
keybind = trigger=action
```

## トリガー {/* #trigger */}

キーバインドの `trigger` 部分は、アクションを実行するキー入力イベントを指定します。
トリガーには、単一のキー、修飾キー付きの単一のキー、またはキーのシーケンスを指定できます。

トリガーは、1 つのキーと 0 個以上の修飾キーの組み合わせです。
たとえば、`a`、`ctrl+a`、`ctrl+shift+a`、`ctrl+alt+a` はすべて有効なトリガーです。

現在、指定できるキーの一覧は、[ソースコード](https://github.com/ghostty-org/ghostty/blob/485b6b73bf8007dee396ca515c5b45cddfc2f5d3/src/input/key.zig#L260)でのみ確認できます。
この一覧は Chromium のキーコードに由来し、USB HID コードを持つキーと密接に対応しています。

一覧にないキーについては、**Unicode コードポイントを指定することもできます**。
キーを単一の Unicode コードポイントとしてデコードできる場合、Ghostty はそれを有効なトリガーとみなし、
そのコードポイントを生成するキー入力イベントが発生するとトリガーを実行します。
これは US 配列以外のキーボードで特に便利です。

たとえば、ドイツ語キーボードでは、以下の設定で「ö」を割り当てられます。
「ö」キー（US 物理キーボードの「;」）を押すと、Unicode の「ö」が生成されるため、トリガーが実行されます。

```ini
keybind = ctrl+ö=action
```

### 修飾キー {/* #modifiers */}

有効な修飾キーは次のとおりです。

- `shift`
- `ctrl`（別名: `control`）
- `alt`（別名: `opt`、`option`）
- `super`（別名: `cmd`、`command`）

<Note>
キーボードの fn キーや「地球儀」キーは、修飾キーとしてサポートされていません。
これは、Ghostty が使う OS と GUI ツールキットの制限です。
</Note>

### トリガーのプレフィックス {/* #trigger-prefixes */}

トリガーの先頭に特別な値を付けると、キーバインドの動作を変更できます。
以下にその一覧を示します。

キーバインドのトリガーは、プレフィックスの組み合わせごとに別のものとして扱われるわけではありません。
たとえば、`ctrl+a` と `global:ctrl+a` は別々のキーバインドではありません。
後から設定したキーバインドが先の設定を上書きします。この場合は `global:` のキーバインドが使われます。

複数のプレフィックスを指定できます。たとえば、
`global:unconsumed:ctrl+a=reload_config` は、設定を再読み込みする入力を消費しないことに加えて、キーバインドをグローバルにします。

#### `all:`

キーバインドをすべてのターミナルサーフェスに適用します。
デフォルトでは、キーバインドはフォーカス中のターミナルサーフェスにだけ適用されます。
これを有効にすると、すべてのターミナルサーフェスにキーバインドが送信されます。
これはサーフェス固有のアクションにのみ適用されます。
すでにグローバルなアクション（`quit` など）には効果がありません。

#### `global:`

キーバインドをグローバルにします。デフォルトでは、キーバインドは Ghostty 内で、
適切な条件（アプリケーションにフォーカスがある、場合によってはターミナルにフォーカスがある、など）のもとでのみ動作します。
システム全体で（Ghostty にフォーカスがない場合も）動作させるには、このプレフィックスを指定します。
このプレフィックスは `all:` を含意します。すべての環境で動作するわけではないため、詳しくは以下の補足を参照してください。

この機能は macOS でのみサポートされています。macOS では、Ghostty にアクセシビリティ権限を付与する必要があります。
`global:` キーバインドを指定して Ghostty を起動または再読み込みすると、Ghostty はこの権限を要求しようとします。
権限が付与されなければ、キーバインドは動作しません。
macOS では、システム設定 → プライバシーとセキュリティ → アクセシビリティで権限を確認できます。

<Note>
`global:` プレフィックスは macOS でのみ利用できます。
</Note>

#### `unconsumed:`

入力を消費しません。デフォルトでは、キーバインドは入力を消費します。
つまり、対応するエンコード結果があっても、ターミナル内で実行中のプログラムには送信されません。
エンコードされた値をプログラムに送信するには、キーバインド全体の前に `unconsumed:` プレフィックスを指定します。例:
`unconsumed:ctrl+a=reload_config`.

`global:` および `all:` プレフィックス付きのキーバインドは、この設定にかかわらず常に入力を消費します。
特定のターミナルサーフェスに関連付けられていないため、エンコードされることはありません。

#### `performable:`

アクションを実行できる場合にだけ入力を消費します。
たとえば、`copy_to_clipboard` アクションは、コピーする選択範囲がある場合にだけ入力を消費します。
選択範囲がなければ、Ghostty はキーバインドが設定されていないかのように動作します。
`global:` または `all:` プレフィックス付きのキーバインドには効果がありません。
キーシーケンスでは、アクションを実行できなければシーケンスをリセットします（キーバインドがまったく設定されていない場合と同じ動作です）。

実行可能性を条件にするキーバインドは、アプリケーションメニューのショートカットとして表示されません。
メニューのショートカットは、ターミナルの状態にかかわらずアクションを強制的に実行するためです。
このキーバインド自体は機能しますが、メニューにショートカットのラベルが表示されなくなります。

例:

```ini
keybind = performable:ctrl+c=copy_to_clipboard
```

## アクション {/* #action */}

アクションは、トリガーが発動したときに行う処理です。
形式は `action`、パラメーターが必要な場合は `action:parameter` です。

以下は、キーバインドでよく使うアクションです。
すべてのアクションについては、[アクションの全一覧](/docs/config/keybind/reference)を参照してください。
Ghostty は数十種類のアクションをサポートしています。

| アクション | 説明 |
|--------|-------------|
| `ignore` | 何もせず、キー入力を無視します。特定の入力を破棄し、効果もエンコードも発生させないようにできます。 |
| `unbind` | 割り当てを解除します。以前のアクションが削除され、キーが表示可能な文字であれば子コマンドに送信されます。 |
| `text:text` | 文字列を送信します。Zig の文字列リテラル構文を使います。たとえば、`text:\x15` は Ctrl-U を送信します。`\x1b[` で始めれば制御シーケンスを送信できますが、代わりに便利なアクション `csi:` と `esc:` を使うことをお勧めします。 |
| `csi:text` | CSI シーケンスを送信します。たとえば、`csi:A` は「カーソルを上に移動」を送信します。 |
| `esc:text` | エスケープシーケンスを送信します。たとえば、`esc:d` は右方向の単語の末尾まで削除します。 |
