## 機能 {/* #features */}

- カーソルがプロンプトにあるターミナルでは、閉じる際の確認を表示しません。
- 新しいターミナルを、直前にフォーカスしていたターミナルの作業ディレクトリで開始します。
- プロンプト行をリフローするのではなくシェルに再描画させることで、複雑なプロンプトも正しくリサイズします。
- control（Linux）または command（macOS）を押しながらトリプルクリックすると、コマンドの出力を選択できます。
- プロンプトのカーソルが、一般的なテキスト編集に近いバー形状になります。
- `jump_to_prompt` キーバインドで、ターミナルウィンドウ内のプロンプト間を前後にスクロールできます。
- プロンプトで Alt+クリック（macOS では option+クリック）すると、クリック位置にカーソルが移動します。
- `sudo` を自動的にラップし、Ghostty の terminfo を保持できます（デフォルトでは無効です）。
- `ssh` を自動的にラップし、リモートのターミナル環境を正しく設定できます。
  詳しくは [SSH](/docs/features/ssh) を参照してください（デフォルトでは無効です）。

## シェル統合の挿入 {/* #shell-integration-injection */}

Ghostty は、`bash`、`elvish`、`fish`、`nushell`、`zsh` 向けのシェル統合コードを自動的に挿入します。

<Note>
  macOS に付属する Bash（`/bin/bash`）は、自動シェル統合に対応していません。
  以下に示すように、シェル統合スクリプトを手動で読み込む必要があります。
  Homebrew などから標準の Bash をインストールし、使用するシェルに設定することもできます。
</Note>

ほかのシェル向けのシェル統合コードは用意されていませんが、Ghostty 内で問題なく動作します。
ただし、上記のシェル統合機能の一部またはすべてが利用できない場合があります。

[Nushell](https://www.nushell.sh) は、タイトルやカーソルの処理など、多くの機能を自身で提供しています。
そのため、Ghostty との統合は `sudo`、`ssh-env`、`ssh-terminfo` など、Ghostty 固有の機能に重点を置いています。
同様に、新しい Fish（4.0 以降）はプロンプトのマークに標準で対応しているため、
`jump_to_prompt`、プロンプトのリサイズ、プロンプトの選択はシェル統合なしで動作します。

Ghostty は、実行するコマンドのベース名を単純な文字列比較で照合してシェルを検出します。
サポート対象のシェルを別の名前で使っている場合は、`shell-integration` 設定オプションでシェル統合を強制できます。

```ini
shell-integration = fish
```

自動シェル統合を無効にする場合は、次のようにします。

```ini
shell-integration = none
```

### シェル統合の確認 {/* #verify-shell-integration */}

シェル統合が動作していることを確認するには、次のログ行を探してください。

```
info(io_exec): using Ghostty resources dir from env var: /Applications/Ghostty.app/Contents/Resources
info(io_exec): shell integration automatically injected shell=termio.shell_integration.Shell.fish
```

以下のいずれかが表示される場合は、正常に動作していません。
主な原因は通常、`GHOSTTY_RESOURCES_DIR` が正しい場所を指していないことです。

```
ghostty terminfo not found, using xterm-256color
```

```
shell could not be detected, no automatic shell integration will be injected
```

### トラブルシューティング {/* #troubleshooting */}

自動シェル統合を動作させるには、macOS のアプリバンドルから Ghostty を実行するか、
Ghostty の実行元ディレクトリより上のどこかに `zig-out/share` の内容が存在する場所にインストールする必要があります。

Linux では、`zig-out` ディレクトリツリー（標準の FHS 形式のツリー）から実行するか、
`-p` で適切にインストールした場所から実行すれば、自動的に動作するはずです
（[ソースからのビルド](/docs/install/build)を参照してください）。

`GHOSTTY_RESOURCES_DIR` を手動で設定し、`zig-out/share/ghostty` の内容を指すようにすることもできます。
このディレクトリが正しい場合、`$GHOSTTY_RESOURCES_DIR/../terminfo/ghostty.terminfo` が存在するはずです。
ただし、この環境変数の手動設定が必要になるのは、ほかに問題がある兆候なので、さらに調査してください。

## シェル統合の手動設定 {/* #manual-shell-integration-setup */}

シェルの設定でシェル統合を手動で読み込むこともできます。
これにより、Ghostty 内でシェルを切り替える場合など、より多くの状況でシェル統合が動作します。

Ghostty は起動時に `GHOSTTY_RESOURCES_DIR` 環境変数を自動設定します。
これを使って、（1）シェルが Ghostty 内で起動されたことを検出し、（2）シェル統合を見つけられます。

たとえば bash では、`~/.bashrc` の*先頭*に次の内容を記述します。

```bash
# Ghostty shell integration for Bash. This should be at the top of your bashrc!
if [ -n "${GHOSTTY_RESOURCES_DIR}" ]; then
    builtin source "${GHOSTTY_RESOURCES_DIR}/shell-integration/bash/ghostty.bash"
fi
```

<Note>
  技術的には、bash シェル統合スクリプトはどこからでも読み込めますが、一部の bash 設定がシェル統合に干渉する可能性があります。
  これを避けるため、シェルの設定のできるだけ早い段階でスクリプトを読み込むことをお勧めします。
</Note>

各シェル統合のインストール手順は、それぞれのファイル内に記載されています。

| シェル     | 統合                                                                                    |
| --------- | ---------------------------------------------------------------------------------------------- |
| `bash`    | `${GHOSTTY_RESOURCES_DIR}/shell-integration/bash/ghostty.bash`                                 |
| `elvish`  | `${GHOSTTY_RESOURCES_DIR}/shell-integration/elvish/lib/ghostty-integration.elv`                |
| `fish`    | `"$GHOSTTY_RESOURCES_DIR"/shell-integration/fish/vendor_conf.d/ghostty-shell-integration.fish` |
| `nushell` | `$"($env.GHOSTTY_RESOURCES_DIR)/shell-integration/nushell/vendor/autoload/ghostty.nu"`         |
| `zsh`     | `${GHOSTTY_RESOURCES_DIR}/shell-integration/zsh/ghostty-integration`                           |

シェル固有の詳細は、<a href="https://github.com/ghostty-org/ghostty/blob/main/src/shell-integration/README.md">shell-integration/README.md</a> を参照してください。

## シェル統合を使いながらシェルを切り替える {/* #switching-shells-with-shell-integration */}

前のセクションで説明した自動シェル統合は、Ghostty の起動時に*最初に起動したシェル*に対してのみ動作します。

Ghostty 内でシェルを切り替えた場合、つまり手動で `bash` を実行したり、`nix-shell` などを使ったりすると、
そのシェルではシェル統合が*失われます*（元のシェルプロセスでは引き続き動作します）。

このような場合にシェル統合を動作させるには、前のセクションのとおり、Ghostty のシェル固有のコードを手動で読み込む必要があります。

## SSH 統合 {/* #ssh-integration */}

シェル統合の `ssh-env` と `ssh-terminfo` は、対話シェル内の `ssh` をラップし、
Ghostty の [`+ssh`](/docs/features/ssh) CLI アクションを透過的に呼び出します。
これにより、リモートのターミナル環境が設定され、`ssh` 経由のアプリケーションが正しく動作します。

対話シェルの外で `+ssh` を直接使う方法を含む詳細は、[SSH](/docs/features/ssh) を参照してください。
