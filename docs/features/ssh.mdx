`ghostty +ssh` は、`ssh` の代わりに使えるラッパーです。Ghostty 向けにリモートセッションを準備してから、
引数をそのまま転送して実際の `ssh` バイナリを実行します。
このコマンドは、リモートマシンに Ghostty の terminfo ファイルが必要になる、よくある鶏と卵の問題を解決します。

```sh
ghostty +ssh -- user@example.com
```

エイリアスとして使うと、シェル内でのすべての `ssh` 呼び出しを `+ssh` 経由にできます。

```bash
alias ssh='ghostty +ssh --'
```

または、Ghostty の[シェル統合](#shell-integration)で `ssh` を自動的にラップできます。

すべてのフラグのリファレンスは、`ghostty +ssh --help` で確認してください。

<Note>
  `+ssh` には、Ghostty 1.4.0 となる予定の Ghostty tip が必要です。
  Ghostty 1.3.x にはありません。このページで説明する SSH シェル統合機能は 1.3.x にもあります。
</Note>

## 機能 {/* #features */}

### 環境変数の転送 {/* #environment-forwarding */}

`--forward-env` フラグ（デフォルトは `true`）は、`COLORTERM`、`TERM_PROGRAM`、`TERM_PROGRAM_VERSION` の
`SendEnv` による転送を要求し、リモートシェルが Ghostty 内で動作していることを検出できるようにします。

転送した変数をリモートセッションに届けるには、リモートの `sshd` の `AcceptEnv` ディレクティブにそれらを列挙する必要があります。
以下の[リモートの `sshd` の設定](#remote-sshd-configuration)を参照してください。

`--forward-env=false` で無効にできます。

### terminfo のインストール {/* #terminfo-install */}

Ghostty は `TERM` の値に `xterm-ghostty` を使いますが、ほとんどのリモートホストにはまだ Ghostty の terminfo エントリーが付属していません。
詳しくは [Terminfo](/docs/help/terminfo#ssh) を参照してください。

`--terminfo` フラグ（デフォルトは `true`）は、初回接続時にリモートの `tic` を使って、
リモートホストに Ghostty の terminfo エントリーをインストールします。
インストールが成功した場合（またはホストがすでにキャッシュされている場合）、リモートセッションの `TERM` は `xterm-ghostty` に設定されます。

インストールに失敗した場合（リモートで `tic` が利用できない場合など）、`+ssh` は警告を記録し、
広くサポートされている `TERM=xterm-256color` にフォールバックします。
これにより、リモートでも色とほとんどのターミナル機能を維持できます。

`--terminfo=false` で無効にできます。

### インストールキャッシュ {/* #install-cache */}

成功した terminfo のインストールは、`user@hostname` をキーとしてローカルキャッシュに記録され、
同じホストへの以降の接続ではインストール手順を省略します。
キャッシュは [`+ssh-cache`](#the-+ssh-cache-cli-action) アクションで管理します。

`+ssh` に `--cache=false` を渡すと、キャッシュには手を加えず、その呼び出しに限り読み書きの両方を回避します。
「常に再インストールする」スクリプトや、問題のデバッグに便利です。

### 別の `ssh` 実行ファイル {/* #alternate-ssh-executable */}

デフォルトでは、`+ssh` は `PATH` 内で最初に見つかった `ssh` を実行します。
`--ssh=PATH` フラグで、代わりに特定のクライアントを指定できます。

```sh
ghostty +ssh --ssh=/opt/homebrew/bin/ssh -- user@example.com
```

別の OpenSSH ビルドやラッパークライアントを `+ssh` で使いたい場合に便利です。
パスは実行ファイルを指す必要があります。そうでない場合、`+ssh` は `PATH` の `ssh` に黙ってフォールバックせず、失敗します。

## `+ssh-cache` CLI アクション {/* #the-+ssh-cache-cli-action */}

`ghostty +ssh-cache` は、`+ssh` が使う terminfo キャッシュを管理します。

```sh
# List every cached destination.
ghostty +ssh-cache

# Show a specific destination, or every cached user on a host.
ghostty +ssh-cache user@example.com
ghostty +ssh-cache example.com

# Manually mark a destination as cached (e.g. after installing
# terminfo by hand).
ghostty +ssh-cache --add=user@example.com

# Force the next connection to reinstall terminfo on a destination.
ghostty +ssh-cache --remove=user@example.com

# Remove cache entries older than a given age (s, m, h, d, w, y).
ghostty +ssh-cache --prune=30d

# Clear the entire cache.
ghostty +ssh-cache --clear
```

接続先は位置引数で検索します。`user@hostname` は完全に一致するエントリーを、
`hostname` のみならそのホストのキャッシュ済みユーザーすべてを表示します。
一致するものがなければ、ゼロ以外のステータスで終了します。

特定の接続先で再インストールを強制するには、`--remove` をお勧めします。
キャッシュエントリーを削除すると、次の接続成功時に再登録されます。
キャッシュを完全に回避するには、`+ssh --cache=false` を使ってください。

キャッシュエントリーのキーは常に `user@hostname` です。`user` は ssh ユーザー（デフォルトはローカルの `$USER`）、
`hostname` は `~/.ssh/config` のエイリアスではなく、解決後のリモートホスト（`HostName` と `ProxyJump` の適用後）です。

すべてのフラグのリファレンスは、`ghostty +ssh-cache --help` で確認してください。

## シェル統合 {/* #shell-integration */}

Ghostty の[シェル統合](/docs/features/shell-integration)は、対話シェル内の `ssh` をラップし、
`ghostty +ssh` を透過的に呼び出せます。デフォルトでは無効ですが、
[`shell-integration-features`](/docs/config/reference#shell-integration-features) で有効にできます。

```ini
shell-integration-features = ssh-env,ssh-terminfo
```

- **`ssh-env`** は環境変数の転送を有効にします（`+ssh` に `--forward-env=true` を渡します）。
- **`ssh-terminfo`** はリモートへの terminfo のインストールを有効にします（`+ssh` に `--terminfo=true` を渡します）。

ラッパーは `ssh` という名前の小さなシェル関数で、これらの機能フラグを適切な `+ssh` コマンドラインオプションに変換し、引数を転送します。

### 制限事項 {/* #limitations */}

ラッパーはシェル関数なので、**子プロセスには継承されません**。
次の場合は、ラッパーが*使われません*。

- **`./script.sh` または `sh script.sh` で実行するスクリプト。** 各スクリプトは、関数を継承しない新しい非対話シェルで実行されます。
  代わりに、現在のシェルでスクリプトを読み込み（`source script.sh` や `. script.sh` など）、関数が定義されている同じシェルプロセスで実行してください。
- **自ら `ssh` を起動するラッパーツール。** `aws ec2-instance-connect ssh`、`gcloud compute ssh`、`mosh`、
  `rsync -e ssh`、`ssh` 経由の `git`、`scp`、`sftp` などです。
  これらは `ssh`（または同等のバイナリ）を直接呼び出し、シェルの関数テーブルは参照しません。
- **より一般的な非対話シェルやサブシェル。** `Makefile` のレシピ、`cron` ジョブ、ほかのプログラム内のコマンド置換などを含みます。

これらの場合は、`ghostty +ssh` を直接呼び出すか、以下のように `~/.ssh/config` を設定してください。

## `~/.ssh/config` の手動設定 {/* #manual-~.sshconfig-configuration */}

シェルラッパーで対応できない場合は、`~/.ssh/config` で `SetEnv` と `SendEnv` を直接設定できます。
これは起動方法にかかわらず、すべての `ssh` 呼び出しに適用されます。

```ssh-config
# ~/.ssh/config
Host example.com
  SetEnv TERM=xterm-256color
  SendEnv COLORTERM TERM_PROGRAM TERM_PROGRAM_VERSION
```

<Note>
  `SetEnv` には OpenSSH 8.7 以降が必要です。
  Ghostty の terminfo エントリーをリモートホストに手動でコピーする方法は、[Terminfo](/docs/help/terminfo#ssh) を参照してください。
</Note>

<Note>
  リモートホストに `xterm-ghostty` の terminfo エントリーがすでにある場合、
  `SetEnv TERM=xterm-256color` の記述は不要な `TERM` のダウングレードになります。
  terminfo エントリーのないホストでのみ使ってください。
</Note>

## リモートの `sshd` の設定 {/* #remote-sshd-configuration */}

環境変数の転送は `SendEnv` を使いますが、これは*要求*にすぎません。
リモートの `sshd` は、`AcceptEnv` ディレクティブにない変数を通知せずに破棄します。
`COLORTERM`、`TERM_PROGRAM`、`TERM_PROGRAM_VERSION` をリモートセッションに届けるには、
リモートの `sshd_config` に次のような設定が必要です。

```sshd-config
# /etc/ssh/sshd_config on the remote host
AcceptEnv COLORTERM TERM_PROGRAM TERM_PROGRAM_VERSION
```

これは Ghostty ではなくリモートホスト側の設定であり、管理対象やセキュリティを強化したサーバーの多くでは設定されていません。
`TERM` 自体は `ssh` によって常に転送され、`AcceptEnv` の影響を受けません。
