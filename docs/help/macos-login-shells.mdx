Ghostty は macOS の慣習を尊重し、各シェルをログインシェルとして起動します。
これは macOS 上のほかのターミナルエミュレーター、とりわけデフォルトの Terminal.app の動作と一致します。
ただし、この動作はほかの Unix システムとは異なるため、
それらのシステムの動作に慣れたユーザーは混乱するかもしれません。

## なぜログインシェルなのか {/* #why-login-shells */}

従来、Unix シェルには、ユーザーがシェルを操作できるようになる前に実行されることを想定した、
主なファイルが 2 つあります。プロファイルファイルと rc ファイルです。
プロファイルファイルは通常、ログイン時に 1 度実行され、ユーザーの環境を設定するために使われます。
rc ファイルは新しいシェルが作られるたびに実行され、シェル自体を設定するために使われます。

zsh（macOS 10.15 以降のデフォルトシェル）を例に説明します。
zsh は `.zprofile` と `.zshrc` ファイルを使用します。
多くの Linux システムでは、ユーザーがデスクトップマネージャーなどを通じて最初にログインしたときに、
`.zprofile`（または同様のファイル）が実行されます。
これにより、後続のシェルは `.zprofile` で設定された環境や各種設定を継承できます。
負荷の高い初期化はログイン時に 1 度だけ実行すればよく、
後続のシェルは設定処理の結果をすべて再利用できる、という考え方です。

<Note>
例として Zsh を使っていますが、bash を除けば、ほぼどのシェルでも同じ動作になります。
Bash が `.bashrc` を読むのは、シェルが対話型かつ非ログインの場合**だけ**です。
macOS は OSX 10.2 Jaguar で tcsh から bash に移行しましたが、この bash の違いは見落とされていた可能性があります。
その結果、`.bashrc` がほとんど実行されず、特に新しいターミナルの起動では実行されないため、
開発者はシェルの設定をすべて `.profile` に置くようになったのかもしれません。
現在は zsh が新たなデフォルトとなり、対話型の非ログインシェルを起動すると `.zprofile` と `.zshrc` の両方が呼び出されます。
</Note>

macOS では、システムにログインするための GUI が、システム全体のグローバル設定を読み込む独自の方法を持つため、
`.zprofile` を実行しない点が異なります。
これは、どのターミナルエミュレーターもシェルをログインシェルとして実行する必要があることを意味します。
そうしないと、新しいシェルで `.zprofile` の設定処理が欠けてしまい、正常に動作しない可能性があります。
残念な現実ですが、`.zprofile` が一度も実行されず、
ユーザーのターミナルに初期設定を渡したりグローバル環境変数などを設定したりできる
`.xsession` のようなものも存在しないことを考えると、理にかなっています[^1]。

ただし、これはすべてを `.zprofile` に入れるべきだとか、2 つのファイルが常に一緒に呼び出されるという意味では*ありません*。
zsh はログインモードかつ対話モードで起動されるため、新しいターミナルを作るたびに `.zprofile` と `.zshrc` の両方が実行されます。
しかし、ターミナルエミュレーターの中でシェルを実行すると、それは単なる対話型シェルとなり、
`.zprofile` で初期化された親シェルの設定にアクセスできなくなります。
これは、`.zprofile` にエイリアスを置き、ターミナルのインスタンスを起動してそのエイリアスを実行し、
次に `zsh` を実行することで確認できます。エイリアスが使えなくなっていることが分かるはずです。

したがって、ターミナル内かどうかにかかわらず、どのシェルも正しく初期化されるよう、
シェルの設定の大部分は引き続き `.zshrc` ファイルに置くべきです。
これは、ほかの Linux システムでの dotfiles の書き方とも、ある程度一致しています。
