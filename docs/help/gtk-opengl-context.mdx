title: GTK の OpenGL コンテキストエラー
description: |-
  状況によっては、「OpenGL コンテキストを取得できない」というエラーで
  Ghostty が起動しないことがあります。このページでは、
  このエラーの詳細と解決方法を説明します。
---

Ghostty の GTK アプリケーションは、レンダリングに OpenGL を使用します。
OpenGL でレンダリングするには、まず GTK から「OpenGL コンテキスト」を取得する必要があります。
これにより、OpenGL コマンドを実行するための名前空間を得られます。

まれに、GTK が Ghostty に OpenGL コンテキストを提供できないことがあります。
この場合、Ghostty は何も描画できないため、このエラーを表示する必要があります。

これは**必ず環境の問題です**。Ghostty に OpenGL コンテキストを提供するのは GTK であり、
通常、Ghostty 自体がこの問題を直接解決するためにできることはありません。
多くの場合、ライブラリ、ドライバー、OS パッケージのバージョンに関する問題です。
このページでは、問題を突き止めるための手がかりを紹介します。

## 手早く試せる対処法 {/* #quick-fixes */}

Ghostty をすぐに動かしたい場合は、次を試してください。

1. **[バイナリパッケージ](/docs/install/binary)をインストールします。** ソースからビルドしている場合は、
   代わりにバイナリパッケージを使ってみてください。バイナリパッケージは、特定のディストリビューションと
   そのライブラリで動作する、より管理された環境でビルドされている傾向があります。

2. **GPU ドライバーを確認します。** GPU ドライバーは、OpenGL の問題のよくある原因です。
   特にプロプライエタリドライバーを使用している場合は、GPU ドライバーの更新またはダウングレードを試してください。

3. **システムパッケージだけを使って Ghostty をソースからビルドします。** Nix 開発環境を使って
   Ghostty をビルドしている場合は、システムパッケージだけを使ってソースからビルドしてみてください。
   その手順は、[ソースからのビルド](/docs/install/build)を参照してください
   （ただし「Nix を使ったビルド」の節は無視してください）。

<Important>
  この節では、問題の根本原因を理解するための詳細を意図的に省いています。
  根本原因をより深く理解したい場合は、この節より下をお読みください。
</Important>

## ライブラリのバージョンの不一致 {/* #mismatched-library-versions */}

このエラーのよくある原因は、ライブラリのバージョンの不一致です。
GTK、[Mesa](https://mesa3d.org/)、libX11/libwayland、カーネルの間のバランスは繊細です。

**このエラーの最も一般的な原因は、Nix 開発環境を使って Ghostty をビルドすることです。**
開発にはこの環境を推奨していますが、これらのライブラリのさまざまなバージョンが固定されるため、
システム全体の環境と互換性がない場合があります。
**解決方法：システムの依存パッケージだけを使って Ghostty をビルドするか、システムパッケージから Ghostty 自体を導入してみてください。**
その手順は、[ソースからのビルド](/docs/install/build)に従ってください
（ただし「Nix を使ったビルド」の節は無視してください）。

**もう 1 つのよくある原因は、システムパッケージが古いことです。**
Linux ディストリビューションは通常、この繊細なバランスを管理しているため、
システム全体を（少なくとも、具体的には上記のパッケージを）更新してみてください。
これにより、Ghostty が動作する整合性のある状態にシステムが戻ることがよくあります。

**GPU ドライバーを確認してください。** GPU ドライバーの更新またはダウングレードを試してください。
GPU ドライバーの変更で GTK の OpenGL が動作しなくなった事例は数多くあります。

## 過去に確認された原因 {/* #known-historical-causes */}

- [Mesa 25.2.0 のリグレッション](https://gitlab.freedesktop.org/mesa/mesa/-/issues/13719)。
  Ghostty は libwayland クライアントライブラリを同梱していませんが、Nix 開発環境でソースからビルドすると、
  システムのものとは異なる libwayland クライアントライブラリを使用します。

- [GTK4 + Nvidia + X11](https://gitlab.gnome.org/GNOME/gtk/-/issues/4950)。
  発生に必要な正確な組み合わせは分かりませんが、特定の状況では、GTK4（Ghostty に必須）、
  Nvidia、X11 の組み合わせがこの問題を引き起こすようです。
  ドライバーのバージョンを変更するか、Wayland に切り替えることで解決する場合があります。
