title: Terminfo
description: |-
  Terminfo は、ターミナルの機能をソフトウェアに伝えるために使われます。
  Ghostty は、その機能を知らせるための独自の terminfo エントリーを同梱しています。
---

[Terminfo](https://en.wikipedia.org/wiki/Terminfo) は古くからある形式で、
現在も多くのターミナルアプリケーションが、ターミナルの機能を判定するために使用しています。
Ghostty は、その機能を知らせるための独自の terminfo エントリーを同梱しています。

Ghostty は、`TERM` の値に `xterm-ghostty` を使用します。

<Note>
  **なぜ `xterm` という接頭辞が付くのでしょうか？** 残念ながら、多くのターミナルアプリケーションは、
  `TERM` の値に「xterm」という文字列が含まれるかを調べて、*機能を推測*します。
  非公開ベータでは、単に `ghostty` という値を試しましたが、あまりにも多くのアプリケーションが動作しなくなり、
  エコシステム全体を修正するのは現実的ではないことが分かりました。
  互換性を維持するため、`xterm-ghostty` に落ち着きました。
</Note>

Ghostty のパッケージには terminfo エントリーが含まれており、
システムで利用できるように適切なファイルシステム構成や環境変数を設定します。
Ghostty を実行すると、terminfo エントリーが利用可能であることを検出した場合に、
環境変数 `TERM` を自動的に `xterm-ghostty` に設定します。

<Important>
  **Ghostty の terminfo エントリーは、ncurses 6.5-20241228 以降で利用できます。**
  ディストリビューションで ncurses パッケージの更新が進むにつれて、
  Ghostty の terminfo エントリーはデフォルトでシステム全体から利用できるようになります。
  普及には時間がかかります。
</Important>

## Sudo {/* #sudo */}

`sudo` を使用すると、sudo が環境変数をリセットすることがあり、
一部のプログラムを実行した際に `missing or unsuitable terminal: xterm-ghostty` や `'xterm-ghostty': unknown terminal type.` というエラーが表示される場合があります。

解決するには、環境変数 `TERMINFO` を保持するよう sudo を設定するか、
`sudo` 機能を有効にしたシェル統合を使用してください。
シェル統合を使うと、Ghostty が sudo にエイリアスを設定して、自動的にこの処理を行います。
このシェル統合機能を有効にするには、設定に
`shell-integration-features = sudo` を指定します。

この設定オプションの詳細は、
[`shell-integration-features`](/docs/config/reference#shell-integration-features)
を参照してください。

## SSH {/* #ssh */}

Ghostty の terminfo エントリーがないマシンに SSH で接続すると、
`missing or unsuitable
terminal: xterm-ghostty`、`Error opening terminal: xterm-ghostty.`、
`WARNING: terminal is not fully functional` などのエラーメッセージが表示されます。

いずれ Ghostty の terminfo エントリーがどこでもあらかじめ配布されるようになることを願っていますが、
それまでの間は、次の 2 つの方法で対処できます。

### 方法 1：Ghostty の terminfo エントリーをリモートマシンにコピーする {/* #method-1:-copy-ghostty's-terminfo-entry-to-the-remote-machine */}
1. ローカルマシンで、次の 1 行のコマンドを実行します。
   ```sh
   infocmp -x xterm-ghostty | ssh YOUR-SERVER -- tic -x -
   ```
2. サーバー上で、設定が
   `/usr/share/terminfo/...` に保存されたことを確認します。
   保存されていない場合は、`$HOME/.terminfo/...` を確認し、そこから移動してください。

サーバー上の `tic` コマンドが `"<stdin>", line 2, col 31, terminal 
'xterm-ghostty': older tic versions may treat the description
field as an alias` という警告を出すことがありますが、安全に無視できます。

`tic` は通常、結果をシステムデータベースの `/usr/share/terminfo` に配置します。
この場所は、環境変数 `TERMINFO` で上書きできます。
`TERMINFO` が設定されておらず、`tic` がシステムの場所に書き込めない場合、
`$HOME/.terminfo` が存在すれば、そこに結果を配置します。
この場合の詳細は、`man tic` を参照してください。

<Note>
  **Sonoma より前の macOS では、システム同梱の `infocmp` は使用できません。**
  同梱の `ncurses` のバージョンが古すぎて、新しい `tic` が読める terminfo エントリーを出力できず、
  大量の `Illegal character` メッセージを表示してコマンドが失敗します。
  Homebrew で `brew install ncurses` を実行して新しい `ncurses` をインストールし、
  上記の `infocmp` を完全なパスである `/opt/homebrew/opt/ncurses/bin/infocmp` または
  `/usr/local/opt/ncurses/bin/infocmp` に置き換えることで解決できます。
</Note>


### 方法 2：既知の terminfo エントリーにフォールバックするよう SSH を設定する {/* #method-2:-configure-ssh-to-fall-back-to-a-known-terminfo-entry */}
1. ローカルマシンで、次の SSH 設定を追加します
   （**[OpenSSH 8.7](https://www.openssh.com/txt/release-8.7)
   以降が必要です**）。
   ```ssh-config
   # .ssh/config
   Host example.com
     SetEnv TERM=xterm-256color
   ```

Ghostty は、どちらの方法も自動化できます。
`ghostty +ssh` CLI アクションと、`ssh-env` /
`ssh-terminfo` シェル統合機能の詳細については、[SSH](/docs/features/ssh) を参照してください。
自動化が適用される条件に関する重要な制限事項も記載しています。

<Warning>
  **フォールバックでは、高度なターミナル機能はサポートされません。**
  `xterm-256color` は Ghostty のすべての機能を含んでいないため、
  色付きの下線や装飾付きの下線など、xterm の範囲を超えるターミナル機能は動作しません。
</Warning>
