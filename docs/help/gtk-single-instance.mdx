---
title: GTK シングルインスタンスモード
description: |-
  GTK シングルインスタンスモードは、アプリケーションのインスタンスが
  同時に 1 つだけ実行されることを保証する機能です。
---

Ghostty は、CLI 環境から起動されていないと検出した場合、
デフォルトで GTK シングルインスタンスモードを使用します。

GTK シングルインスタンスモードは GTK プロジェクトが推奨しており、
公式の Gnome アプリケーションに期待される標準的な動作です。
Ghostty の 2 つ目のインスタンスが起動されると、元のインスタンスが新しいウィンドウを作成し、
フォーカスを取得して、2 つ目のインスタンスを終了させます。

<Tip>
  Linux で Ghostty を使用していて、起動に時間がかかったりメモリ使用量が多かったりする場合、
  環境によっては GTK シングルインスタンスの検出が機能しておらず、強制的に有効にする必要があるかもしれません。
  詳細はこのページを読み進めてください。
</Tip>

## CLI 環境の検出 {/* #cli-environment-detection */}

Ghostty のデフォルトの動作は、**CLI 環境から起動されていない場合に**
GTK シングルインスタンスモードを使用することです。

この動作を採用しているのは、CLI からターミナルを使うことが一般的であり
（たとえば `ghostty -e "some command"`）、その場合は新しいプロセスを起動し、
終了するまでブロックすることが期待されるためです。
シングルインスタンスモードではこれを簡単に実現できないため、
CLI 以外の環境から起動された場合にのみ有効にしたいと考えています。

アプリケーションが CLI 以外の環境から起動されたかを検出する標準 API はないため、
Ghostty は次のヒューリスティックを使用します。

1. 環境変数 `TERM_PROGRAM` に空でない値が設定されている場合は、
   グラフィカルなターミナルエミュレーター内にいるとみなし、GTK シングルインスタンスモードを無効にします。

2. Ghostty にコマンドライン引数が渡されている場合は、インスタンス固有の設定が必要だとみなし、
   GTK シングルインスタンスモードを無効にします。

## GTK シングルインスタンスモードを強制的に有効または無効にする {/* #forcing-gtk-single-instance-mode-on-or-off */}

[`gtk-single-instance`](/docs/config/reference#gtk-single-instance) オプションを設定すると、
GTK シングルインスタンスモードを強制的に有効または無効にできます。

```ini
gtk-single-instance = true
```

値を `true` にすると、Ghostty は強制的にシングルインスタンスモードで実行されます。
このモードでは、すでに Ghostty のインスタンスが実行されている場合、
新しい `ghostty` プロセスを起動するたびに、既存のインスタンスに新しいウィンドウが作成されます。

## 起動パフォーマンスとメモリとの関係 {/* #relationship-to-startup-performance-and-memory */}

Ghostty は GTK アプリケーションです。GTK フレームワークには、
起動にかかる時間とメモリ使用量の両面で、避けられないオーバーヘッドがあります。
Ghostty 側でこれをどうにかすることはできません。

GTK シングルインスタンスモードでは、Ghostty の後続のインスタンスでこのオーバーヘッドを回避できます。
既存のインスタンスに新しいウィンドウを作るだけなので、2 つ目のインスタンスの起動は非常に高速で、
メモリもほとんど使用しません。
