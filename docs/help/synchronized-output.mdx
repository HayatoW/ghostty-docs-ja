---
title: 同期出力
description: |-
  表示画面の広い範囲を更新するコマンドラインプログラムは、
  同期出力が有効でない場合、Ghostty のような高速なターミナルで
  画面のティアリングが発生することがあります。
---

一部のシステムでは、表示画面の広い範囲を頻繁に更新するコマンドラインプログラムを Ghostty で使用すると、
ほかのターミナルエミュレーターでは発生しない、繰り返すちらつきや激しい画面のティアリングが生じることがあります。
**これは通常、Ghostty のバグではなく、プログラム自体のバグです。**

多くの場合、その理由は Ghostty のレンダリングが**速すぎる**ことであり、
画面を再描画するプログラムによるセルの更新がレンダラーに追いつかないため、ティアリングが起こります。

パフォーマンスを犠牲にせずに Ghostty 側でできることはほとんどありません。
そのため、影響を受けるプログラムのユーザーには、その開発者が根本的な問題の修正方法を理解できるよう、
このページの[「開発者向け」](#for-developers)の節へのリンクを添えて、
上流の開発者に問題を報告することを**強くお勧めします**。

影響が確認されているプログラムには、次のものがあります。

- Claude Code ([#8176], [#8285])
- Docker CLI ([#5493], [#5657], [#8162])
- Ollama ([#4048])
- Grok ([#9618])

## 開発者向け {/* #for-developers */}

この問題が発生する CLI または TUI ベースのアプリの開発者は、[同期出力][Synchronized Output]プロトコルを実装する必要があります。
このプロトコルは、画面が完全に更新され、次のフレームを安全にレンダリングできるタイミングを
Ghostty（およびほかの最新の高性能ターミナルエミュレーター）に伝えます。

ただし、ベストプラクティスとして、**本当に更新が必要なセルだけを更新する**ことも推奨します。
新しいセルを更新する前に、行全体やアクティブな画面全体を消去することは避けてください。
代わりに、[カーソル位置 (CUP)][Cursor Position (CUP)]を使ってカーソルを更新する部分に戻し、
セルを更新した後、[行内消去 (EL)][Erase in Line (EL)]を使って行の残りを消去できます。
これにより、同期出力プロトコルをサポートしていないターミナルでの画面のティアリングを軽減できるだけでなく、
不要な更新とターミナルに送信するデータ量を減らすことで、パフォーマンスを大幅に向上させることもできます。
