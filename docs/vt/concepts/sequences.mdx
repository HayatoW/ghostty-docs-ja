---
title: 制御シーケンス
description: |-
  制御シーケンスは、プログラムがターミナルとやり取りするための手段です。
---

制御シーケンスは、カーソルの移動、テキストの色の変更、画面の消去などに使用します。プログラムがターミナルとやり取りする主な手段です。

ターミナル内で動作するプログラムがターミナルと通信する手段は、接続されたファイル記述子（通常は疑似端末、略して「pty」）にバイトを書き込むことだけです。表示するテキストと実行するコマンドを区別するため、ターミナルは**制御シーケンス**と総称される特別な構文を使用します。

制御シーケンスの種類ごとに、形式と目的が異なります。以下では、それぞれの構文とともに説明します。[リファレンス](/docs/vt/reference)には、サポートされている制御シーケンスの完全な一覧が種類別に掲載されています。

## C0 制御文字 {/* #c0-control-characters */}

各制御シーケンスは、**制御文字**と呼ばれる、表示されない特別な文字で始まります。最も単純な制御文字は **C0 制御文字**と呼ばれ、ASCII エンコーディングで `0x00` から `0x20` の間にあり、それ自体以外のパラメーターを取りません。

制御文字の数はごくわずかですが、1 バイトの値がターミナルの状態に影響するため、理解しておくことが重要です。

ターミナルエミュレーションで意味を持つ C0 文字には、次のものがあります。

| C0     | 略称    | 正式名称       | 機能                                    |
|--------|---------|-----------------|---------------------------------------------|
| `0x07` | [`BEL`] | ベル            | ユーザーの注意を引きます。            |
| `0x08` | [`BS`]  | バックスペース       | カーソルを 1 つ前の位置に移動します。      |
| `0x09` | [`TAB`] | タブ             | カーソルを右側の次のタブストップに移動します。 |
| `0x0A` | [`LF`]  | 改行        | カーソルを 1 行下に移動します。              |
| `0x0D` | [`CR`]  | 復帰 | カーソルを左端の列に移動します。     |

[`BEL`]: /docs/vt/control/bel
[`BS`]: /docs/vt/control/bs
[`TAB`]: /docs/vt/control/tab
[`LF`]: /docs/vt/control/lf
[`CR`]: /docs/vt/control/cr

## エスケープシーケンス {/* #escape-sequences */}

C0 文字の 1 つである Escape（`0x1b`、`ESC`）は特別です。いくつかの独立したシーケンスの開始にも、シーケンスの系列全体の開始にも使用できます。このため、制御シーケンスは、一部で全体を表す *pars pro toto* として、一般に**エスケープシーケンス**とも呼ばれます。

Escape で始まるすべてのシーケンスが、ここで定義するエスケープシーケンスであるとは限りません（[C1 シーケンス](#c1-sequences)である場合の方が多くあります）。ただし、`ESC D` のような真のエスケープシーケンスは、次の形式です。

```
esc_sequence = "0x1B" intermediates final
intermediates = [0x20-0x2F]*
final = [0x30-0x7E]
```

## `Fe` シーケンス {/* #fe-sequences */}

Escape の後に特定の表示可能文字が続く場合、さまざまな歴史的理由から、両者をまとめて **C1 制御文字**として解釈します。その一部は、`Fe` シーケンスと総称される多くのシーケンス系列を担います。これらの文字は単一の 8 ビット文字でも表現できますが、現代のターミナルで通常使用される UTF-8 やその他の上位バイトを使用するエンコーディングとの競合を避けるため、今でも**ほとんどの場合**、Escape 文字を使ってエンコードされます。

| ESC コード | C1     | 略称 | 正式名称                   | 機能                                                                                                 |
|----------|--------|------|-----------------------------|----------------------------------------------------------------------------------------------------------|
| `ESC [`  | `0x9b` | CSI  | 制御シーケンス導入子 | 圧倒的に最も一般的です。整数を使ってカーソル、画面、モード、セル、およびそのスタイルを制御します。 |
| `ESC ]`  | `0x9d` | OSC  | オペレーティングシステムコマンド    | 現代のターミナル拡張で、文字列データの送信によく使用されます。                                        |
| `ESC P`  | `0x90` | DCS  | デバイス制御シーケンス     | 主にターミナルの機能を問い合わせる際（XTGETTCAP）に使用されます。それ以外での使用はまれです。                   |
| `ESC _`  | `0x9f` | APC  | アプリケーションプログラムコマンド | 任意のペイロードを必要とする Kitty Graphics Protocol のような、非常に複雑なプロトコルで使用されます。         |
| `ESC X`  | `0x98` | SOS  | 文字列開始             | 廃止されています。Ghostty は無視します。                                                                            |
| `ESC ^`  | `0x9e` | PM   | プライベートメッセージ             | 廃止されています。Ghostty は無視します。                                                                            |

### CSI {/* #csi */}

CSI シーケンスは、C1 シーケンスの中で*圧倒的に*最も一般的な種類です。コロン（`:`）またはセミコロン（`;`）で区切られた整数パラメーターを使って、カーソルの移動、ターミナルのモード設定、上下のスクロール、セルや行の挿入と削除、セルのスタイル変更などを行います。

主な制限は、整数値**しか**エンコードできないことです。文字列データをエンコードするには、OSC や DCS などの別の種類のシーケンスが必要です。

CSI シーケンスは次の形式に従います。CSI シーケンスの例は `ESC [ 1 ; 2 m` です。

```
csi_sequence = "0x1B" "[" params intermediates final
params = param | param sep params
param = [0-9]
sep = ";" | ":"
intermediates = [0x20-0x2F]*
final = [0x40-0x7E]
```

### OSC {/* #osc */}

OSC シーケンスは通常、ターミナルとアプリケーションの間で送信する文字列や、その他の整数以外のデータをエンコードするために使用します。一般に、タイトル、パレット、クリップボードなど、ターミナルエミュレーター自体に関する変数を変更したり、ハイパーリンク、進捗報告、現在の作業ディレクトリなどの追加機能について指示したりします。

この柔軟性により、OSC シーケンスは現代の拡張で非常によく使用され、古いターミナルでは単に無視できる形で新しい機能を提供します。

OSC シーケンスは OSC（`ESC ]` または `0x9d`）で始まります。続いて、慣例として、操作を識別する整数を追加します。

OSC シーケンスの形式を以下に示します。慣例として、OSC シーケンスは整数の識別子と、それに続くセミコロン（`;`）で識別しますが、規格ではこれは必須ではありません。廃止された一部の OSC シーケンスはセミコロンの前に数値以外の識別子を使用しますが、Ghostty はこれらをサポートしません。

> [!NOTE]
> さらに複雑な歴史的理由により、xterm（およびそれに倣う Ghostty）の OSC シーケンスは、標準の文字列終端子（`ST`、`ESC \` または `0x9c`）の代わりに、ベル文字（`BEL`、`0x07`）で終端することもできます。
>
> ほとんどの場合はどちらも使用できますが、Ghostty は古いプログラムやターミナルとの互換性を最大限に確保するため、応答時に OSC シーケンスで使われた終端子をそのまま返すようにします。新しいコードでは、規格への準拠のため、常に `ST` を優先してください。

これらが OSC シーケンスの終端に使われます。OSC シーケンスの例は `OSC 2 ; 👻  Ghostty 👻  ST` です（`ST` は文字列終端子です）。

```
osc_sequence = "0x1B" "]" data terminator
data = [0x20-0xFF]
terminator = "0x1B" "0x5C"
```

### DCS {/* #dcs */}

DCS シーケンスは、CSI シーケンスと OSC シーケンスを組み合わせたようなもので、整数パラメーターと文字列値の両方を標準でサポートします。DSC シーケンスの例は `DCS + P q <string> ST` です。

```
dsc_sequence = "0x1B" "P" params intermediates final data ST
params = param | param ";" params
param = [0-9]
intermediates = [0x20-0x2F]*
final = [0x40-0x7E]
data = [0x20-0xFF]
ST = "0x1B" "0x5C"
```

### APC {/* #apc */}

Ghostty は APC シーケンスをサポートしています。現在サポートしている APC シーケンスは、Kitty Graphics Protocol シーケンスの 1 つだけです。これについては[こちら](https://sw.kovidgoyal.net/kitty/graphics-protocol/)に記載されています。

```
apc_sequence = "0x1B" "_" data ST
data = [0x20-0xFF]
ST = "0x1B" "0x5C"
```

### SOS と PM {/* #sos-and-pm */}

Ghostty は SOS シーケンスと PM シーケンスを完全に無視します。

```
sos_sequence = "0x1B" "X" data ST
pm_sequence = "0x1B" "^" data ST
data = [0x20-0xFF]
ST = "0x1B" "0x5C"
```
