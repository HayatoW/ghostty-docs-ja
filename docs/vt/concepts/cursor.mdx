---
title: カーソル
description: |-
  カーソルは、次の文字が表示される、または位置に依存する制御シーケンスが実行される行と列です。
---

カーソルはターミナルに常に存在し、アクティブな画面領域内のいずれかの行と列に位置します。カーソルは見た目上非表示になることがありますが、ターミナルの内部状態には常にカーソルが存在し、常にいずれかのアクティブな位置にあります。

カーソルは通常、次に表示される文字の配置場所と関連付けられます。ただし、位置に依存する制御シーケンスにも使用されます。たとえば、[行消去制御シーケンス](/docs/vt/csi/el)を実行すると、カーソルによって最初に消去する行が決まります。

ターミナルには[画面ごと](/docs/vt/concepts/screen)に 1 つのカーソルがあります。**この文書は、[ターミナル API](/docs/vt) に関連するカーソルについて説明していることに注意してください。** エディターなどのアプリケーションには、ターミナルのカーソルとはまったく無関係な、独自の「カーソル」という概念がある場合があります。たとえば、エディターは「複数のカーソル」をサポートしているかもしれませんが、その基盤となるターミナル API は別の概念であり、どの時点でも単一のカーソルしかサポートしません。

## 初期状態 {/* #initial-state */}

カーソルは常に画面の左上隅にある状態で始まります。

## 保留中の折り返し状態 {/* #pending-wrap-state */}

保留中の折り返し状態は、画面の右端の列に文字を表示したときに設定される真偽値で、次に表示する文字を次の行に折り返すことを示します。

保留中の折り返し状態が設定されている場合、次の文字の表示時にカーソルを次の行の左端の列に移動し、保留中の折り返し状態を解除してから、その文字を表示します[^1]。

保留中の折り返し状態は、当然で取るに足りない機能に思えるかもしれませんが、カーソルの動作に大きな（ただし微妙な）影響を与えます。たとえば、文字の表示に続けて[バックスペース](/docs/vt/control/bs)を送ると、画面の右端の列に表示しているかどうかによって動作が異なります。

右端以外の列に文字を表示してから[バックスペース](/docs/vt/control/bs)制御文字を送ると、カーソルは直前に表示した文字の上に戻ります。しかし、右端の列に文字を表示してから[バックスペース](/docs/vt/control/bs)制御文字を送ると、カーソルは直前に表示した文字の左に移動します。これが、[複数の有名なシェルプロンプトにあるバグ](https://github.com/ghostty-org/ghostty/issues/884)の原因です。

多くの制御シーケンスには、「保留中の折り返し状態を解除する」と記載されています。これは文字どおり、カーソルに保留中の折り返し状態が設定されていれば、それを解除するという意味です。次に表示する文字は、次の行に折り返されません。

[^1]: 厳密には、これは常に正しいわけではありません。折り返しモードやスクロール領域によって、この動作は変わることがあります。
